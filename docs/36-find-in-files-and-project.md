## 0. 정의(사용자)

- **프로젝트** = 폴더 하나(루트) + 설정 파일 `<root>/.nexa-sql/project.json`. 열린 탭 목록·**이름 없는 메모리 탭의 본문**까지 프로젝트 파일에 저장되어, 프로젝트를 다시 열면 탭이 그대로 복원된다(Sublime hot exit + `.sublime-project`의 결합 · docs/18 §3 확장).
- 탭 = **파일 탭**(경로 있음 · 디스크와 동기) 또는 **메모리 탭**(경로 없음 · 본문은 프로젝트 파일 안에만).
- 검색 범위 3종: ① 열린 탭(파일·메모리 모두 — 메모리 탭은 편집기 버퍼를 직접 검색) ② 프로젝트 루트 이하 재귀 ③ 사용자가 추가한 폴더(프로젝트 설정 `folders[]`에 저장 · 여러 개).

## 1. UI — 활동 막대 두 번째 패널(VS Code Search)

```
[🔍] Search                               ⟳  ⌫  ⊞  ≡  ⊟        ← 다시 검색 · 결과 지우기 · 새 검색 편집기(후속) · 전체 접기 · 결과 뷰 토글
     › [검색어 (↑↓ 히스토리)          Aa ab .*]                 ← › = 바꾸기 줄 펼침(플로팅 찾기와 같은 토글)
       [바꾸기                              AB]  [⇄][⇄모두]
     Where: [<current file>, D:\…\이슈관리, D:\…\Oracle  ▾]     ← Sublime 규약 · 콤마 구분 · 히스토리 콤보 · […] = 폴더 추가(자체 대화상자 Folder 모드)
     ☐ 열린 탭만   ☐ 프로젝트 폴더   ☑ 지정 폴더                 ← 범위 토글(체크 = 합집합)
     ─────────────────────────────────────────────
     ▾ Script_3 (메모리 탭)                                 2
         12:  SELECT * FROM M4S_I002040 A
         40:  AND A.PROJECT_CD = 'SEBANG'
     ▾ 이슈관리/2026-09-01.sql                               1
         7:   -- 1433 포트 …
     ▸ Oracle/sp_m4p_mp_version_create.sql                  3
```

| 요소 | 동작 |
|---|---|
| 단축키 | `Ctrl+Shift+F` = 패널 열고 검색어 상자 포커스(선택 텍스트 씨앗 · 플로팅 찾기와 같은 규약) · `Ctrl+Shift+H` = 바꾸기 펼침 · `Enter` 검색 · `Esc` 편집기로 · `F4`/`Shift+F4` 다음/이전 결과 |
| 토글 | `Aa` 대소문자 · `ab` 단어 단위 · `.*` 정규식(T-59 자체 NFA 뒤 활성 · 그 전엔 비활성 + 툴팁) |
| Where | 비면 = 범위 토글대로 · 항목: `<current file>`(활성 탭 파일의 폴더) · `<open files>`(열린 탭 전부) · `<project>`(루트) · 절대 경로 폴더/파일 · `-` 접두 = 제외(`-*.log`) · 콤마 구분 · 히스토리 10개 |
| 결과 트리 | 파일 → 줄(번호 · 일치 부분 강조 · 앞뒤 문맥 한 줄) · 클릭 = 그 탭/파일 열고 해당 위치 선택 · 파일 행 `×` = 결과에서 제외 · 우클릭 = 경로 복사·탐색기에서 보기 |
| 진행 | 상태줄 `n files · m matches · 0.42s` · 취소 버튼(진행 중) · 결과는 **도착하는 대로**(스트리밍) |
| 바꾸기 | 미리보기(파일별 diff 행 · 체크로 제외) → 적용 = 파일 저장(탭에 열려 있으면 버퍼 갱신 · docs/15 외부 변경 규칙) · 되돌리기는 편집기 히스토리(열린 탭) / 백업 `.nexa-sql/replace-<ts>/`(닫힌 파일 · 옵션) |

## 2. 검색 엔진(속도 설계)

목표: **10만 파일 · 1GB 텍스트에서 수 초 안**(ripgrep 계열 원리 차용 · 외부 crate 0 · docs/26 계측).

| 단계 | 방법 |
|---|---|
| **열거** | 병렬 폴더 걷기 — 스레드 풀(코어 수) + 작업 훔치기 큐(폴더 단위) · `fs::read_dir` 메타데이터로 심볼릭 링크 루프 차단(방문 집합 = (dev, inode)/Windows 파일 ID) · **무시 규칙**: `.git` `node_modules` `target` `.nexa-sql` 등 기본 + `.gitignore` 상위 규칙(glob 부분집합: `*` `**` `?` `!` · 자체 매처) + 이진 파일(NUL 바이트 있음 · 첫 8KB 검사) 제외 · 크기 상한(`search.max_file_mb` 기본 20) |
| **읽기** | 파일당 한 번 `read` → `Vec<u8>` (mmap 없음 — 3-OS 동일 · 작은 파일 다수엔 read가 더 빠르다) · 스레드마다 버퍼 재사용 |
| **매칭** | 리터럴: **memchr 계열**(첫 바이트를 `u64` SWAR로 스캔 · 후보에서만 비교) → 대소문자 무시는 소문자 테이블로 두 바이트 후보 · 단어 단위는 후보 앞뒤 바이트 검사 · 유니코드 대소문자는 ASCII 빠른 길 + 비ASCII만 `char` 경로 · 정규식(T-59 NFA)은 **리터럴 접두/필수 부분 문자열 추출**로 같은 사전 필터를 태운 뒤 NFA 확인 |
| **줄 번호** | 일치가 있는 파일만 개행 수를 센다(일치 오프셋 정렬 후 한 번 훑기) — 일치 없는 파일은 줄 계산 0 |
| **인코딩** | UTF-8 그대로(잘못된 시퀀스는 바이트 그대로 매칭) · BOM UTF-16은 UTF-8로 변환 후(T-79와 같은 디코더) · EUC-KR은 T-79 표 뒤 |
| **결과 전달** | 워커 → 메인 `mpsc` 채널로 파일 단위 배치(≤ 64 일치) · 취소 토큰(`AtomicBool`) · 16ms마다 UI 갱신(30ms 페이드 타이머와 같은 예약) |
| **캐시**(2차) | 폴더별 (경로, mtime, 크기) 스냅샷을 프로젝트 파일 옆 `.nexa-sql/index.bin`에 — 다음 검색은 변한 파일만 다시 읽는다 · 파일 수·총 크기가 상한 아래면 **내용 캐시**(ripgrep이 하지 않는 것 · 반복 검색이 잦은 IDE 사용 패턴에 맞춤) |
| **열린 탭** | 편집기 버퍼(`String`)를 같은 매처로 — 디스크가 아니라 **지금 화면의 본문**(저장 안 된 변경 포함) · 파일 탭은 디스크 대신 버퍼를 우선(중복 방지) |

부품 위치: `nsql-search`(신규 크레이트 · 의존 0 · CLI `nsql grep`도 같은 엔진 — DR-6 "CLI와 같은 코어") · UI 패널 = `search_panel.rs`(활동 막대 두 번째 패널 · 결과 = nexa-ctl `TreeView`) · 병렬 열거는 `nexa-fs`(docs/20 §2 `listing` 배치/취소)로 올려 파일 대화상자와 공유.

## 3. 프로젝트 파일(docs/18 §3 확장)

```json
{ "version": 1,
  "root": ".",                              // project.json이 있는 폴더 기준
  "folders": ["D:/Projects/sebang/2026-sebang-snop/이슈관리", "../Oracle"],   // ③ 지정 폴더(상대 = root 기준)
  "tabs": [
    { "path": "scripts/a.sql", "caret": 120, "scroll": 3, "encoding": "utf8", "indent": [4, true] },
    { "title": "Script_3", "memory": "SELECT ...", "caret": 0 }            // 메모리 탭 = 본문 자체를 저장
  ],
  "active": 1,
  "search": { "where_history": ["<current file>, ../Oracle"], "queries": ["1433"] },
  "connection": "biscm"                      // 프로필 이름만(비밀번호는 vault)
}
```
- 저장 시점: 탭 열기/닫기/이동 · 5초 디바운스 자동 저장 · 종료 시. 메모리 탭 본문은 `hot exit`처럼 매번 통째로(상한 `project.memory_tab_max_kb` 기본 512 · 넘으면 파일로 저장 권유).
- 프로젝트 없이 실행 = **기본 프로젝트**(사용자 폴더 `nsql-projects/default/project.json`) — 지금의 "이름 없는 탭"도 여기에 저장되어 다음 실행에 복원(hot exit · docs/18 §2). 명시 프로젝트는 File ▸ Open Project…(자체 대화상자 Folder 모드 · F-4 잔여).

## 5. 사용 편의(요청 "편의성을 해치지 않게")

- 검색 중에도 편집·실행 가능(워커 스레드 · UI 비차단) · 첫 결과가 100ms 안에 보이도록 배치 크기 작게 시작.
- Where 상자는 **폴더 끌어놓기**(winit `DroppedFile`)로 추가 · `…` 버튼 = 자체 폴더 선택 대화상자 · 잘못된 경로는 즉시 빨간 밑줄 + 툴팁.
- 결과 행 Enter/더블클릭 = 이동 · `Alt+Enter` = 전부 열기 · 결과에서 `Ctrl+C` = 경로 복사.
- 큰 범위 경고: 무시 규칙 없이 10만 파일 넘으면 "이 폴더는 큽니다 — `.gitignore` 규칙을 켤까요?" 한 줄(한 번의 입력으로 이어지게).
