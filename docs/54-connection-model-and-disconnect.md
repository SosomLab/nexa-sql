# 54 — 연결 모델과 접속 해제 UX (사용자 09-19 · DBeaver 항해자 모델 대비)

> 요구(09-19): 공유 연결 · 개별 연결 두 모드에 "공유 모드 안의 전용 세션"까지 더해지자 **연결은 단순한데 해제가 복잡**해졌다 —
> 해제는 그 연결을 쓰는 탭들과 함께 봐야 하고, 전용 탭은 빼야 하고, 인텔리센스·툴팁을 위한 **메타 세션(탐색기)**은 같은 서버의
> 세션이 하나라도 남아 있으면 지우면 안 된다. 사용자가 직관적으로 행동할 수 있는 **시퀀스 · 버튼 모양 · 기능**을 종합 설계한다.
> 가장 닮은 구조 = DBeaver(좌측 연결 목록에서 접속 → 편집기가 연결을 attach · 상단 콤보로 바꿈). 우리는 **탭 표식이 그 콤보를
> 대신**하고, DBeaver에 없는 **탭별 전용 세션**이 있다.

## 1. DBeaver의 모델(소스 · 첨부 캡처 기준)

| DBeaver 요소 | 동작 | 우리 대응 |
|---|---|---|
| **Database Navigator**(좌측 연결 목록) | 연결 항목 = 데이터소스. 우클릭 Connect/Disconnect/Invalidate/Edit. 접속돼야 편집기·탐색이 된다. 끊어도 항목은 남는다 | **오브젝트 탐색기의 서버 루트** = 연결 항목. 루트 우클릭 **New tab here · Refresh · Disconnect** / 오프라인이면 **Connect · Remove** |
| 툴바 **활성 데이터소스 콤보**(`BISCM@PRD ▾`) | 지금 편집기가 붙은 연결 · 바꾸면 그 편집기만 바뀜 | **탭 표식(S/P 배지) 메뉴** — `No connection` · 공유 연결 목록 · 전용 줄 |
| 툴바 **Disconnect** | 활성 데이터소스를 끊는다 → 그 연결을 쓰는 **모든 편집기**가 "Not connected" | 툴바 Disconnect = **지금 탭의 연결** — 전용이면 그 탭만 · 공유면 그 연결 전체(다른 탭도 쓰면 **묻는다**) |
| 새 스크립트 | 활성 데이터소스에 자동 attach | 새 탭 = 활성 공유 연결에 묶임(개별 모드 = 접속 창) |
| 편집기별 세션 | 없음(데이터소스 단위 · "Separate connection per editor" 설정만) | **전용 세션**(`CONNECT` · P 배지) |
| 메타(탐색기 트리·자동완성) | 데이터소스의 메타 세션 · 연결이 살아 있는 동안 캐시 | **서버 키당 탐색기 하나**(52 §2-2) · 어떤 세션이든 붙어 있으면 유지 · 0이면 오프라인(트리는 남음) |
| Disconnect 뒤 항목 | 항목은 남고 아이콘만 끊김 | 루트 오프라인(흐림) · 트리 유지 · **Remove**로만 사라짐 |

## 2. 개념 3층 — 연결 · 세션 · 탭 (여기서 복잡성이 풀린다)

```
연결(Connection) = 서버·계정 하나 = 탐색기 루트 하나 = 메타 세션 하나(캐시)
  ├ 공유 세션 0~1개  ← 탭 N개가 참조(tab_bind)
  ├ 전용 세션 0~N개  ← 탭 하나씩 소유(owner)
  └ 메타 세션(탐색기·인텔리센스·툴팁) — 위 세션 합이 ≥1이면 살아 있음 · 0이면 접속만 닫고 트리 유지
탭 = { 공유 참조 | 전용 소유 | 미연결 }
```

- **연결하기**는 세션을 하나 더 다는 일이라 단순하다(같은 서버·계정이면 기존 공유 세션 활성화 · 아니면 추가).
- **해제하기**는 "무엇을 끊는가"를 골라야 한다 — 이 탭의 참조만? 이 세션만? 이 연결(서버)의 전부? 아래 §3이 그 답을 **버튼 자리로** 나눈다.

## 3. 해제 = 자리마다 범위가 정해져 있다 (외우지 않아도 되게)

| 자리 | 범위 | 뜻 |
|---|---|---|
| **탭 표식 메뉴 ▸ No connection** | **탭** | 이 탭만 뗀다(전용이면 그 세션을 닫고 · 공유면 참조만 푼다). 다른 탭·연결은 그대로 |
| **툴바 Disconnect**(플러그 ✕) | **지금 탭이 쥔 연결** | 전용 = 그 탭 세션만 · 공유 혼자 = 그 공유 연결 · **공유를 다른 탭도 쓰면 확인**: `N개 탭 모두 연결 해제 / 이 탭만 떼기 / 취소` |
| **탐색기 루트 ▸ Disconnect** | **연결(서버) 전체** | 그 서버의 공유·전용 세션 전부 → 탭들은 미연결 표식 · 메타 닫힘 · 루트 오프라인(트리 유지) |
| **세션 창 ▸ 접속 해제 / 모두 해제** | **세션 하나 / 전부** | 표에서 고른 세션(공유든 전용이든) · 빈 곳 우클릭 = 모두 |
| 스크립트 `DISCONNECT` | 그 탭의 세션 | 전용 = 거둠(공유 복귀) · 공유 = 공유 해제(종전) |
| 탭 닫기 · 유휴 · 끊김 중지(■) | 자동 | 전용 세션 거둠 · 유휴 닫기 · 끊긴 워커 교체 |

**규칙 하나**: *작은 자리는 작은 범위, 큰 자리는 큰 범위* — 탭(표식) < 툴바(지금 탭의 연결) < 탐색기 루트(서버) · 세션 창(명시적 선택). 모두 같은 함수(`disconnect_private_as` · `disconnect_shared` · `disconnect_server`)로 모이고, 미커밋은 어느 길이든 잃는 순간에만 묻는다(DR-30).

### 3-1. 툴바 Disconnect의 판정(순수 함수 `sessions::disconnect_plan` · D16)

| 지금 탭 | 묶인 탭 수 | 판정 | 동작 |
|---|---|---|---|
| 전용 | — | `Private` | 바로 해제(공유 모드 = 공유 복귀 · 개별 = 미연결) |
| 공유 | 1 | `SharedAlone` | 바로 해제 |
| 공유 | ≥2 | `SharedAsk` | 팝업(버튼 아래): **N개 탭 모두 연결 해제** / **이 탭만 떼기(No connection)** / 취소 |

버튼 자체가 범위를 미리 보여 준다: **툴팁** = "이 탭의 전용 연결 해제" / "`BISCM@host` 연결 해제" / "`BISCM@host` 연결 해제 — 3개 탭이 함께 씀" · **배지** = 함께 쓰는 탭 수(≥2일 때만 · 툴바 Commit 배지와 같은 문법).

### 3-2. 탐색기 루트 메뉴

| 루트 상태 | 항목 |
|---|---|
| 연결됨 | **이 연결로 새 탭**(공유 세션에 묶인 새 탭) · 새로 고침 · ─ · **연결 해제(이 서버의 모든 세션)** |
| 오프라인 | **연결**(남은 공유 세션이 있으면 그것으로 · 없으면 공유 세션 추가 · `connect.reconnect_same`) · **탐색기에서 제거** |

## 4. 메타(탐색기·인텔리센스) 생존 규칙 — 변경 없음(52 §2-2 · 이번 요구의 핵심 제약)

- 같은 서버에 전용 4개를 붙여도 탐색기 루트는 **하나** · 메타 인덱스 하나를 4탭이 본다.
- 참조 수 = 그 서버에 붙은 (공유 + 전용) 세션 수. **1 이상이면 메타 유지**. 어느 자리에서 해제하든 `sync_sess_ui`의 참조 수 맞춤이 0이 될 때만 메타를 닫고 트리는 오프라인으로 남긴다. 탐색기에서 없애는 것은 오직 **Remove**(오프라인일 때만 보임).
- 탭과 메타의 관계를 **완전히 분리**하는 안(사용자 대안 ③)은 택하지 않았다: 인텔리센스가 "이 탭이 붙은 서버"의 메타를 봐야 하므로 참조는 필요하고, 위 참조 수 규칙이 이미 분리에 가깝게 동작한다(탭이 없어도 트리는 남는다).

## 5. 해제 로그 — "어느 경로로 어떤 서버를"(사용자 09-19)

종전 `disconn` 한 줄은 내용이 비어 있었다(워커 이벤트 그대로). 이제 세션의 `disc_path`(진입점이 표시)로 한 줄에 셋을 남긴다:

`{공유 세션 | 전용 세션 [탭 제목]} 접속 해제: oracle://BISCM/***@61.81.244.214:1521/BISCM — 경로: {툴바·메뉴 Disconnect | 접속 창 Disconnect | 탭 표식 메뉴(No connection) | 오브젝트 탐색기(서버 메뉴) | 세션 창 | 스크립트 DISCONNECT · 서버 | 유휴 닫기 | 탭 닫기 | 끊긴 접속 중지(■) | 다른 연결로 전환}`

호스트가 워커를 바꾸는 해제(툴바·유휴·■)는 `Disconnected` 이벤트가 오지 않으므로 호스트가 즉시 남기고, 이벤트로 오는 해제(스크립트·서버)는 `disc_path`가 비어 있을 때만 남긴다(중복 0). 접속되면 `disc_path`를 비운다.

## 6. 시퀀스 예(사용자 시나리오)

1. **공유 1 + 탭 4, 탭 B에서 툴바 Disconnect** → 배지 `4` · 팝업 → "4개 탭 모두 연결 해제"(전 탭 미연결 · 루트 오프라인) / "이 탭만 떼기"(B만 미연결 · 나머지 그대로 · 루트 유지).
2. **같은 서버에 전용 P 탭 2 + 공유 S 탭 2, 탐색기 루트 ▸ Disconnect** → 세션 4개 전부 해제 · 탭 4개 미연결 표식 · 메타 닫힘 · 트리 유지 · 로그 4줄(경로: 오브젝트 탐색기).
3. **P 탭에서 표식 ▸ No connection** → 그 P 세션만 닫힘 · 참조 수 3 → 탐색기 유지 · 로그 1줄(경로: 탭 표식 메뉴).
4. **오프라인 루트 ▸ Connect** → 공유 세션이 남아 있으면 그것을 다시 접속 · 없으면 공유 세션 추가 · 활성 공유 연결이 됨.

## 8. 남은 것 · 열린 결정

- **D-117** 탐색기 루트에 참조 수(탭 수)를 표시할 것인가 — 권장: 루트 오른쪽 흐린 숫자 `· 3 tabs`(DBeaver엔 없음 · 우리 모델의 핵심 정보라 보이는 게 낫다). 답을 받으면 구현.
- **D-118** 툴바 Disconnect의 `SharedAsk` 기본 항목 — 권장: 첫 항목 "모두 해제"(DBeaver 의미와 같음) · Enter = 첫 항목.
- 표식 메뉴에 "이 서버의 모든 세션 해제"를 넣지 않는다(작은 자리 = 작은 범위 규칙).

## 9. 서버 묶음 트리 · 연결 해제 UX(사용자 09-25 · 100차 후반)

> 요구: "SQL Server(·Oracle)에서 같은 서버에 DB(계정)만 다른 연결 둘이면 탐색기에는 **서버 하나** 아래 연결 둘(S1 → D1(C1) · D2(C2))로 보이고, C2를 해제하면 D2 행이 사라지게. 서버 노드 Disconnect는 전부인지 골라 해제인지 설계·제안 — 고르는 방식이면 1개여도 고르는 설정 · 전부 방식이면 개별 해제 길이 있어야."

### 9-1. 트리 모양(구현 ✅ §191)

```
S1 192.168.0.58:1433   연결 2개              ← 서버 헤더(ExplorerSet가 그림 · 우클릭 = 서버 메뉴)
  ▾ BISCM_MS   sa · M4PLAN                 ← 연결 행(= 그 연결 Explorer의 루트 · DB(서비스) · 계정 · 프로필)
      Schemas …
  ▾ JPN_POC    sa · JPN                    ← 같은 서버의 둘째 연결
```

- 묶음 열쇠 = **방언·호스트·포트**(`worker::same_host`) · 연결 열쇠는 종전대로 방언·호스트·포트·DB·계정(`same_server` · 칸 = 연결 = 메타 세션 1). 파일 방언(SQLite · 호스트 없음)은 헤더 없이 종전 모양.
- `Explorer::set_grouped(true)` = 루트 행이 연결 행이 되고(라벨 `DB · 계정 · 프로필`) 트리를 한 단 들여쓴다 · 헤더는 그룹 첫 칸이 `paint_server_header`로(브랜드 아이콘 + `host:port` + 흐린 "연결 N개[· 일치 M]").
- Oracle도 같다(서비스가 같아도 계정이 다르면 연결 둘 = 한 서버 아래 두 행).
- **해제된 연결은 트리에서 빠진다**(`sync_refs` → `remove`) — 종전 "오프라인 행으로 남김"은 설정 `explorer.keep_offline`(기본 끔)로 돌아온다(D-204 · 충돌 조정: 09-18 56차 설계(메타 유지 · 연결/제거 메뉴)보다 09-25 지시가 나중).

### 9-2. 해제 UX(제안 → 권장안 구현 ✅)

| 자리 | 동작 |
|---|---|
| **연결 행 우클릭** ▸ "이 연결 해제" | 그 연결의 세션 전부(개별 해제 — 늘 있다) |
| **서버 헤더 우클릭** ▸ 연결 해제 | 설정 `explorer.disconnect_pick`: **auto**(기본) = 연결 1개면 항목 하나로 바로 · 2개 이상이면 **하위 메뉴**(모두 해제(N) · ─ · 연결마다 한 줄 `DB · 계정`) / **always** = 1개여도 하위 메뉴 / **all** = 늘 "모두 해제(N)" 하나(개별은 연결 행에서) |
| 툴바 Disconnect | 변경 없음(탭 범위 · §3-1) |

권장 = auto: 한 번의 우클릭에서 "전부"와 "이것만"을 같은 자리에서 고르고, 연결이 하나면 물음 없이 끝난다(DBeaver·SSMS엔 없는 다중 연결 모델이라 두 요구를 한 메뉴에 담았다). 판정은 순수 함수 `explorers::disc_menu(mode, n)`(MC/DC 시험) · 실행은 종전 `ExplorerAction::DisconnectServer(spec)`를 연결마다.

결정: **D-204** 해제된 연결 행 = 제거(기본) · `explorer.keep_offline`로 유지 · **D-205** 서버 헤더 해제 방식 = `explorer.disconnect_pick` auto 기본. 남은 것 = 헤더 접기(그룹 접힘) · Databases 층(T-204 · 83 §5 D-201)과의 결합(헤더 아래 "Databases" 폴더로 다른 DB 열람).

## 10. 카탈로그 단위 메타 공유(사용자 09-25 "인텔리센스는 서버 단위로 하나 · 해제 시 종속 데이터 분리는 어렵다 — 알고리즘·자료 구조 정리")

### 10-1. 문제
같은 서버에 계정만 다른 연결 둘(Oracle BISCM · BISCM_SB)이면 종전엔 칸(트리 + `MetaStore` + 메타 세션 2)이 둘 = 스키마 45개가 두 번, 완성 메타도 두 벌.

### 10-2. 정의 — 데이터의 주인은 "카탈로그"
- **카탈로그 열쇠** = 방언 · 호스트 · 포트 · DB(서비스) (`worker::same_catalog`). 계정은 열쇠가 **아니다**. SQL Server의 다른 DB는 객체가 다르므로 다른 카탈로그(= 다른 칸 · §9 헤더 아래 DB 행 둘) · Oracle의 다른 계정은 같은 카탈로그(한 칸).
- **칸(`Pane`) = 카탈로그 하나** = 트리 + `MetaStore` + 메타 세션(급한 1 · 백그라운드 1) + `conns: Vec<ConnectSpec>`(붙어 있는 연결들 · 계정별).
- 연결은 **자격만 빌려 준다**: 메타 세션은 `conns[0]`의 자격으로 열고, 그 계정이 끊기면 남은 계정으로 **재바인딩**(`Explorer::rebind` = 세대 +1 · 트리·메타 유지 · 읽는 중이던 노드만 Idle · 열림 응답에서 트리를 건드리지 않음).
- **해제 시 분리 문제는 정의로 없앤다**: 카탈로그 데이터는 연결이 아니라 서버의 사실이므로 어느 연결이 읽었든 남은 연결에게 그대로 유효하다 → 연결별 태그·부분 제거가 필요 없다. 마지막 연결이 끊기면 칸을 통째로 뺀다(`explorer.keep_offline`이면 오프라인 행으로 유지 · 메타 캐시 유지) · 그 사이 메모리는 기존 회수(완성 버킷 미사용 즉시 회수 `reclaim_intel_buckets` · 메타 유휴 회수 · 트리 노드는 펼친 것만)로 보완.
- 가시성 차이(계정 권한이 달라 보이는 객체가 다름)는 **합집합**으로 보인다(먼저 읽은 계정의 결과가 남는다 · 재바인딩 뒤 새로 고침(F5/⌘⇧R)으로 그 계정 기준으로 갱신).

### 10-3. 알고리즘(ExplorerSet)
```
connect(spec):  칸 = find(same_catalog)  → 있으면 conns에 계정 추가(없을 때만) · 오프라인이면 다시 열기
                                          → 없으면 새 칸(key = 첫 스펙 · conns = [spec]) · 메타 세션 열기
sync_refs(live): 칸마다 alive = live ∩ same_catalog
                 conns.retain(alive에 있는 계정)
                 메타 세션 계정 ∉ alive ∧ alive ≠ ∅ → rebind(alive[0])
                 alive = ∅ → GoOffline → keep_offline ? 오프라인 행 : remove(칸)
헤더 메뉴 해제: 항목 = 그룹의 (칸, 연결) 전부 · 루트 행 "이 연결 해제" = 그 칸의 연결 전부
```
시험 = `groups_by_host_and_removes_disconnected`(같은 카탈로그 두 계정 = 한 칸 · 헤더 연결 수 3 · 계정 하나 끊김 = 칸 유지·연결 1 · 카탈로그 전부 끊김 = 칸 제거).

### 10-4. 충돌·조정(09-25 저녁)
사용자가 §10을 **원복**: "각 접속별로 권한이 달라 인텔리센스도 분리돼야 하니 연결별 서버 노드가 맞다" → 기본은 종전대로 **연결(계정) = 칸**(`same_server`) · §10-2~10-3의 카탈로그 공유는 설정 `explorer.share_catalog`(기본 끔 · 새 연결부터 · `ExplorerSet::same_pane`)로 남긴다 — 가시성 합집합 문제도 그래서 기본에서는 없다.

### 10-5. 편집기 `CONNECT` 두 번 = 앞 연결이 사라진다(사용자 09-25 · 결정 대기 D-208)
현상: 한 탭에서 `CONNECT oracle://BISCM:…` → `CONNECT oracle://BISCM_SB:…` → 다시 첫 것 = 앞 연결이 없어지고 하나만 남는다. 원인 = **모델**: 편집기 `CONNECT`는 그 탭의 **전용 세션 = 탭당 하나**(DR-34 · 52 §2) → 두 번째 `CONNECT`가 앞 세션을 대체(89차 "같은 서버 CONNECT = 자격 변경 = 재접속") · 종전엔 대체된 연결이 탐색기에 **오프라인 행**으로 남아 둘처럼 보였고 D-204(해제 행 제거 · 기본)로 바로 사라진다. 살아 있는 연결 둘을 두려면 탭 둘(각 `CONNECT`) 또는 접속 창의 공유 연결 추가. **D-208** 선택지: ① 모델 유지(권장 · 탭 = 세션 하나 · 안내 문구를 로그에 "앞 연결 X를 닫고 Y로 바꿈") ② `explorer.keep_offline` 켜서 옛 행을 남김(재연결 메뉴) ③ 새 규칙 "다른 계정으로 CONNECT = 앞 세션을 **공유 연결로 남기고** 새 전용 세션" — 통제 단위가 흔들려 비권장.
