# 74 · 탭별 변수 보존의 **문서 식별** — 현 설계 · 동일성이 깨지는 경우 · 개선안

> **요구(사용자 09-23)**: `vars.persist`가 켜져 있으면 `%APPDATA%\nexa-sql\vars\`에 탭별 변수를 저장하는데, 편집기 탭과 **혼돈 없이** 연결할 방법이 없다 — 탭 이름도 파일 이름(이름만이든 전체 경로든)도 바뀔 수 있어 유일성을 확보할 수 없다. 현 설계를 설명하고, 파일 동일성이 확보되는 경우는 두되 **같은 파일인데 동일성이 깨질 수 있는 경우**를 감안한 더 효과적인 저장 방식을 제안.
>
> 선행: [63 §V4·D-136](63-variable-management.md)(파일별 보존) · [67 §6·§7](67-project-workspace.md)(작업 모드 셋 · 파일 형식 v2) · [70 §6-1](70-autosave-and-restore.md)(미저장 본문 = 프로젝트 파일) · [73](73-project-path-portability.md)(경로 앵커) · [69 §3](69-bookmarks.md)(북마크의 4단 앵커 — 같은 문제를 먼저 푼 곳).

## 0. 결론 여섯 줄

1. 지금은 **"경로 = 문서"** 다: `vars/<canonicalize(경로)를 소문자로 해시>.sql` · 파일 탭이 실행으로 변수를 바꿀 때 씀 · 그 경로를 다시 열 때 읽음. 이름 없는 탭은 보존하지 않는다.
2. 그래서 깨지는 경우 = **이름 바꿈 · 이동 · 다른 이름으로 저장 · 복사본 · 대소문자만 다른 경로 · 드라이브 문자/네트워크 경로 변경**(전부 "같은 문서, 다른 열쇠") 와 반대로 **다른 문서, 같은 열쇠**(파일을 지우고 같은 이름으로 새로 만듦 · 다른 PC의 같은 경로).
3. 어떤 단일 열쇠도 다 못 푼다(경로·파일시스템 id·내용 지문·내장 id 각각의 표 §2) → **층을 쌓는다**: ① 앱이 아는 이동(우리 Save As·이름 바꾸기·프로젝트 복원)은 **이관** ② 프로젝트 모드는 **탭 id**(프로젝트 파일 안 · §101과 같은 자리) ③ 파일·폴더 모드는 **경로 열쇠 + 파일시스템 id 보조 + 내용 지문 후보** ④ 사용자가 원하면 **문서 id 주석**(`-- nsql:doc 8f3c…`)으로 무엇이든 넘어서게.
4. 저장 자리는 작업 모드 셋을 따른다([67 §6](67-project-workspace.md) `WorkMode::local_dir`): 파일 모드 = `%APPDATA%/nexa-sql/vars/` · 폴더 모드 = `<폴더>/.nsql/vars/` · 프로젝트 모드 = **프로젝트 파일의 탭 블록**(`vars=<id>` payload · 본문과 같은 층 · 이름 없는 탭도 자연히 보존).
5. 못 맞추면 **조용히 다른 문서의 변수를 올리지 않는다**: 후보가 있으면 상태줄/변수 창에 "이전 변수 표 후보 n개 — 올릴까요?"(사용자 선택 · 자동 채택은 정확 일치일 때만).
6. 단계 P1(이관 훅 + 프로젝트 탭 블록) → P2(파일시스템 id + 지문 후보) → P3(문서 id 주석 · 설정) · 결정 D-191~D-195(§6).

## 1. 현 설계(D-136 · `varsfile.rs`)

| 항목 | 지금 |
|---|---|
| 열쇠 | `name_for(경로)` = `canonicalize(경로)`(실패하면 원문) → 소문자 → 해시 → `vars/<해시>.sql` |
| 언제 씀 | 실행이 그 탭의 **탭 층 변수**를 바꿨을 때 · 파일 탭만 · `vars.persist` 켬 |
| 언제 읽음 | 파일 탭을 열 때 1회(`vars_persist_load` · 이미 표가 있으면 안 읽음) |
| 내용 | 실행 가능한 스크립트(`VAR`/`EXEC :v := 리터럴` · 비밀·커서·여러 줄 제외 · D-140) |
| 정리 | `vars.persist_days` 지난 파일 삭제 |
| 이름 없는 탭 | 보존 안 함(hot exit와 함께 넓히기로 했던 것 — §101로 본문은 이미 프로젝트에 들어갔다) |

**깨지는 순간(같은 문서 · 다른 열쇠)**: 이름 바꾸기(앱 안팎) · 폴더 이동 · 다른 이름으로 저장(새 경로 = 빈 표) · 복사본을 여는 경우(복사본은 별개 문서라 빈 표가 맞다 — 그러나 "원본을 옮긴 뒤 복사본만 남은" 경우와 구별 불가) · 프로젝트 폴더째 다른 PC로(경로 전부 바뀜 · 73) · 대소문자만 다른 경로는 소문자화로 맞지만 심볼릭 링크/정션은 `canonicalize`가 실제 경로로 풀어 **같은 파일을 두 경로로 열면 한 열쇠**(이건 맞음).
**반대(다른 문서 · 같은 열쇠)**: 파일을 지우고 같은 이름으로 새로 만듦 · 다른 PC의 같은 경로 · `${home}` 아래 같은 상대 경로 — 옛 변수가 새 문서에 올라온다(지금은 막지 못함).

## 2. 열쇠 후보 — 무엇이 무엇을 견디나

| 열쇠 | 이름 바꿈 | 이동(같은 볼륨) | 이동(다른 볼륨)/복사 | 다른 PC | 내용 편집 | 앱의 tmp→rename 저장 | 비용·부작용 |
|---|---|---|---|---|---|---|---|
| **경로 해시**(지금) | ✗ | ✗ | ✗ | ✗ | ✓ | ✓ | 0 · 단순 |
| **파일시스템 id**(Windows `FileId`(볼륨 시리얼+파일 인덱스) · Unix inode) | ✓ | ✓ | ✗ | ✗ | ✓ | **✗**(rename 저장은 새 파일 = 새 id · 우리 `save_file`이 이 방식) → 저장 뒤 id를 다시 읽어 갱신해야 | 저장마다 `metadata` 1회 · Windows는 `GetFileInformationByHandle`(std `MetadataExt::file_index`는 nightly → `windows-sys` 호출 or 폴백) |
| **내용 지문**(크기 + 앞 4 KB 해시 + 전체 해시) | ✓ | ✓ | ✓ | ✓ | **✗**(한 글자 고치면 다른 문서) — "가까운 후보" 판정용(유사도)으로만 | 열 때 파일 1회 읽기(이미 읽는다) |
| **문서 id 주석**(`-- nsql:doc <uuid>` 첫 줄 · JetBrains `@formatter`·Sublime의 파일 헤더 관례 · Jupyter `id`) | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | **사용자 파일을 고친다**(옵트인 · 첫 저장 때 넣기 · 실행 시 주석이라 무해) · 복사본이면 두 문서가 같은 id(복사 뒤 첫 열기에 새 id 부여 규칙 필요) |
| **사이드카**(`a.sql.nsql-vars` 같은 폴더) | ✗(앱이 함께 옮기면 ✓) | 폴더째면 ✓ | 폴더째면 ✓ | 폴더째면 ✓ | ✓ | ✓ | 폴더가 지저분 · VCS 노이즈 |
| **프로젝트 탭 id**(프로젝트 파일 `tabs[].id` · §101) | ✓(앱 안) | ✓(앱 안) | ✓(프로젝트 폴더째) | ✓ | ✓ | ✓ | 프로젝트 모드에만 · 이미 있는 구조 |

읽는 법: 단독으로 다 견디는 것은 **문서 id 주석**뿐이고 그것은 사용자 파일을 건드린다. 나머지는 각자 구멍이 있으므로 **아는 것부터 쓰고 모르면 후보로**.

## 3. 다른 도구는

- **JetBrains**(DataGrip 콘솔 변수·스크래치): 문서 상태를 `workspace.xml`에 **파일 URL** 기준으로 두고, IDE 안에서의 rename/move는 VFS 사건으로 **이관**한다. 외부 이동은 잃는다.
- **VS Code**: `workspaceStorage`의 문서별 상태(뷰·백업)는 **URI 해시** — 외부 rename은 잃고, 편집기 안 rename은 `onDidRenameFiles`로 옮긴다.
- **DBeaver**: 스크립트별 상태를 `.dbeaver`/`.metadata`에 **프로젝트 상대 경로**로.
- **Sublime**: 세션에 **절대 경로** + 버퍼 내용 — 외부 이동은 "파일 없음".
- 공통: **경로가 1차 열쇠 · 앱 내부 이동은 이관 · 외부 이동은 포기**. 우리는 여기에 프로젝트 탭 id(§101)와 파일시스템 id·지문 후보를 더한다.

## 4. 개선안

### 4-1. 층 — "아는 것부터 쓰고, 모르면 묻는다"

```
① 앱이 아는 이동: Save As · 이름 바꾸기(탭 메뉴·탐색기) · 프로젝트 복원 → 변수 표를 새 열쇠로 이관(옛 파일은 지우거나 별칭)
② 프로젝트 모드: 탭 id — 변수 표는 프로젝트 파일의 탭 블록 payload(`vars=<id>` · 본문 `tab=<id>`와 나란히) → 파일 이름·경로와 무관 · 이름 없는 탭도 보존
③ 파일·폴더 모드: 경로 열쇠(지금) + 기록에 [파일시스템 id · 크기 · 지문 · 마지막 경로 · 시각]을 함께 적음
     열 때: 경로 일치 → 즉시 적용
            불일치 → 같은 파일시스템 id가 있는 기록(= 이동/이름 바꿈) → 적용 + 열쇠 갱신
            그것도 없으면 → 지문 유사(크기 ± · 앞부분 해시 같음) 기록을 **후보**로 상태줄/변수 창에 제시(자동 적용 없음)
④ 옵트인 문서 id: 설정 `vars.doc_id`(off) 켜면 첫 보존 때 파일 첫 줄에 `-- nsql:doc <id>`를 넣고 그 뒤로는 이 id가 1차 열쇠(②③보다 먼저) · 복사본 감지 = 같은 id가 두 경로에서 열리면 두 번째에 새 id
```

### 4-2. 기록 형식(파일·폴더 모드 · `vars/<열쇠>.sql`의 첫 줄 메타 = 지금의 "실행 가능한 스크립트" 규칙 유지)

```sql
-- nsql:vars v2 path="D:/w/a.sql" fsid="0x3a2f:0x1c9e0000000f12" size=1834 head=7f3a… saved=2026-09-23T13:20:11
VAR v_max NUMBER
EXEC :v_max := 42
```

- 파일 이름은 **`fsid` 해시가 있으면 그것 · 없으면 경로 해시**(한 문서 = 한 파일 · 이관 때 이름을 바꾼다). 인덱스 파일 없이도 폴더를 훑어 후보를 찾을 수 있다(수십 개 · 시작 때 아님 · 열 때 1회).
- `fsid`: Windows = `GetFileInformationByHandle`(볼륨 시리얼 · 파일 인덱스 · `windows-sys` 이미 의존) · Unix = `MetadataExt::{dev, ino}`. **우리 저장(tmp→rename)은 새 파일**이므로 저장 직후 `fsid`를 다시 읽어 기록을 갱신한다(비용 = 저장마다 `metadata` 1회).
- `head` = 앞 4 KB FNV(주석 헤더는 제외) · `size` = 바이트 — 후보 판정(§4-1 ③)에만.

### 4-3. 프로젝트 모드 = 프로젝트 파일 안(§101·§102와 한 몸)

- 캡처(`project_capture_state`): 탭 층 변수가 있으면 `vars=<탭 id> len=<n>` 블록으로 스크립트(같은 `vars_to_script` 형식)를 담는다 · 헤더 탭 메타에 `"vars": true`.
- 복원(`project_restore`): 탭을 만든 뒤 그 블록을 `tab_vars`에 올린다(재매핑 §101과 같은 id 표) → 파일 이름·경로·이름 없는 탭 무관.
- 파일·폴더 모드의 `vars/` 기록은 프로젝트 모드에서 **읽지도 쓰지도 않는다**(북마크 §105와 같은 분리 · 원천은 프로젝트 파일 하나).

### 4-4. 이관 훅(①)

| 사건 | 지금 | 개선 |
|---|---|---|
| Save As(파일 탭 → 새 경로) | 새 경로 = 빈 표 | 옛 열쇠의 기록을 새 열쇠로 **복사**(원본 문서는 남으므로 지우지 않음 · 두 문서가 각자 이어감) |
| 이름 없는 탭 → 파일로 저장 | 표 없음 | 탭 층 변수를 새 경로 기록으로(북마크 C-21 열쇠 옮기기와 같은 자리) |
| 탭 메뉴 이름 바꾸기 · 프로젝트 탐색기 이름 바꾸기(있으면) | — | 기록 이름 변경 |
| 프로젝트 복원 · 폴더째 이동(73) | 경로 바뀜 = 잃음 | ②(프로젝트) · ③ `fsid`/지문 후보 |

### 4-5. 사용자에게 보이는 것

- 변수 창(View ▸ Variables) 머리에 **출처 줄**: "이 표 = 프로젝트 탭 #12" · "`D:/w/a.sql` 기록(2026-09-23 13:20)" · "후보 2개 — [올리기] [무시]".
- 후보를 올리면 그 기록의 열쇠를 지금 경로로 갱신(다음부터 정확 일치).
- 설정: `vars.persist`(있음) · `vars.persist_days`(있음) · **`vars.match_fsid`**(on · 파일시스템 id 보조) · **`vars.match_fingerprint`**(on · 지문 후보 제시) · **`vars.doc_id`**(off · 문서 id 주석 옵트인).

## 5. 단계

| 단계 | 내용 | 크기 |
|---|---|---|
| **P1** | 이관 훅(Save As · 이름 없는 탭 → 파일 · 이름 바꾸기) + **프로젝트 모드 = 탭 블록**(`vars=<id>` · 복원 재매핑) + 파일·폴더 모드 기록에 v2 메타 줄(`path`·`size`·`head`·`saved` · `fsid`는 P2) | 중 |
| **P2** | `fsid` 읽기(Windows `GetFileInformationByHandle` · Unix `dev/ino`) + 저장 뒤 갱신 + 열 때 불일치 → fsid 일치 → 지문 후보 → 변수 창 출처 줄/후보 UI | 중 |
| **P3** | 문서 id 주석 옵트인(`vars.doc_id`) + 복사본 감지 + 설정 3 · 위키 | 소 |

부하원: 열 때 `metadata` 1회 + 후보 판정은 `vars/` 폴더 목록 1회(수십 개 · 캐시) · 저장 때 `metadata` 1회 — [39 §3](39-resource-governance.md) "변수 보존" 행에 추가(스레드 0).
