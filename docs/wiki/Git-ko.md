# 편집기의 git

[English](Git) | **한국어**

연 파일이 git 추적 파일이면 Nexa SQL은 git **HEAD**의 판과 견주어 바뀐 곳을 보여 줍니다. 읽기만 합니다 — 커밋 · push · fetch는 하지 않습니다. git이 PATH에 있어야 합니다.

## 변경 띠와 상태줄

- **거터 띠**(`editor.git_gutter` · 켬) — 저장 표시 오른쪽의 둘째 띠: **추가** 줄(초록) · **수정** 줄(강조색) · 위쪽 줄이 **삭제**된 자리의 빨간 쐐기. 띠를 누르면 그 변경을 HEAD 글과 나란히 작은 팝업으로 봅니다(앞뒤 문맥 `editor.git_context` = 3줄).
- **상태줄**(`statusbar.git` · 켬) — 브랜치와 바뀐 파일 수(예: `main (3)`). 브랜치가 이미 받아 둔 원격 브랜치를 따르면 앞섬/뒤처짐도 보입니다: `main ↑2 ↓1 (3)`(0인 쪽은 생략). 이 PC에 이미 있는 정보만 씁니다 — 원격에 접속하지 않습니다.
- 갱신 = 유휴 중 `statusbar.git_secs`초(15)마다 · 저장 직후 · 탭을 바꿀 때. 상태줄 칸을 꺼도 거터는 계속 파일을 따라갑니다.

## 명령

명령 팔레트(Ctrl+Shift+P)의 **Edit** 묶음에 있고, 단축키 창에서 키를 붙일 수 있습니다:

| 명령 | id | 하는 일 |
|---|---|---|
| 다음 git 변경 / 이전 git 변경 | `git.next_hunk` · `git.prev_hunk` | 다음/이전 변경 덩어리로 커서를 옮깁니다(끝에서 처음으로) · 없으면 "이 탭에 git 변경이 없습니다" |
| 커서의 git 변경 되돌리기 | `git.revert_hunk` | 커서가 있는 변경 덩어리를 HEAD 글로 되돌립니다 — **되돌리기 한 단계**라 Ctrl+Z로 내 편집이 돌아옵니다 · 저장하기 전까지 파일은 **바뀌지 않습니다** |

큰 파일도 줄 단위로 정확히 비교합니다: 수천 줄 파일에서도 실제로 바뀐 줄만 표시됩니다.
