# 로컬 히스토리

[English](Local-History) | **한국어**

Nexa SQL은 작업한 내용의 **시점(스냅숏)**을 내 PC에 남깁니다 — 파일을 저장할 때마다, 그리고 데이터베이스 객체(뷰 · 프로시저 · 패키지 · 트리거 …)를 열거나 컴파일할 때마다. 실수로 덮어썼으면 시점 목록을 열어 지금 본문과 비교하고 되돌리면 됩니다.

- 어디로도 보내지 않습니다 — 시점은 앱 데이터 폴더(`settings.conf` 옆 `history/`)의 평문 `.sql` 파일입니다.
- 기본으로 켜져 있습니다(`history.enabled`). 오래된 시점은 자동으로 지웁니다(아래 수·크기 상한) · **고정한** 시점은 늘 남깁니다.

## 명령

넷 다 **명령 팔레트**(Ctrl+Shift+P)의 **File** 묶음에 있고, 단축키 창에서 키를 붙일 수 있습니다.

| 명령(팔레트) | id | 하는 일 |
|---|---|---|
| File: 로컬 히스토리… | `edit.history` | 활성 탭의 시점 목록(최신 먼저) · 하나를 고르면 지금 본문과 비교 탭에서 **비교** |
| File: 로컬 히스토리에서 복원… | `edit.history_restore` | 같은 목록 · 고르면 그 시점 본문을 **활성 탭에 넣습니다** · 서버에는 아무것도 보내지 않습니다(객체면 확인 뒤 직접 F5로 컴파일) · 복원 자체도 시점으로 남습니다 |
| File: 로컬 히스토리 시점 고정/해제… | `edit.history_pin` | 같은 목록 · 고르면 고정(목록에 📌 · 상한 정리에서 지우지 않음)하거나 고정을 풉니다 |
| File: 이 객체의 서버 변경 확인 | `edit.history_check` | 오브젝트 소스 탭에서: 서버에서 객체를 다시 읽어 마지막 서버 본과 비교 · 같으면 "server source unchanged since <시각>" · 다르면 **external** 시점으로 저장 + 상태줄·로그 "server source changed since <시각>" |

서버 변경 확인(수동·자동)에서 바뀐 것을 찾으면 **알림 카드**도 뜹니다 — 누르면 그 오브젝트 탭으로 가서 서버 본과 편집기 본문을 비교합니다.

명령은 **활성 탭**에 대해 동작합니다: 파일 탭(그 파일의 시점) 또는 탐색기에서 연 오브젝트 소스 탭(그 객체의 시점). 서버 변경 확인은 오브젝트 소스 탭에서만 됩니다.

## 시점 종류

| 종류(파일 이름에 들어감) | 언제 | 내용 |
|---|---|---|
| `save` | 파일을 저장할 때 | 저장한 파일 |
| `open` | 탐색기에서 객체를 열 때 | 서버가 준 소스 — "원본" |
| `compile` | 객체를 컴파일(F5)하기 직전 | 내 버퍼(서버가 거부해도 남음) |
| `server` | 컴파일이 성공한 뒤 | 서버가 지금 가진 소스(다시 읽음) |
| `restore` | 시점을 되돌릴 때 | 되돌린 본문 |
| `external` | 서버 변경 확인에서 달라진 것을 찾을 때 | 새 서버 소스(다른 사람이 바꾼 것) |

바로 앞 시점과 내용이 같으면 새로 저장하지 않습니다.

## 설정

설정 창에서 "로컬 히스토리"로 찾습니다:

| 키 | 기본값 | 뜻 |
|---|---|---|
| `history.enabled` | 켬 | 시점을 남길지 |
| `history.max_per_item` | 50 | 파일·객체당 시점 수 · 넘으면 오래된 것부터 지움(고정한 것은 보존) |
| `history.max_mb` | 200 | 전체 시점 크기 · 넘으면 오래된 것부터 지움 |
| `history.server_check_secs` | 0(끔) | **오브젝트 소스 탭으로 돌아올 때** 그 탭의 마지막 확인에서 이 초가 지났으면 서버 변경을 자동으로 확인 · 바뀌었으면 `external` 시점으로 저장하고 상태줄에 알림 · 같으면 아무것도 보이지 않음 · 뒤에서 주기적으로 묻지 않고, 이미 있는 접속만 씀 |
