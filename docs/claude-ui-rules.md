# UI 컨트롤 규칙(포커스 · hover · 마우스 라우팅 · 팝업)

> 2026-10-22에 CLAUDE.md §3에서 글자 그대로 옮겼다. 창·패널·컨트롤·팝업을 만들거나 고칠 때 읽는다. 자세한 배경 = [61 §2-2](61-core-design-and-working-rules.md).

- ★ **포커스 규칙(사용자 09-14 · 반복 버그)**: 한 창에 포커스 링은 **정확히 하나 이하**. nexa-ctl 버튼·콤보·체크박스는 MouseDown에서 스스로 `focused=true`가 되고 **스스로 끄지 않는다** → 컨트롤을 여러 개 담는 쪽(패널·창)이 **MouseDown마다 하나만 남기고 끄고**(`connect.rs own_focus`) · 창/패널이 포커스를 잃으면 전부 끈다. **컨트롤을 추가·배선할 때마다 점검**: ① 클릭 뒤 링 1개 ② 다른 컨트롤 클릭 뒤 앞 링 꺼짐 ③ 텍스트박스 클릭 뒤 버튼 링 0개 ④ Esc/창 전환 뒤 0개 — 실기 캡처로 확인하고 journal에 남긴다. ⑤ **가려지거나 교체되는 컨트롤은 일시 상태(hover·눌림·포커스)를 비운다**(`Button::clear_transient`) · 다시 보일 때 현재 커서로 hover 재판정 — 이벤트를 못 받는 동안 hover가 1.0에 멈춰 "선택된 것처럼" 남는 버그(09-14 Delete 무장).
- ★ **hover 효과 규칙(사용자 09-14)**: 마우스가 거쳐 가는 모든 대상이 이벤트를 만들어 속도를 떨어뜨리면 안 되고, **최종 위치가 아닌 대상의 효과는 즉시 취소**된다. 구현은 nexa-ctl `tokens::IntentFade` 하나로(행·콤보 항목·버튼 공통): 사건은 목표 **덮어쓰기만**(큐 0 · 비용 0) → `tick`이 70ms 머문 **마지막 목표만** 페이드에 넘김 → 목표가 바뀌면 켜지던 것은 바로 꺼짐. 속도 = 컨트롤 속성 `FadeSpeed { Fast, Slow }`(버튼·콤보 = Fast · 행 = Slow · `set_fade_speed`) → 실제 ms는 설정 `ui.fade_fast`(500)/`ui.fade_slow`(1000)에 연계 · 키보드 이동은 `jump`(즉시). 새 hover 효과를 넣을 때 자체 타이머·큐를 만들지 말고 이 부품을 쓴다.
- ★ **마우스 라우팅 규칙(사용자 09-15 · 다른 앱에서도 재발)**: 컨트롤을 여러 개 담는 창/패널은 **MouseDown/Up/휠을 커서 아래 컨트롤(`bounds().contains(p)`)에만** 전달한다 — 컨트롤이 스스로 걸러 주리라 기대하지 않는다(`prefs_win.rs route`). 컨트롤 자체의 히트 테스트도 **x·y 둘 다**(y만 보고 행을 고르던 nexa-ctl 트리 결함 = 오른쪽 클릭이 왼쪽 메뉴를 선택). 키 사건은 포커스 컨트롤에만. MouseMove는 hover용으로 넓게 보내도 된다. 새 창·패널을 만들 때 "클릭이 영역 밖 컨트롤에 닿는가"를 실기로 한 번 확인한다.
- ★ **팝업 배치 규칙(사용자 09-21 "모든 우클릭 메뉴·툴팁은 화면에서 잘리지 않게")**: 떠서 그려지는 것(우클릭 메뉴 · 하위 메뉴 · 툴팁 · 드롭다운 · HUD · 카드)은 **창(그리기 표면) 밖으로 나가면 안 된다**. ① 위치는 직접 계산하지 말고 nexa-ctl의 공용 규칙을 쓴다 — `geom::place_popup`(정방향 → 반대쪽 → 밀어 넣기) · 이미 놓인 것은 `geom::nudge_into` · 영역은 `geom::popup_host(host, ctx.surface_size())` ② 우클릭 메뉴 = `ContextMenu` · 툴팁 = `draw::draw_tooltip(_in)` · 드롭다운 = `Combo`만 쓴다(셋 다 그리는 시점에 표면 크기를 배워 스스로 들어온다 — 호출자가 영역을 잘못 넘겨도 잘리지 않는 안전망) · **글자 상자를 직접 그려 툴팁·메뉴를 흉내 내지 않는다** ③ `open_at`의 `host`에는 아는 한 **창 전체 Rect**를 넘긴다(모르는 자리만 끝없는 영역 — 그때는 주석으로 안전망에 기댄다고 적는다) ④ 새 팝업을 만들면 **창의 네 모서리 근처에서 연 캡처**를 한 번 남긴다(짧은 창 = 격리 폴더의 `window.main_size` · 기동 명령으로 메뉴를 여는 길을 같이 만든다 — 예 `result.menu`) ⑤ 팝업이 창보다 크면 잘리는 대신 **스크롤**이 있어야 한다(지금은 메뉴 항목 수를 창 높이 안으로 유지). 자세히 = [61 §2-2](docs/61-core-design-and-working-rules.md).
- ★ **팝업/메뉴 UX 규칙(사용자 09-14 "UX 관점에서 섬세하게")**: 우클릭 메뉴·입력란 편집 메뉴·콤보 드롭다운은 열려 있는 동안 모달이되, **바깥 좌/우클릭은 메뉴를 닫고 그 클릭을 그대로 진행**한다(다른 컨트롤 선택·포커스 이동·새 메뉴가 한 번의 클릭으로 · `conn_win.rs route` `outside_click`). 항목 선택·Esc는 닫기만. 팝업은 창의 **맨 마지막**에 그린다(다른 컨트롤이 덮지 않게 · `paint_popups`). 닫힌 직후 커서 아래 대상을 다시 hover 판정(`rehover`). 기능을 막거나 추가할 때는 사용자의 다음 동작이 한 번의 입력으로 이어지는지 먼저 본다. ★ **편집·팝업 UX 기본 6칙(09-26 · [61 §2-2-b](docs/61-core-design-and-working-rules.md))** = 편집 진입 글자 제자리 · 긴 글 첫머리부터 · 팝업은 선택을 가리지 않음(셀 아래) · 팝업 최상위 층 · 팝업 열림 중 클릭은 팝업에만(팝업 사각형 판정) · Esc 취소/Enter 확정 — 국제 표준 대조 = [88](docs/88-ui-ux-standards-survey.md).
