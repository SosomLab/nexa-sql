## 1. 핵심 설계 — 불변식과 금지 사항

### 1-1. 편집 버퍼 `TextBuf`(nexa-ctl `edit/textbuf.rs` · [59 §6](59-large-file-handling.md))

- 저장 = UTF-8 갭 버퍼(`Vec<u8>` + 갭 하나) + **줄 시작 표**(줄마다 바이트 시작 · 글자 시작) + **줄 변경 기록**(`LineChange{first, removed, inserted}` · 통째 교체 세대 `epoch`).
- **좌표는 글자(char) 인덱스다.** 캐럿 · 선택 · 되돌리기 기록 · 기록 파일 · 호스트의 찾기/실행 범위/오류 줄이 전부 글자 단위다. 바이트 오프셋은 `textbuf.rs` 밖으로 나가지 않는다.
- 불변식: 갭의 양 끝은 글자 경계 · `lines[0] = (0, 0)` · `lines[k]` = k번째 `'\n'` 바로 뒤 · 논리 바이트열은 늘 온전한 UTF-8 · `unsafe` 0.
- **규칙 ①**: 본문 전체를 글자 배열(`Vec<char>`)이나 문자열(`String`)로 뜨는 코드를 **자주 도는 길**(키 입력 · 그리기 · 틱 · 상태줄)에 새로 넣지 않는다. `buf()`의 줄·구간 조회(`get` · `slice` · `iter_from`/`iter_rev_from` · `line_of`/`line_start`/`line_end`/`line_text` · `find` · `eq_str` · `byte_len` · `content_hash`)를 쓴다. 동작 한 번에 한 번(실행 · 정규식 찾기 · 저장)은 괜찮다. `EditState::chars_vec()`는 드문 명령·테스트 전용이다.
- **규칙 ②**: 줄별 캐시를 새로 만들면 **변경 기록의 소비자**로 만든다 — `(epoch, seq)`를 들고 `changes_since(seq)`로 바뀐 줄만 고치고, `None`(기록이 버려짐)이나 `epoch` 불일치면 전부 다시. 본문 세대(`rev`)만 보고 전 줄을 다시 계산하지 않는다(본보기 = `RowWidthCache` · `LineHlCache`).
- **규칙 ③**: 본문을 통째로 바꾸는 길은 `set_string`/`adopt`뿐이다(세대가 이어서 오른다 — 새 `TextBuf`로 그냥 갈아 끼우면 캐시가 "같은 세대"로 착각한다).
- 아직 본문 전체를 보는 것: 줄 변경 표시(기준선 비교) · 괄호 짝 표 · 접기(wrap) 모드 → T-145.

### 1-2. 되돌리기(nexa-ctl `edit.rs` · [60](60-undo-redo-redesign.md))

- 기록 = 연산 `Op{pos, remove_n, insert, insert_n}` · 적용하면 역연산이 나온다(되돌리기와 다시 실행이 한 함수) · **저장하는 것은 지운 글자뿐** · 묶음 안의 연산은 **뒤에서 앞으로** 적용.
- **규칙 ④ — 본문을 바꾸는 길은 셋뿐**: `splice_rec(_str)`(한 곳) · `replace_many_inner`(여러 곳) · `apply_ops`(되돌리기). 새 편집 기능은 이 셋 위에 짓는다 — `buf.splice`를 직접 부르면 세대(`rev`) · 기록 · 읽기 전용 · 거대 편집 확인이 전부 빠진다(83차에 실제로 있던 결함).
- 저장 지점 = 상태 id(`mark_saved`/`is_saved` · O(1)). 호스트는 본문 비교 전에 이것부터 본다. 저장하면 열린 타이핑 묶음을 끊는다.
- 메모리 = 바이트 예산(`editor.undo_budget_mb`) + 개수 상한 보조 · 최신 1단계는 늘 남긴다.
- 묶음 규칙 = 인접 타이핑·Backspace·Delete 합치기 + 단어 경계 + (보조) 긴 정지(`editor.undo_group_ms`). 시간 단독 기준은 쓰지 않는다.
- **거대 편집 확인**(`editor.undo_giant_mb`): 확인 수단은 **지우는 동작의 되풀이**(Delete · Backspace · 잘라내기 · 편집 명령 · 모두 바꾸기)뿐이다. **타이핑·붙여넣기·IME는 확인이 되지 않는다** — 새 편집 진입점을 만들면 `giant_refused(bytes, confirmable)`를 먼저 부르고 끝에 `giant_done()`.
- **기록 파일**(`undofile.rs` · `export_history`/`import_history`): 저장할 때 쓰고 · 열 때 본문 길이·해시가 같으면 들이고 · 하나라도 어긋나면 **통째로 버린다**(부분 복구 없음). 형식의 좌표 단위가 바뀌면 `HISTORY_VERSION`을 올린다. 기록에는 지운 글자가 평문으로 들어간다 — 설정 폴더 밖에 두지 않는다.

### 1-3. 큰 파일 · 적재(nexa-sql `editors.rs` · `fileload.rs` · [59 §5](59-large-file-handling.md))

- 큰 파일 모드 L1/L2 = 기능을 **끈다**(미니맵 · 선택어 강조 · 기준선 / + 구문 강조). 큰 탭은 **저장본 사본을 들지 않는다** → 더러움 = 저장 지점, 외부 변경 = 자동 병합 없이 띠로 묻는다, 기록 파일도 쓰지 않는다. 새 기능이 `saved[i]`(저장본 사본)에 기대면 큰 탭에서 빈 문자열을 본다는 것을 기억한다.
- **적재는 탭 안에 가둔다**: 8 MB 이상 = 자리 탭(`begin_load_tab` — 비어 있음 · 읽기 전용 · **경로 없음**) → 작업 스레드(읽기 → 글자 풀이 → `PreparedText`) → `fill_loaded`(활성 탭을 **빼앗지 않는다**). 진행 막은 그 탭이 활성일 때만 · 0.3초 넘게 걸릴 때만 · 100% 프레임 뒤에 편집 화면.
- **규칙 ⑤**: 오래 걸리는 일 때문에 **창 전체의 입력을 막지 않는다**(사용자 09-20 — 처음 요구를 같은 날 뒤집음). 막는 범위 = 그 일의 대상 하나(탭). 막는 명령의 판정은 순수 함수 + 테스트(`fileload::blocked_while_loading`).
- **규칙 ⑥**: 뒤에서 끝난 일이 실행으로 이어질 때는 **시작할 때의 탭(세션)** 을 확인한다 — "열지 않고 실행"은 읽는 사이 활성 탭이 바뀌면 실행하지 않는다(다른 접속 = 운영일 수도 있다).
- **규칙 ⑦**: 무거운 준비는 스레드에서, UI 스레드는 **옮겨 받기만**(`PreparedText` · `set_prepared` · 0 ms). 읽기 경로에 사본을 만들지 않는다(`decode_owned` · `detect_owned` — 온전한 UTF-8 · LF 파일이면 읽은 버퍼가 그대로 본문).
- 뷰 탭(본문 없는 탭 · 확장 상세 `ext_view.rs`): 편집 입력·찾기·실행이 가지 않는다 · 닫을 때 저장을 묻지 않는다. 읽을거리 "문서"(안내 탭)와 구분한다 — 화면이면 뷰 탭, 글이면 Plain Text + No connection 안내 탭.

### 1-6. 09-21(Windows 89차)에 굳은 것 — 능력표 · PG 커서 · 입력

- **엔진·러너는 방언을 묻지 않는다 — `Caps`를 묻는다**(`nsql-core/caps.rs` · T-152): 새 분기가 필요하면 `Dialect` `match`를 쓰지 말고 능력표에 칸을 더한다(전수 테스트 `table_matches_the_former_dialect_branches`에 한 줄) · 세션이 붙으면 `Engine::set_caps(방언, session.caps())` · 남겨 둔 방언 분기 = 값 인용(`to_sql_literal`)과 카탈로그 질의뿐.
- **자동 커밋 모드의 `COMMIT`은 `caps.autocommit_needs_commit(tx_open, tx_user)`가 참일 때만**(T-155) · CLI 종료 = `Runner::commit_at_exit`.
- **PG refcursor는 드라이버가 푼다**(T-150): 결과의 글자 값이 열린 커서 이름이면 그 자리에서 `FETCH … IN` → 결과 집합 + `result_labels` · 자동 커밋이면 호출과 FETCH를 한 트랜잭션으로 · 러너·GUI는 모른다(Oracle 핸들 커서와 같은 "결과 + 라벨" 모양).
- **PG 호출의 OUT 값은 서명이 말한 자리의 바인드가 받는다**(T-151 · `Engine.call_captures` — 한 번 쓰이고 비워진다).
- **`ACCEPT`는 실행할 때마다 묻는다**: GUI = 실행 전 입력 창이 한 번에(`InputNeed{prompt,default,hide}`) → `apply_inputs`가 `Engine.accepted`에 표시 → 러너는 그 `ACCEPT`를 지나간다 · CLI = 그 자리에서 묻는다.
- **실서버 통합 테스트는 프로필로**: `NSQL_PG_PROFILE=<볼트 프로필 이름>`(비밀번호를 환경 변수·명령줄에 쓰지 않는다) · 서버에는 `pg_temp` 임시 객체만 만든다.
- **날짜·불리언은 진짜 타입으로 바인드한다**(Oracle · T-151): 값이 ISO 꼴(`YYYY-MM-DD[ HH:MM[:SS[.f]]]`)이면 `OracleType::Date`/`Timestamp`, 아니면 종전처럼 글자(서버의 암묵 변환). 변수 값의 표시도 ISO 꼴 — 결과 그리드의 DATE 열과 같다.
- **T-SQL 호출의 `OUTPUT`은 서명이 보충한다**(`Caps::call_signature = OutputMarks` · `Engine.call_outputs` — 한 번 쓰이고 비워진다) · **선언 없이 생긴 글자 변수는 값이 돌아오는 바인드에서만 4000으로 넓힌다**(`dialect.rs bind_type` — 선언한 길이는 사용자의 뜻).
- **미정의 바인드 경고는 읽기만 하는 보통 SQL에서만** — 블록·`EXEC`의 바인드는 받는 쪽일 수 있다.
- **시스템 변수는 `Engine.sysvars`에**(사용자 `DEFINE`과 섞지 않는다 · 이름 = `SYSTEM_VARS`) · `${이름:형식}`은 정의된 이름 + 아는 형식만 바꾼다(모르면 글자 그대로 · 묻지 않는다).
- **새 부하원은 스위치와 함께**: 결과에 영향을 주면 개별 설정(`vars.signature_lookup` · `pg.refcursor_expand`), 영향이 없으면 `perf::BOOST` 후보(39 §4-6). 실서버 시험은 프로필 환경 변수 셋(`NSQL_ORACLE_PROFILE` · `NSQL_MSSQL_PROFILE` · `NSQL_PG_PROFILE`) — Oracle은 객체를 만들지 않고(익명 블록 · SYS 패키지), SQL Server는 세션 임시 프로시저(`#…`)만.
- **큰 파일 탭은 상시 비용이 드는 기능을 단계별로 끈다 — 새 기능(특히 확장 효과·플러그인 훅)을 넣을 때 `editors.rs enforce_large`에 한 줄**(`feature_limited(level, 기준)` · 기준은 설정 · 편집 코어는 끄지 않는다 · 단계가 내려가면 `restore_large_features`로 되돌린다).
- **설정의 종속은 `DEPENDS`로**(부모가 조건을 못 채우면 설정 창에서 잠김 + 흐림) · 키를 바꾸면 옛 값은 `migrate_*`로 옮긴다(`grid.result_tabbar` → `grid.result_tabbar_single`).
- 자체 캡처: 설정 창은 `NSQL_STARTUP_CMD=edit.prefs:<검색어>`로 그 카드만 보이게 연다 · 격리 폴더의 `settings.conf`는 **`키=값`(공백 없음)** — 덧붙인 뒤 `nsql config get <키>`(같은 `NSQL_HOME`)로 읽히는지 확인한다.
- **결과 탭 제목 = 번호 규칙이 기본**(`결과N` · 가장 큰 번호 + 1 · `results.rs numbered_index`가 두 언어의 틀을 읽는다) · 사용자가 붙인 이름(`named`)과 커서 라벨은 덮지 않는다.
- **DBMS별 종속 설정은 "자동 탐지 / 직접 지정 / 읽기 전용 정보" 틀로**([64 §2](64-dbms-clients-and-driver-packaging.md)): 계산 값은 `nsql_settings::INFO_KEYS`(저장 안 함 · `set` 거부 · 설정 창에서 늘 잠김) · 탐지는 파일 시스템만 읽는다 · **직접 지정한 것은 그것만 쓴다**(조용히 다른 것으로 넘어가지 않는다 — 실패가 낫다) · 드라이버는 값만 돌려주고 문구는 호스트가 `Msg`로.
- **`${…:q}`** = 작은따옴표로 감싸고 안의 작은따옴표는 두 번 · SQL Server `N'…'` · MySQL 역슬래시 두 번(`engine.rs sql_text_literal`).
- **마우스 이동·키 처리 경로에서 `edit.text()`·`chars_vec()`를 부르지 않는다** — 줄·구간 조회는 `edit.buf()`의 줄 표로(`line_of` · `line_start` · `line_end`). 89차 추가: 드래그 처리가 사건마다 본문 전체를 문자열로 만들어 20 MB에서 12.7 ms/이동이었다 → 입력 경로를 고치면 `bench_editor`에 그 시나리오를 더한다.
- **드래그 선택은 포인터가 컨트롤 밖에 있어도 세로 위치를 따라간다**(옆 밖 = 그 줄의 처음/끝 · 한 글자씩 미는 가로 자동 스크롤은 같은 줄에 가려진 글이 있을 때만).
- **"잠금"은 사건 전달을 막는 것으로 끝나지 않는다** — 포커스 지정 · 키/IME/붙여넣기 경로(`focused_textbox`) · 값 수거 · 잠금 재계산 시점 넷을 다 본다. 글자 칸은 nexa-ctl 읽기 전용(`set_read_only` — 복사는 되고 편집은 편집 코어가 거부)으로, 나머지는 포커스를 주지 않는다(`prefs_win.rs apply_deps` · 89차 추가 7).
- **창은 만들 때 모니터 안으로**(`wingeom::keep_on_screen`) — 새 창을 추가하면 생성 직후 한 줄.

### 1-7. 데이터 보호 불변식(09-26 · 사용자 핵심 규칙 · [87 §14](87-grid-data-editing.md))

프로그램이 사용자 대신 만든 쓰기 문장(그리드 셀 편집의 UPDATE/DELETE, 앞으로의 어떤 자동 생성 DML도)은 **세 겹**을 지난다: ① **사전 검사** — 같은 WHERE로 `SELECT COUNT(*)`를 먼저 보내 대상이 정확히 1행인지 전부 확인(하나라도 아니면 쓰기 0) ② **영향 행 수 = 1** — 실행한 문장의 affected가 1이 아니면 그 자리에서 멈춘다(설정으로 끌 수 없다) ③ **되돌림** — 자동 커밋 모드는 전체 롤백 · 수동 커밋 모드는 `SAVEPOINT nsql_edit`로 이번 적용분만 되돌리고(앞선 작업 보존) 사용자에게 원인(단계 · 문장 라벨 `UPDATE #행 (키=값)` · 메시지/행 수)과 함께 "필요하면 ROLLBACK"을 알린다 · 되돌리기까지 실패하면 "⚠ ROLLBACK 필요"를 토스트+상태줄+로그로. 유일성은 적용 대기 변경 안 키 중복을 미리 거부하고(NULL 키 제외) 서버 제약 오류는 ②·③으로 받는다. 구현 = `nsql_run::Runner::apply_changes` 한 곳 · `ApplyStmt{req, guard, label}` · 시험 = 모의 세션(사전 검사 실패 = 쓰기 0 · 실행 실패 = 롤백/세이브포인트).

### 1-8. 지연 로딩 = 모든 설계의 기본(09-28 · 사용자 "필요한 시점에 필요한 데이터를 조회하는 Lazy loading이 모든 설계의 기본")

> 예(10-23) = 삭제 대기 드라이버 정리 `sweep_pending()` — 기동마다 폴더를 훑지 않고 표식 파일 `.delete-pending` 하나만 본다(없으면 stat 1).

- **화면에 지금 보이거나 지금 쓰는 것만 읽는다.** 한 객체에 딸린 데이터가 다섯 가지면 지금 필요한 것만 먼저 읽고 나머지는 그것이 필요해지는 순간(펼침 · 탭 전환 · 스크롤 도달 · 클릭)에 읽는다. 예: 객체 상세 패널이 접힌 한 줄 모드면 **설명(코멘트)만** — 상세 섹션은 ▲로 펼치는 순간 청한다([86 §5-2](86-object-details-panel.md)).
- **이미 있으면 즉시 배정.** 필요해지는 순간 캐시(`detail_cache` · 메타 L1/L2 · 탐색기 노드)에 있으면 왕복 없이 바로 채운다(깜빡임 0) · TTL이 지났거나 `dirty`면 보이는 채로 다시 읽어 교체.
- **미리 읽기는 예외이며 근거가 있어야 한다**: 유휴 시간에 · 상한 안에서 · 설정으로 끌 수 있게(39 §3 부하원 원장 · 85 L2 워머처럼) — "곧 필요할 것 같아서"는 근거가 아니다.
- 새 기능 체크리스트(30 §1-2)에 한 줄: *지금 안 보이는 데이터를 읽고 있지 않은가? 읽는다면 어느 사건에서 읽어야 하나?*

### 1-9. 타이밍 기법(스로틀 · 디바운스 · 배치 · 주기 점검)의 목적 = 데이터 일관성 + 불필요한 수행 최소화(09-28 · 사용자)

사용자 09-28: "이 모든 기법은 **데이터 일관성을 확보하면서 불필요한 진행을 최소화**하기 위한 것이다. 제일 중요한 것은 **사용성을 훼손하지 않으면서 데이터 유실도 없이 빠르게** 기능을 수행하는 것."

- 새 타이머·큐·배치를 만들 때 **먼저 정할 것** — ① 창의 앵커가 첫 사건(트레일링 스로틀 · 프로젝트/파일 저장 · [70 §7-1](70-autosave-and-restore.md))인가 마지막 사건(트레일링 디바운스 · 설정 저장 · 잦은 호출)인가 ② 감시되지 않는 변경 요인이 있으면 **주기 안전망**을 두되 문서가 같으면 쓰지 않는다 ③ 저장·수행이 끝나면 타이머를 초기화해 횟수를 줄인다.
- **판정 순서** = 데이터 유실 없음(종료·전환·닫기 길은 디바운스를 기다리지 않고 지금 저장 `flush_on_exit`) → 사용성(입력을 막지 않는다 · 상태줄 표식으로 "아직 안 씀"을 보여 준다) → 속도·횟수(합치기·건너뛰기). 횟수를 줄이려고 유실 가능성을 만드는 선택은 하지 않는다.
- 부품 원장 = [30 §2](30-architecture-patterns.md) "타이밍 두 벌".

### 1-10. 메타는 서버별 1벌 · 접근성은 세션 계정(사용자 09-30)

같은 서버의 연결 N개는 메타(이름·컬럼·코멘트)를 한 벌만 갖는다. 그러나 **어떤 세션이 어떤 객체를 볼 수 있는가는 그 세션의 계정·현재 스키마로 판정**한다 — 현재 세션에
권한이 없는 행위·설명·객체 접근이 허용되는 것처럼 보여서는 안 된다. 규칙 = [96 §6](96-object-links.md) `schema_visible`(현재 스키마 · PUBLIC · 자기 계정이 수집한 스키마).

### 1-12. 실행 통제의 순서(10-01 · 사용자)
- **① 실행할 것이 있는가 → ② 어디로 가는가 → ③ 운영이면 확인.** 바꿀 것이 없는 항목(지금 유형과 같은 `CONNTYPE` 등 · `sessions::run_needed_items`)은 실행하지 않고 "변경 없음"만 알린다. 운영 2단 확인(`prod_confirm_needed`)은 **서버에 변경을 보내는 문장**과 **운영 유형을 내리는 `CONNTYPE`**(보호를 푸는 변경 · 팔레트·메뉴도 `env_change_needs_confirm`)에 — 그 밖의 클라이언트 전용 명령(`is_client_only`)은 세지 않는다. 새 통제를 넣을 때 이 순서를 지킨다(판정은 `sessions.rs` 순수 함수 + 시험).
- **서버 유형 변경 = 알림 게이트 하나(10-15 · 127차 · 사용자 "서버 유형 변경은 관련 기능 전체에 Announce")**: 세션의 유형(영속 프로필 · 임시 `env_temp`)을 바꾸는 코드는 **`announce_env_change`(app/grid_results.rs)를 지난다**(그리드 `set_prod` 재판정 · 세션 UI 표식 · `sync_gate` · 다시 그리기) — 진입점 = 접속 · 세션 메뉴/팔레트/`CONNTYPE`(`set_session_env`) · 프로필 편집 반영(`apply_profile_env`). **유형을 캐시하는 소비자를 새로 만들면 그 함수에 등재**한다(접속 때 한 번만 받아 두면 유형을 바꿔도 낡은 값이 남는다 = 127차 결함).
- **현재 문장 고르기(10-13 · 사용자 결함 "그리드에서 Ctrl+Enter = 파일 첫 블록 실행")**: ① **편집기 선택이 있으면 선택 글** — 포커스가 그리드에 있어도(종전 `copy_selection()`은 편집기 포커스가 없으면 None → 선택 무시) · ② 없으면 캐럿 문장 · 캐럿이 **문장 사이**(빈 줄·주석)면 **줄 거리가 가까운 쪽**(동률·같은 줄 꼬리 주석 = 앞 문장 · nsql-script `statement_at_in`) — 종전 = 늘 앞 문장이라 빈 줄 16행에서 14줄 위 첫 블록이 돌았음. 협업 V1 = SQLite·Oracle 4조합 ✓.

  규칙: ① 위치를 직접 계산하지 않는다(위 세 부품 · `place_popup`/`nudge_into`/`popup_host`) ② 글자 상자를 직접 그려 툴팁·메뉴를 흉내 내지 않는다 ③ `host`는 아는 한 창 전체 Rect(끝없는 영역을 넘기는 자리는 주석으로 안전망에 기댄다고 적는다 — 지금 결과 탭 · 편집기 탭 · 접속 창 네 곳) ④ 새 팝업 = 창 모서리 근처에서 연 캡처 1장(짧은 창 = 격리 폴더 `window.main_size` · 기동 명령으로 여는 길을 같이 만든다) ⑤ 창보다 큰 팝업은 스크롤이 있어야 한다 ⑥ **범위 인자는 창 좌표 사각형**(10-15 · 127차) — 패널 폭·높이 같은 **크기 값을 x/y 상한으로 쓰지 않는다**(패널이 창 왼쪽 끝이 아니면 그만큼 밀린다 · `FilterBar::clamp_x` = 틀 자리 `area`의 창 좌표). `DrawCtx::surface_size()`를 구현하지 않은 그리기 컨텍스트(테스트 기록기)는 `None` = 종전 동작.

#### 2-2-b. 편집·팝업 UX 기본 규칙(사용자 09-26 "당연한 것들이 안 지켜진다" · §218 · 상세 = [88](88-ui-ux-standards-survey.md))

1. **편집에 들어가도 글자는 제자리** — 인라인 편집 상자는 표시 글자와 같은 x 여백·같은 세로 기준선·같은 글꼴로 그린다(nexa-ctl `TextBox::set_cell_pad`). 둥근 틀·테두리를 덧입혀 글자를 밀지 않는다.
2. **긴 글은 첫머리부터** — 편집 진입 = 전체 선택 + 캐럿 **앞**(`End → Shift+Home`) · 표시 폭은 셀과 같게(오른쪽 여백 0) → 잘려 보이지 않는다.
3. **팝업은 선택·편집 중인 내용을 가리지 않는다** — 셀 편집 모드의 우클릭 메뉴는 셀 아래에 연다 · 툴팁/카드도 앵커 옆.
4. **팝업은 항상 최상위** — 창의 팝업 층(`paint_overlays`/`paint_popup` · 마지막 패스)에서 그린다 · 편집 테두리·이웃 셀·스플리터가 덮지 않는다(`set_popup_deferred`).
5. **팝업이 열려 있는 동안의 클릭은 팝업에만** — 항목 클릭 = 기능만(복사·잘라내기·붙여넣기 실행) · 아래 셀/캐럿/포커스로 새지 않는다 · 바깥 클릭 = 닫고 그 클릭은 진행(§3 팝업 규칙) · 판정은 **팝업 사각형**(`popup_bounds`)으로(팝업은 소유 컨트롤 밖으로 펼쳐진다).
6. **Esc = 취소 · Enter = 확정(+아래) · Tab = 확정(+오른쪽)** · 검증 실패 = 상자에 남고 붉은 띠 + 안내 · 되돌리기는 어디서나.
7. 새 편집 UI를 만들면 이 여섯을 격리 캡처/시험으로 한 번 확인하고 journal에 남긴다(nexa-ctl 시험 `menu_item_click_does_not_move_caret`).

8. **오버레이 스크롤바는 사용자 입력에서만 보인다**(사용자 10-08 "탭 클릭 때 세로 스크롤바가 보인다" · fda9ade) — 막대를 깨우는(`bars.show()`) 길은 휠 · 드래그 · 썸 접근(`ScrollBars::on_event`)과 **키보드 선택 따라가기**(`reveal_selection`)뿐 · 코드가 옮긴 스크롤(탭 연결 동기 `focus_server → after_reveal` · 찾기 · 객체 탐색기에서 보기 · 복원)은 위치가 바뀌어도 막대를 깨우지 않는다 · 새 "코드가 스크롤을 옮기는" 길을 만들면 `show()`를 부르지 않는지 확인한다. · **영역이 포인터를 잃으면 호스트가 그 영역에 "밖" MouseMove를 한 번 준다**(hover 이탈 통지 · 스크롤바 썸 두꺼움·툴팁 hover 정리 · 10-08 e955ea7) — 포인터가 나간 영역은 MouseMove를 더 못 받으므로 컨트롤이 스스로 hover를 걷을 수 없다 · 스크롤바를 가진 새 영역을 추가하면 `app/input.rs` `route_inner`의 이탈 통지 목록과 `pointer_gone` 목록에 함께 넣는다.

9. **클릭은 놓을 때**(사용자 10-09 "급박한 UI가 아니면 MouseDown을 직접 쓰지 않는다 · 업계 표준" · af9a280 · nexa-ui 5a04e13) — 동작(명령 실행·토글·확정)은 **같은 자리에서 누르고 놓을 때**만: Down = 자리 기억(삼킴) · 같은 자리 Up = 동작 · 다른 자리 Up = 무동작(취소). 대상 = 토스트 · 외부 변경 띠 · 트랜잭션 경고 카드 · 실행 카드 · 상태줄 항목 · Ctrl 객체 링크 · 접속 창 복사 버튼 · 체크박스 · 스위치 · 풀다운 항목(누른 채 끌어 다른 항목에서 놓으면 그 항목 = Windows 메뉴 표준) · 버튼은 원래 Up. **Down 그대로인 예외** = 선택·캐럿·드래그 시작·메뉴/콤보/우클릭 메뉴 열기·풀다운 라벨 열기/닫기·바깥 클릭 닫기(표준 · 지연 없는 반응) · 부품 = 겹침 요소 `OverlayZone`(누름/놓음 짝 · `overlay_zone_at`/`overlay_act`) · nexa-ctl `Checkbox`/`Switch` `pressed` · `MenuBar` `pressed_entry`.

10. **우클릭 메뉴는 영역 간 배타**(사용자 10-08/09 "각 영역의 우클릭 메뉴는 다른 영역에서 우클릭·좌클릭·키 입력이 있으면 숨김 · 바로 반응할지는 설정" · beefed8 · af9a280) — 열린 메뉴 **밖** 좌/우 클릭 = 그 메뉴들 닫기 · 메뉴가 쓰지 않는 키 = 전부 닫기 · 설정 `ui.ctxmenu_exclusive`(켬 · 끔 = 종전) · `ui.ctxmenu_passthrough`(켬 = 닫는 클릭이 바로 동작 = 다른 곳 우클릭이면 새 메뉴 즉시 · 끔 = 닫기만, 다시 클릭) · 판정 = 순수 함수 `ctxmenu_exclusive_step`(MC/DC 9) · 좌표 판정 = `menu_hit_bits`(메뉴바·완성 팝업 제외) · 메뉴 사각형 = `menu_bounds` 부품.
10-1. **모든 우클릭 메뉴 = 공용 입구 `menu_icons::open_at`**(사용자 10-13) — 아이콘 칸은 늘 있다(nexa-ctl `set_icon_col_always` · 아이콘 없는 항목도 글 시작 x가 같음) · id → 아이콘은 `menu_icons::decorate` 한 자리(하위 메뉴 재귀) · 향상 모드(`ui.menu_icons` FORCED off) = 아이콘 생성·그리기 0 · 칸만 유지 · **새 우클릭 메뉴는 `ContextMenu::open_at`을 직접 부르지 않는다**. 팝업 배타는 스플리터·커서 모양에도 — 새 영역 라우팅을 넣을 때 `open_menus()` 게이트를 먼저(10-13 스플리터 결함).
10-2. **메뉴 캡션에 "…"를 붙이지 않는다**(사용자 10-13 2차 "다른 메뉴에도" · 1차 = "입력 대화상자가 올 때만 …"은 폐기) — 풀다운·우클릭·툴바 메뉴의 모든 `Mn*` 캡션(열기 · 다른 이름으로 저장 · 이름 바꾸기 · 프로젝트 · 필터 조건 · 툴바/상태바 설정 등 66곳)에서 뺐다 · 한국어 "…로 시작…" 꼴 = "시작 글" · 새 메뉴 항목도 "…" 없이 · 확인 = 파일 메뉴 · 결과 탭 메뉴 · 그리드 머리글/셀 메뉴 캡처.
10-3. **언어 전환 = 생성 때 굳힌 글도 다시 단다**(사용자 10-13) — `t()`로 만들 때 한 번 넣은 글(플레이스홀더 · 스위치 라벨 · 버튼 · 창 제목)은 `App::relabel`이 부품별 `relabel()`을 불러 다시 단다 · 새 부품에 글을 넣으면 `relabel()`도 같이 · 시험 = 격리 홈 `config.set:ui.lang=en`(또는 동작 id `view.lang:en`) → 패널·창 캡처 → `=ko` 복귀 · **모달리스 창도 대상**(객체 찾기 창 10-16 ㊲ = 체크박스는 라벨 setter가 없으면 체크 상태를 지키며 재생성 · 열린 창 제목 `set_title`까지).
10-4. **팝업 소유 상자의 클릭은 "다른 영역"이 아니다**(사용자 10-13) — 우클릭 메뉴 배타·바깥 클릭 판정의 히트 영역에 **팝업을 연 상자 자체 bounds를 합친다**(FilterBar·CondBar·Grid 행수/셀 편집기·SearchPanel·FindBar·ObjDetail) · 아니면 상자 재클릭이 "바깥 → 닫고 통과"가 되어 토글이 다시 열린다 · 이력 드롭다운 토글 = `Recall::toggled_off`(같은 사건의 `on_click` 건너뜀) + `FilterBar::popup_keeps` = 상자 자체 누름이면 틀이 처리하고 끝(상자 밖 누름만 통과) · 입력창 팝업(편집 메뉴·이력·완성·값 고르기)도 `open_menus`/`menu_hit_bits`/`close_menu_bits` 비트로 배타에 들어간다 · 팝업이 열린 동안 마우스는 그 상자로(`tb.popup_open()`) — 담는 쪽이 영역 밖이라 버리면 메뉴 항목 클릭이 안 먹는다(10-13 전수 9곳).
10-5. **틱과 수신은 `||`로 묶지 않는다**(사용자 10-13 · 파일 검색 "검색 중…" 고착) — `if a.tick(now) || a.poll()`은 단락 평가라 애니메이션(혜성)이 도는 동안 `poll`이 한 번도 안 불린다 · 둘 다 늘 부르고 결과를 합친다(`let t = tick(); let p = poll(); t || p`).
10-6. **팝업이 열린 상자의 키·마우스는 그 상자(메뉴)가 먼저**(사용자 10-13) — 담는 쪽(패널·바)은 팝업이 열린 동안 Esc·Enter·↓ 등을 제 용도(필터 지우기·이력 열기·실행)로 가로채지 않는다 · 패널 머리 = "팝업 열림 + Key/Char → 상자로 보내고 끝" · 이력 분기는 `!popup_open()` 가드 · 편집 메뉴가 열린 상자가 둘 이상인 패널은 **소유 상자에만** 보낸다.
10-7. **팝업을 닫은 놓임(MouseUp)은 통과시키지 않는다**(사용자 10-13) — 바깥 클릭 = 닫고 통과는 **누름(MouseDown)만** · 메뉴 항목을 고른 놓임까지 아래로 흘리면 같은 자리 상자가 클릭으로 받아 방금 한 동작(전체 선택 등)을 되돌린다.
10-8. **툴팁 앵커 = 항목 사각형 그대로**(사용자 10-13) — 공용 `draw_tooltip_in`이 "항목 위"(nexa-ui 171 · `ui.tooltip_above`)로 스스로 올리므로 호출자는 앵커를 **미리 올리거나 아래 점(높이 0)으로 넘기지 않는다** — 이중 올림(툴바에 묻힘) · 점 위 배치(버튼을 덮음) 결함이 파일 검색·찾기 바·필터 틀·로그 창 스위치·프로젝트 행 경로에서 나왔다 · 아래가 맞는 것(IME 안내)만 `draw_tooltip_in_dir(…, false)`.
10-9. **팝업 열림 중 휠도 팝업 몫**(사용자 10-13) — 담는 쪽(패널 목록)의 스크롤바보다 **앞**에서 열린 팝업(이력 드롭다운·편집 메뉴)이 휠·가로 휠을 받고 끝 · 공용 필터 틀 `popup_takes`도 휠 포함.

11. **메뉴를 여는 항목은 다시 누르면 닫는다**(사용자 10-09 · 65eab8d) — 상태바 항목(들여쓰기·줄끝·자동 저장·트랜잭션·인코딩)의 좌클릭 메뉴는 같은 항목을 다시 누르면 닫힘(누름에서 닫고 그 놓음은 삼킴 = `menu_toggle_swallow_up` · `status_menu_item`) · 다른 항목을 누르면 그 항목의 메뉴로 바뀜(한 번의 클릭) · 툴바 ▾·풀다운 라벨과 같은 규칙 · **툴바 서버(`sess.tab`)·DB/스키마(`sess.db`) 드롭다운**도 열린 채 같은 항목을 다시 누르면 닫힘(누름에서 닫고 놓음 삼킴 · d07478a) · 열린 채 다른 드롭다운을 누르면 그 목록으로 바뀜(배타) · 바깥 클릭 = 닫힘. 협업 V1 bin119·120·123 ✓.

12. **정렬 방식은 전역 하나 · 영역별 설정 없음**(사용자 10-09 "컬럼 정렬시에 자연정렬" · "전체 진행" · 5fda818 · 9484472) — 이름을 정렬하는 모든 곳(그리드 글자 열 · 객체/프로젝트 탐색기 · 북마크 · 로그인 목록 · 팔레트 동점)은 nexa-ctl `natural::cmp_names` 하나를 부르고 스위치는 `ui.sort_natural` 하나 · 서버가 준 순서(`ORDER BY name` = 바이트 순)를 그대로 쓰지 않고 표시 전에 다시 정렬한다(전체 목록·디프 갱신 둘 다) · 구조 순서(종류 폴더·묶음)는 정렬하지 않는다 · 새 목록을 만들면 이 함수로 정렬하는지 V1에서 대소문자·자릿수가 섞인 이름으로 본다.
13. **IME 모드 = 모든 입력란에 단일 상태 · 허용 결정은 사건 끝에 한 번**(사용자 10-15 · 127차 T-350) — 포커스가 옮겨 가는 한 사건 안에서 IME를 껐다 켜면 입력 문맥이 초기화되어 한글 모드가 영문으로 돌아간다 → 입력 경로는 **바라는 값만 기록**(`ime_refresh` · 켜기는 즉시) · 끄기는 사건 끝(`about_to_wait` 첫머리 `ime_apply`)에 한 번(`ime_write_needed` 순수 함수) · **최종 결정은 묶음 끝 재판정** = `about_to_wait`에서 `ime_refresh`(최종 포커스로 다시 판정) 뒤 `ime_apply`(포커스를 넘기는 경로마다 재판정을 기대하지 않는다 — 조건 바 클릭 결함) · **끄기 직전 변환 모드 저장 → 켠 직후 복원**(Windows `imestate.rs` `conversion_mode`/`set_conversion_mode` = `WM_IME_CONTROL` `IMC_GET/SETCONVERSIONMODE`) · 새 입력란은 IME 허용 판정 `ime_allow`에 등재.
14. **메뉴 이름에 "…"를 붙이지 않는다 · 다른 창으로 포커스가 가면 열린 메뉴를 닫는다**(사용자 10-16 ㉓㉔) — "…"는 "실행 전에 입력 창이 먼저 뜬다"는 HIG 관례지만 이 프로젝트 메뉴는 전부 즉시 그 기능(창·탭)으로 가므로 통일해 붙이지 않는다(메뉴 밖의 진행 글 "읽는 중…" · 툴팁 · 버튼은 별개) · 메인 창 `Focused(false)` = `open_menus()` 비트 전부 `close_menu_bits`(설정 `ui.menus_close_on_blur` 기본 켬) · 새 모달리스 창도 blur 때 자기 드롭다운을 닫는다.
15. **파괴적 일괄 동작 = 2단 확인**(사용자 10-16 ㊿) — 여러 대상의 변경을 한 번에 버리는 동작(탭 닫기 메뉴 "모두 취소" 등)은 첫 선택 뒤 **두 번째 팝업**에서 개수를 밝혀 다시 묻는다("예, N개 탭의 변경을 버리고 닫기 / 취소") · 하나짜리 동작은 1단 그대로 · 운영 서버 2단(61 §1-12)과 같은 취지.
16. **클릭은 즉시 · 머무름(의도 지연)은 연타(키 자동 반복)에만**(사용자 10-16 54) — 마우스 클릭은 사용자가 한 번 고른 대상이라 `LatestIntent` 지연·중복 방지로 늦추지 않는다 · 키 자동 반복처럼 사건이 몰리는 입력에만 머무름을 둔다(99 §3-1) · 반응 측정은 **창 사건 한 길**에서 시작한다(컨트롤 함수 직접 호출 시험은 창 안 분기를 놓침 · 113 §5-4).
17. **보조 창 애니메이션 프레임 = 시간 간격으로 요청 · `about_to_wait`마다 요청 금지**(10-16 58) — winit Windows는 RedrawRequested마다 메시지 배분을 끊고 `about_to_wait`로 돌아오므로, 한 창이 매번 다시 그리기를 청하면 `PeekMessage`가 그 창 WM_PAINT만 뽑아 **다른 창(메인)이 굶는다** → 진행 표시·혜성 같은 상시 애니메이션은 다음 프레임 시각(16 ms)을 두고 그때만 요청 · 화면 갱신 시험은 `painted` 계측 + 캡처 없는 실행.
18. **떠 있는 카드가 덮은 자리도 머무르면 그 대상으로**(사용자 10-21 · 96 §7) — hover 카드 영역 안에서 다른 줄 링크 위 = 머무름(`objlink.hover_ms`) 뒤 교체 · 카드 버튼 위 = 2배 머무름(버튼 누르러 가는 길은 지키되 막지 않음) · 같은 줄 띠 = 즉시. 교훈 = **`ObjLinks`처럼 재분석마다 새로 만드는 상태 묶음에 필드를 더하면 이어받기 목록에도 넣는다**(hot·menu_link·zone_switch = 구간으로 이어받음 · 빠뜨리면 백그라운드 메타 응답이 예약을 지운다).

- ★ **패널 목록 영역 = 테두리 열 제외(10-13 사용자 확대 캡처)**: 구역 머리·선택 행·hover 배경은 목록 영역을 칠하므로, 목록 영역 폭을 패널 전체 폭으로 잡으면 오른쪽 테두리 열(`b.right()−1` = 스플리터 선)을 1~2 px 덮는다 → 목록 영역 폭 = 패널 폭 −1(프로젝트 · 북마크 · 아웃라인 · 파일 검색 · 확장 패널) · 새 패널도 같게 · 확인 = 테두리 열 픽셀이 위아래 끊김 없이 한 색인지.

#### 2-2-c. 드래그 컨트롤의 기본 처리 = 포인터 캡처(사용자 09-30)

글자 선택·행 선택·썸 드래그처럼 **누른 채 끄는** 컨트롤은 커서가 영역 밖으로 나가서 놓여도 **드래그가 끝나야 한다**. 이것은 컨트롤마다
고치는 일이 아니라 호스트의 **포인터 캡처 부품**([30 §2](30-architecture-patterns.md) PointerCapture · `app/input.rs`)이 기본으로 한다 —
MouseDown 때 누른 영역(`area_at`)을 기억하고, 그 영역 밖의 MouseMove/MouseUp은 커서 아래 컨트롤이 아니라 **누른 영역**에 전달
(`dispatch_captured` · 그 영역이 포커스일 때만 = 팝업·메뉴가 먹은 누름은 제외) · MouseUp으로 끝. 새 영역(패널·창)을 만들면 `area_at`/
`area_bounds`/`dispatch_captured`의 표에 한 줄을 더한다 — 개별 컨트롤에 "밖에서 놓임" 코드를 새로 넣지 않는다.
★ **한 영역 안의 하위 부품 사이(10-12)**: 포인터 캡처는 영역 **사이**를 맡는다. 그리드처럼 한 영역 안에 썸·트랙·필터 줄·푸터·셀 편집기가 여럿이면 **드래그 중인 부품이 MouseMove/MouseUp을 히트 테스트보다 먼저 받는다**(`grid.rs` `bars_drag_event` · nexa-ctl `ScrollBars::is_dragging()`) — 경계를 맞댄 부품 위에서 놓이면 드래그가 남던 결함([journal 10-12](journal/2026-10-12.md) · 10-07 `drag_sel`과 같은 꼴). 새 드래그 부품을 넣으면 그 컨트롤의 사건 순서 맨 앞에 "드래그 중이면 그 부품" 분기를 둔다.
★ **캡처 분기보다 앞에 둘 호스트 처리(10-12 · 121차 오후)**: 누른 영역의 끌기를 **다른 영역에 놓는** 기능(열 머리 → 편집기에 열 이름 삽입 · 놓을 자리 표시)은 포인터 캡처 분기(`press_capture` = 누른 영역 밖 MouseMove/MouseUp을 누른 영역에 주고 return)보다 **앞**에서 처리하고, 놓음에서 캡처도 끝낸다 — 뒤에 두면 다른 영역 위 이동·놓임이 영영 닿지 않는다(V1 ⓑ 1차 ✗ · journal 10-12 §5).
- ★ **팔레트(명령·프롬프트 입력창) 열림 중 포인터 사건 = 팔레트가 가장 먼저(10-13 사용자 실기)**: `route_inner`의 `press_capture`는 누른 **영역**(프롬프트가 덮은 편집기·그리드)으로 이동·놓임을 보내므로, 팔레트가 열려 있으면 `is_ptr` 직후 `route_palette`가 먼저 받는다(입력란 클릭 = 캐럿 · 드래그 = 선택 · 영역 밖 놓임 = 드래그 끝) · 키는 종전 자리 · 영역 캡처를 새로 만들 때 "위에 떠 있는 층이 먼저"인지 본다.

#### 2-2-d. 밀려 들어오는 같은 사건은 "마지막만"(사용자 09-30 · [99](99-latest-intent-coalescing.md))

스크롤·마우스 이동처럼 같은 종류의 사건이 연달아 오고 **마지막 상태만 뜻이 있는** 동작(툴팁 · hover 효과 · 검색어 확정 · HUD)은 사건마다 일을 하지
않는다. 사건은 nexa-ctl `LatestIntent<T>`(또는 `IntentFade`)의 목표를 **덮어쓰기만** 하고, `tick`이 머문 목표만 확정한다. 확정된 목표를 쓸 때는
**지금도 유효한지**(커서 아래인지 · 노드가 아직 있는지)를 한 번 더 확인한다. 자체 타이머·큐·"마지막 사건 플래그"를 새로 만들지 않는다.

- ★ **툴바 글자 항목(10-01)**: 글이 바뀌는 항목(`ToolItem::text` + `set_item_label`)은 그룹 사각형이 낡는다 — nexa-ctl `ToolDock`이 paint에서 감지해 `relayout_if_stale`로 재배치하므로 호스트는 paint 뒤 그 함수를 한 번 부른다(`app/paint.rs`). 새 글자 항목을 넣을 때 **글이 길어진 뒤 클릭이 닿는지** 실기 1회.

- ★ **스크립트 엔진 메시지 = `tr!` 영어 기본 + 호스트 `set_lang`(10-17 · T-369)**: nsql-script는 의존 0이라 `nsql-i18n::Msg`를 못 쓴다 → 사용자에게 보이는 엔진 메시지는 `tr!(영어, 한국어)`로 쓰고, 언어는 호스트(GUI 기동·언어 전환 · nsql-cli)가 `nsql_script::set_lang`으로 정한다 · 새 엔진 메시지에 한국어 리터럴만 넣지 않는다.

- ★ **C 라이브러리가 프로세스 로캘을 보는 자리 = 호출 전에 LC_CTYPE을 UTF-8로 보정(10-24)**: Rust 프로세스는 `setlocale`을 부르지 않아 **늘 C 로캘**이라고 전제한다 → 로캘을 보고 글자를 바꾸는 C 코드(외부 명령 `pbcopy`/`pbpaste` = [journal 10-16 §13](journal/2026-10-16.md) · ODBC 벤더 드라이버의 UTF-16 메시지 = [journal 10-24 §1](journal/2026-10-24.md))를 부르기 전에 보정한다 — 패턴 = nsql-driver-odbc `ensure_utf8_ctype()`(유닉스 · 프로세스 1회 · **LC_CTYPE만** · 후보 `""` → `C.UTF-8` → `en_US.UTF-8` → `UTF-8` · 순수 판정 `is_utf8_locale` + 시험) · 외부 명령은 `LC_ALL=en_US.UTF-8` 환경으로 띄운다(`clipboard.rs` `imp::cmd`).

- ★ **메뉴 항목 id 접두(10-01 ㉔)**: `ContextMenu` 항목 id의 `starts_with` 분기를 더할 때 **같은 메뉴의 기존 접두와 겹치지 않는지** grep 한다(`sess.use:` 둘 = 연결 고르기가 스키마 `"0"`으로 — guard 분기라 컴파일러가 닿지 않는 코드를 못 잡는다).

### 2-3. 검증 규칙(이번 주에 효과가 있었던 방법)

- **측정 먼저.** 느리다는 곳을 고치기 전에 재서 병목을 확인한다 — "읽기가 느릴 것"이라던 큰 파일 열기의 실제 병목은 UI 스레드의 행 폭 측정(3.8초)이었다. 도구 = §4.
- **자료 구조를 바꿀 때는 단순 모델과 난수로 대조한다**(자체 xorshift · 외부 crate 0): `TextBuf` ↔ `Vec<char>`(30 시드 × 150 편집) · 되돌리기 ↔ 상태 전체 스냅샷(40 × 120). 한글 · 이모지 · 개행 · 빈 본문 · 끝 개행을 알파벳에 넣는다.
- **교체는 호환 경로로 먼저 전체 테스트를 통과시킨 뒤** 자주 도는 길부터 새 API로 옮긴다(T-142: 임시 `chars_vec()`로 290개 통과 확인 → 이관).
- 새 구현이 옛 정의와 **같은 답**을 내는지 테스트로 남긴다(`eol::detect` 한 번 훑기 · `enc::decode_owned` · 줄 단위 찾기 · `TextBuf::find` = `str::find`).
- 결과는 Release로 잰다. Debug의 "멈춤"은 최적화 없는 빌드의 느림일 수 있다(65 MB).
- 보고는 정직하게: 하지 않은 것 · 시험하지 못한 것(키 입력이 필요한 것) · 기존 실패(CI)를 따로 적는다.

### 2-4. 격리 · 안전 규칙

- **앱을 띄워 시험할 때는 `NSQL_HOME`을 임시 폴더로 돌린다** — 사용자의 실제 설정 · 프로필 · 최근 파일 · 되돌리기 기록에 닿지 않게. 그리고 **정말 적용됐는지 확인한다**: 09-20에 셸 인자 실수로 격리 폴더가 엉뚱한 새 폴더로 잡혔고, 화면에 "Not connected"가 나온 것이 단서였다. 확인 방법 = 격리 폴더의 `settings.conf` 수정 시각 · 실제 설정 파일의 수정 시각이 그대로인지 · 임시 영역에 떠돌이 폴더가 생기지 않았는지.
- **스크립트의 CLI 쓰기 명령은 전부 `NSQL_HOME` 접두**(또는 스크립트 위에서 `export NSQL_HOME` · 10-04) — `conn add/remove` · `config set/reset` · `license install` · `bookmark add` 등. 격리판 줄을 새로 넣을 때 옛 줄을 지운다(10-04 `mac-grid-edit-e2e.sh` · `linux-func-check.sh`에 `NSQL_HOME` 없는 `conn add … || true`가 남아 사용자 실제 프로필에 `Local`을 썼다). 실제 프로필이 꼭 필요한 스크립트(`bench-boost.ps1`)는 바꾼 설정을 **원래 값으로** 되돌린다. 처음 돌리는 스크립트는 실행 전에 이 점을 훑는다(협업 세션 = [102](102-collab-session-operation.md) §2-1).
- **단위 테스트는 실제 설정 폴더에 쓰지 않는다.** 파일을 다루는 모듈은 폴더를 인자로 받는다(`undofile::store_in(dir, …)` 패턴) · 테스트는 `std::env::temp_dir()` 아래에서만.
- **프로세스 전역 상태(스위치 · 환경 변수 · 현재 폴더)를 만지는 시험은 가드로 직렬화한다** — 시험은 병렬로 돈다. 본보기 = nexa-font `tests::GdiOn`(정적 뮤텍스를 쥔 동안 켬 · Drop에서 끔). 09-22(92차): 가드 없던 두 시험이 CI windows-latest에서만 겹쳐 네 번 실패했고, 로그를 못 본 채 "되돌리니 통과"로 엉뚱한 원인(`file_type()`)을 지목했다 → **CI 실패는 로그를 본 뒤에 고친다**(`gh run view <id> --log-failed` · `gh` 없는 PC면 있는 PC 몫으로 넘긴다) · "되돌리니 통과"는 원인의 증거가 아니다(타이밍도 같이 돌아간다).
- **사용자가 자리에 있을 때 키·마우스 입력을 주입하지 않는다**(`SendKeys` · System Events 키 입력은 사용자의 전경 창으로 간다) · **포커스를 빼앗지 않는다**(`SetForegroundWindow` · `activate` 금지). 앱은 `NSQL_STARTUP_CMD`로 몰고 화면은 창 단위로 찍는다(§3 · §4). 키 입력이 있어야만 볼 수 있는 것(한글 조합 · 드래그)은 **단위 테스트로 덮고, 실기는 사용자 몫으로 보고에 적는다.**
