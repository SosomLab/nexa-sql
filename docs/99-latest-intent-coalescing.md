# 99. "마지막 사건만" — 최신 의도 코얼레싱 아키텍처 (2026-09-30)

> 사용자 09-30: "스크롤처럼 이벤트가 발생하고 밀리면서 동일 이벤트가 발생하는 경우라면 마지막 이벤트만 살아남아도 되는 상황(툴팁 표시 등)이라면
> 다른 이벤트는 버리는 방식의 큐잉 처리를 하면 될 것 같아. 잘 고려해서 아키텍처 설계해줘."
>
> 부품 = nexa-ctl `tokens::LatestIntent<T>`(nexa-ui 99차) · 규칙 = [61 §2-2-d](61-core-design-and-working-rules.md) · 원장 = [30 §2](30-architecture-patterns.md).
> 발단 = 객체 탐색기 툴팁이 스크롤로 밀린 **직전 행**의 것을 보이던 결함(journal 09-30).

## 0. 결론

- "큐"가 아니라 **슬롯 하나**다. 같은 종류의 사건은 목표 값을 **덮어쓰기만** 한다(비용 0 · 할당 0). 처리(툴팁 표시 · 페이드 · 검색 확정)는
  주기 `tick`이 "목표가 `delay` 동안 그대로 머물렀다"를 확인한 순간 **한 번** 한다. 그 사이에 목표가 바뀐 사건들은 처리에 닿지도 않고 사라진다.
- 확정된 목표를 **쓸 때** 호출자가 "지금도 유효한가"를 한 번 더 본다(커서 아래인가 · 노드가 아직 있는가). 스크롤로 밀린 목표는 여기서 걸린다.
- 이미 있던 같은 사상의 부품: `IntentFade`(hover 페이드 · 09-14 규칙 "최종 위치가 아닌 대상의 효과는 즉시 취소") · 검색 요청의 `rev`/`gen`(스레드
  응답 중 최신만) · 자동 저장 스로틀(70 §7-1). `LatestIntent<T>`는 이것을 **값 종류에 무관하게** 일반화한 것이다.

## 1. 문제의 모양

| 사건 원천 | 밀려 들어오는 이유 | 마지막만 뜻 있는 동작 | 종전의 함정 |
|---|---|---|---|
| 휠 스크롤 | 틱마다 행이 밀려 커서 아래 대상이 바뀐다 | 노드 툴팁 · hover 강조 | 툴팁 타이머가 "마지막 이동" 기준이라 스크롤은 이동이 아니어서 직전 행 툴팁이 남았다 |
| 마우스 이동 | 픽셀마다 | 툴팁 · hover 페이드 · 링크 밑줄 | 대상마다 페이드를 시작하면 지나간 행이 모두 깜빡인다 |
| 키 입력(필터 상자) | 글자마다 | 다시 거르기 · 스레드 검색 | 글자마다 검색 요청 → 스레드가 밀린다(`rev`로 이미 해결) |
| 키 자동 반복(↑/↓) | 반복마다 | 선택 이동은 **모두** 유효(마지막만이 아님) | → 이 부품 대상이 아니다(가속 = `ScrollAccel`) |

판정 기준: **중간 상태에 부작용이 없고, 최종 상태만 화면·서버에 닿아야** 하면 이 부품. 중간 사건도 각각 뜻이 있으면(타이핑 글자 · 셀 이동) 아니다.

## 2. 부품 API(`nexa_ctl::LatestIntent<T: PartialEq + Clone>`)

| 호출 | 뜻 | 비용 |
|---|---|---|
| `new(delay_ms)` · `set_delay_ms` | 머문 시간 기준(툴팁 700 · hover 70 = `ui.hover_intent_ms`) | — |
| `set(Some(target))` / `set(None)` | 사건: 목표 덮어쓰기(같은 값이면 대기 계속 · None = 취소) | O(1) · 시계 없음 |
| `tick(now_ms) -> bool` | 목표가 바뀌었으면 확정 내림 + 새 대기 · 머문 시간이 차면 확정 올림 · **상태가 바뀔 때만 true**(다시 그림) | O(1) |
| `settled() -> Option<&T>` | 확정된 목표(처리 대상) | — |
| `restart()` | 같은 목표라도 대기를 새로(스크롤 뒤) | — |
| `clear()` | 목표·확정 모두 비움(기능 끔 · 메뉴 열림) | — |

시험 = nexa-ctl `tokens::tests::latest_intent_keeps_only_the_last_target`(덮어쓰기 · 확정 시점 · 바뀜 = 확정 내림 · restart · None · clear).

## 3. 적용 — 객체 탐색기 노드 툴팁(첫 사례)

- 목표 `T = (칸 index, 노드 index)` = **지금 커서 아래 노드**(`ExplorerSet::tip_target` · `Explorer::node_at`).
- 사건: MouseMove → `tip.set(target)` · 공용 스크롤로 행이 밀림 → hover 재판정(`MouseMove` 재전송) + `tip.set(target)` + `restart()`.
- `tick(now)`: 확정이 바뀌는 순간만 다시 그림(종전 `tip_moved/tip_since/tip_on` 셋 → 부품 하나).
- 그리기: `tip.settled()`가 있고 **그 칸의 `hover_under(cursor)` && `node_at(cursor) == node`** 일 때만 카드(창 안 맞춤 61 §2-2).
- 끔·메뉴 열림: `clear()`.

## 4. 다음 적용 후보(T-265 · 각각 한 줄씩 옮기면 된다)

| 대상 | 지금 | 옮기면 |
|---|---|---|
| Ctrl 객체 링크 툴팁(`objlinks.hot`) | 이동마다 hot 갱신 · 즉시 표시 | `LatestIntent<link index>` + 표시 때 `index_at_point == hot` 재확인 |
| 그리드 표식 툴팁(`MARK_TIP_MS`) | `since` 시각 비교 | 같은 부품(목표 = 열/행) |
| 필터 상자 → 다시 거르기 | 글자마다 `refilter`(트리 작을 땐 문제 없음 · 큰 트리는 ms) | `LatestIntent<String>`(delay 50~80) → 마지막 글만 거름 · 스레드 검색 `rev`는 그대로 |
| 상태줄 hover 힌트 · 탭 툴팁 | 각자 타이머 | 같은 부품 |
| 고속 스크롤 HUD | 사건마다 `note` · 페이드는 자체 | 유지(마지막 사건마다 값이 바뀌는 표시 = 중간도 뜻 있음) |

## 5. 규칙(61 §2-2-d)

1. 새 "지연 뒤 한 번" 동작에 자체 타이머·플래그(`*_moved` `*_since` `*_on`)를 만들지 않는다 — `LatestIntent<T>`.
2. 사건 핸들러는 `set`만 · 일은 `tick`에서 · 표시·전송 직전에 유효성 재확인.
3. 중간 사건에도 뜻이 있는 동작(입력·선택 이동·실행)에는 쓰지 않는다.
4. 스레드로 가는 요청은 여기에 더해 `rev`/`gen`으로 늦은 응답을 버린다(85 §6).
