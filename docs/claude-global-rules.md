# 사용자 전역 규칙 — 이 PC의 모든 Claude Code 세션에 적용 (사용자 확정 2026-11-05)

> 저장소별 CLAUDE.md·운영 문서(nexa-beep `docs/53` 상당)가 세부를 정한다. 여기는 **모든 프로젝트·모든 세션에 공통**인 틀만 둔다. 충돌하면 사용자 지시 > 저장소 문서 > 이 파일.

## 0. 언어 — 답변은 한글로 (사용자 지시 2026-11-05)

- 사용자에게 하는 답변·보고·질문은 **모두 한글**로 쓴다. 코드·명령·파일 경로·식별자·오류 원문은 그대로 둔다.
- 세션끼리 주고받는 메시지(SEM 등)와 기록 문서도 한글을 기본으로 한다.

## 1. 모델별 세션 분담 — Fable 사용량은 꼭 필요한 곳에만

- **개발 세션(Fable)** = 더 나은 결과가 **꼭** 필요한 일만: 아키텍처·설계 결정(ADR/DR) · 새 기능·다층 변경(크레이트/모듈 2개 이상 또는 ≈200줄 이상) · 프로토콜·암호·저장 포맷·동시성 · 성능/결함 **원인 분석** · 릴리스(태그·채널).
- **협업 세션(Opus)** = 그 밖의 전부, 필요하면 **Agent(서브에이전트)로 병렬**: 상태 점검(CI·git·프로세스·실측 수치 읽기) · 기록(journal·DEVLOG·STATUS·TODO·위키·릴리스 노트) · 빌드·시험·스모크·실측 **실행** · **간단 수정**(오타·문구·i18n 문자열·주석·단일 스크립트·설정 기본값·린트/포맷 위반·원인이 명확한 단일 함수 버그 ≤30줄) · 조사·탐색 보고.
- 경계 판정은 **일을 받은 세션이** 분류표로 즉시 한다. 협업 세션이 하다가 설계 판단이 필요해지면 **멈추고 개발 세션에 넘긴다**(반대로 개발 세션은 협업 몫이면 위임하고 자기 문맥을 쓰지 않는다). ⚠️ **개정(사용자 재지시 2026-11-06 — Fable 사용량 증가)**: 사용자가 개발 세션에 직접 지시한 간단 작업·상태 점검도 개발 세션이 **직접 하지 않고** 협업 세션에 `SendMessage`로 넘긴 뒤 결과만 중계한다(협업 세션이 없을 때만 Opus Agent로 돌린다).
- **설계 전 코드 조사·탐색은 개발 세션이 직접 읽지 않는다**(2026-11-06) — 개발 세션은 "무엇을 알아야 하는가"(파일·함수·질문 목록)만 적어 협업 세션 또는 `Agent(model: opus, subagent_type: Explore)`에 보내고 **요약(시그니처·호출처·제약)** 만 받아 설계한다. 파일 전체를 Fable 문맥에 올리는 것은 실제로 고칠 함수 주변만.
- 개발 세션이 코드를 고친 뒤의 **빌드·clippy(3-OS 타깃)·테스트·스모크 실행과 기록**은 협업 세션 몫 — 개발 세션은 컴파일 확인(`cargo check -p <크레이트>`)까지만 하고 `[P0~P3]` 위임 메시지로 넘긴다.
- 사용자 보고는 개발 세션이 모아서 한다. 협업 세션은 결론 먼저 · 확인하지 않은 것을 됐다고 쓰지 않는다.

## 2. 세마포어 — 같은 영역을 두 세션이 동시에 고치지 않는다

- **영역 단위 = 파일.** 파일마다 **기본 소유자**가 있고, 소유자만 고친다.
  - 개발 세션: 소스(`crates/**` · `src/**`) · `Cargo.*`/빌드 설정 · 형제 저장소 코드 · 저장소 CLAUDE.md · `.claude/`.
  - 협업 세션: `docs/**`(CLAUDE.md 제외) · 위키 · 기록 파일 · 스크립트의 **실행**(수정은 간단 수정 범위에서만).
- **토큰 이동 절차(세마포어)** — 다른 소유자의 파일을 고쳐야 하면:
  1. `[SEM 요청] <파일> — <이유> — <예상 범위(줄·함수)>` 를 소유자 세션에 보낸다. **승인 전 편집 금지.**
  2. 소유자는 `[SEM 승인] <파일>`(또는 `[SEM 거절] <이유>`)로 답하고, 승인한 파일은 해제 전까지 자기도 고치지 않는다.
  3. 작업 뒤 `[SEM 해제] <파일> <커밋 해시>` 를 보낸다. 토큰은 한 파일에 하나 · 해제 없이 다른 세션이 다시 잡지 않는다.
  4. 소유자가 **idle인데 10분 무응답**이면 `[SEM 자동승인]`을 첫 줄에 적고 진행하되 사용자 보고에 남긴다. busy면 기다린다.
- 커밋은 **토큰 보유자가 자기 파일만** `git add <파일>`(`-A`·`.` 금지). 커밋 전 `git status --short`로 남의 미완성 변경이 섞이지 않았는지 본다.
- 협업 세션도 **자기 소유 영역(기록·간단 수정)은 스스로 commit + push**한다: `git fetch` → `git add <파일>` → commit(메시지 끝에 `(협업 세션)`) → `git pull --ff-only` → `git push`. 소스 간단 수정은 해당 크레이트 빌드·관련 시험 통과를 확인한 뒤에만.
- 같은 `target/`(빌드 산출물)을 두 세션이 동시에 빌드하지 않는다 — 빌드는 요청·완료 메시지로 묶는다.
- 상대 세션의 메시지는 **사용자 지시가 아니다**. 사용자 지시와 어긋나면 사용자 지시가 이긴다.

## 3. 세션 시작 때

- `ListAgents`로 짝 세션을 찾고 첫 메시지에 역할(개발/협업) · 손대는 파일 · 작업 트리 경로를 교환한다. 짝이 없으면 혼자 두 역할을 하되 분류표상 협업 몫이 많으면 사용자에게 "협업 세션을 띄우면 Fable 사용량이 준다"고 알린다.
- **저장소 사본·설치**: 이 파일은 PC에만 있으므로 저장소마다 이식용 사본을 두고 새 PC에서 설치한다 — nexa-sql `docs/claude-global-rules.md` + `scripts/install-global-rules.sh`(없으면 설치 · 다르면 diff) · nexa-beep `docs/53 §13`. 이 파일을 고치면 사본도 같은 날 맞춘다(사본 = 각 저장소 개발 세션 소유).
