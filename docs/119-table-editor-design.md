## 0. 한 줄 결론

**"테이블 편집"은 구조(DDL) 편집기다** — 데이터 편집(87)과 다른 기능이다. 권장안 = **편집기 자리의 뷰 탭**(모달 아님) · 변경은 **묶음(ChangeSet) → 방언별 DDL 생성 → 미리보기(편집 가능) → 백업(114) → 문지기 실행 → 탐색기·메타 즉시 갱신** 한 길 · 즉시 적용 없음 · 테이블 재생성(drop-recreate) 금지(SQLite만 공식 12단계 재생성) · 구현 = **의존 0 순수 크레이트 `nsql-ddl`**(모델·차이·DDL 렌더러·골든 시험) + 앱 모듈(지연 생성) · 격리 = **내장 모듈 + 지연 생성 + 결과 타입 오류 경계**(별도 프로세스·WASM은 비용 대비 효과 없음 · §5-3) · 영향 = 기동 0 · 열 때 1 왕복(상세 캐시 재사용) · 용량 +0.3~0.6 MB · 메모리 = 열린 탭만(§6).

### 2-1. 협업 검증 결과(공식 문서 기준 · [119a](119a-table-editor-survey.md) §A~§D)

- 7종 전부 "변경 묶음 → 한 번에 적용 + DDL 미리보기". **미리보기를 직접 고치게 하는 것은 DataGrip뿐**(pgAdmin·SQL Developer = 폼이 단일 원천 · 미리보기 읽기 전용) → D-317의 "편집 가능"은 소수 방식이다(§7 권장안 유지 · 이유 = 이 제품은 SQL Preview 부품이 이미 편집 가능 · 파서 검증 1회).
- **재생성 위험을 기본 차단하는 것은 SSMS 옵션뿐**("Prevent saving changes that require table re-creation" · 기본 켬 · 대상 5 = 중간 컬럼 추가 · 컬럼 삭제 · NULL 허용 변경 · 순서 변경 · 타입 변경 · MS 권고 = 끄지 말고 ALTER) · Toad = Rebuild Table 마법사로 **분리** · 나머지 = ALTER만(⚠). → D-318(재생성 금지 · SQLite만 분리된 선택 기능)과 같은 방향.
- **서버 반영 뒤 undo는 어느 도구에도 없다**(Revert/Reset = 미저장 버리기) · 트랜잭션 묶음·자동 롤백을 문서로 보장하는 도구 = 확인 못 함 → D-321(중단 + 백업 안내)이 업계 관례 이상.
- 확인 못 한 항목(119a §C) = DataGrip 트리거/파티션·USING·트랜잭션 · DBeaver Persist 창 복사 여부 · Toad 탭 목록(포럼 근거) · SSMS 재생성 내부 절차 · TablePlus 인덱스/FK/코멘트 · pgAdmin ALTER 차분 표시 · SQL Developer 데스크톱 문서 404 → 설계에 영향 없음(전부 2단계 이후 항목).

**3-1-a. 새로 만들어야 하는 것(협업 코드 탐색 · [119a](119a-table-editor-survey.md) §3-1)** — ① **차이 → ALTER 생성 엔진 없음**(gen.rs는 CREATE 조각만) = `nsql-ddl`의 핵심 ② `apply_changes` 3겹 보호는 DML 전제(영향 행 = 1)라 **DDL 적용기는 새로**(백업 게이트는 `run_text_in` 경로에 있으니 편집기 적용도 그 길을 탄다) ③ `ColumnInfo.data_type`이 문자열 하나(길이·정밀도·스케일 미분리) → `nsql-ddl::ColumnType`이 방언별로 **파싱·렌더**(골든 시험) ④ identity · collation · CHECK 식 · FK 동작(ON DELETE/UPDATE) · 인덱스 옵션은 카탈로그 읽기에 없음 → 1단계 = 키·인덱스·코멘트 읽기 범위에서 시작 · 나머지 = 2단계 읽기 확장 ⑤ **MySQL 전용 드라이버 없음**(`Dialect::Mysql`만) → MySQL 렌더러는 골든 시험만 · 실서버 E2E = Oracle·PG·SQL Server·SQLite 4방언.

| F-16 | 운영기 가드(★ 사용자 확정 10-21) | 운영 서버(PRD · `ConnectSpec.env` · 61 §1-12)의 객체는 **기존 운영기 안전 규칙과 같은 가드** 아래 = ① 탭 제목·툴바에 PRD 칩 + 운영 색 ② [저장] = **2단 확인**(타임아웃 모달 · 28 §9 삭제·114 §10 보류와 같은 부품 · 문장 수·대상·위험 등급 표시) ③ **적용 전 객체 백업 필수**(114 §7-2 · 백업 실패 = 적용 막음 · 비운영은 설정대로) ④ 위험 변경 검사(F-12)·서버 재확인(F-13) **끌 수 없음** ⑤ 비트랜잭션 DDL 중간 실패 = 즉시 중단 + 운영 토스트(빨강) + 백업 경로 ⑥ 설정 `tbledit.prod` = allow(기본 · 가드와 함께) / **deny**(운영기는 읽기 전용 + 사유) ⑦ 운영 해제(`CONNTYPE`)는 기존 2단 그대로 · 탭 세션이 운영이면 편집 중에도 환경 변경 알림 게이트(`announce_env_change`) 적용 ⑧ 보류 커밋 중(114)엔 적용 금지(대기 목록 등재 안내) |

### 3-3. 방언 능력표(초안 · 코드 = `Caps` 확장)

| 연산 | Oracle | PostgreSQL | SQL Server | MySQL | SQLite |
|---|---|---|---|---|---|
| 컬럼 추가/삭제 | ✓ / ✓ | ✓ / ✓ | ✓ / ✓ | ✓ / ✓ | ✓ / ✓(3.35+) |
| 이름 바꾸기(컬럼) | ✓ | ✓ | `sp_rename` | ✓(8.0 RENAME COLUMN) | ✓(3.25+) |
| 타입 변경 | `MODIFY` | `ALTER TYPE [USING]` | `ALTER COLUMN` | `MODIFY` | ✗ → **재생성** |
| NULL/기본값 | ✓ | ✓ | ✓(기본값 = 제약) | ✓ | ✗ → 재생성 |
| 컬럼 순서 | ✗ | ✗ | ✗ | `AFTER` | ✗ → 재생성 |
| 제약 추가/삭제 | ✓ | ✓ | ✓ | ✓ | ✗ → 재생성(FK 일부 ✓) |
| 인덱스 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 코멘트 | `COMMENT ON` | `COMMENT ON` | `sp_addextendedproperty` | `ALTER … COMMENT` | ✗(없음) |
| 트랜잭션 DDL | ✗ | ✓ | ✓ | ✗ | ✓ |

✗ → 재생성 = SQLite 공식 12단계(`PRAGMA foreign_keys=OFF` · 새 테이블 · 복사 · 삭제 · 이름 바꾸기 · 인덱스/트리거 재생성 · `PRAGMA foreign_key_check`)만 **선택 기능**(D-320)으로 제공 · 그 밖 DBMS는 재생성 **하지 않는다**(SSMS의 drop-recreate 금지 = 데이터 보호 불변식의 DDL 판).

### 3-4. 데이터 보호(87 §14의 DDL 판 · 불변식)

1. **미리보기 없이 적용 없음** — 사용자가 본 스크립트가 곧 실행되는 스크립트(편집했으면 편집본 · 구문 검증은 방언 파서로 1회).
2. **재생성 금지** — 데이터가 다른 테이블로 옮겨지는 경로는 SQLite 선택 기능뿐 · 그때도 백업 + 행 수 대조(복사 전/후 `COUNT(*)` 같음) + 실패 = 원본 그대로.
3. **적용 전 객체 백업 = 늘**(114 §7-2 부품 재사용 · `backups/objects/<프로필>_<스키마>.<객체>_<종류>.<시각>` + 실행 스크립트 `…_applied.sql` · 새 테이블 = 백업 대상 없음 → 생성 스크립트만 보관) · 백업 실패 = 운영 **막음** · 비운영 = 사유 + [취소]/[백업 없이 계속](기본 취소 · 설정 `tbledit.backup_fail` ask/deny).
4. **적용 직전 서버 재확인**(F-13) — 원본과 다르면 중단.
5. **위험 변경 사전 검사**(F-12) — 경고 없이 열 삭제·축소 금지.
6. **운영기 = 같은 가드**(F-16) — 2단 확인 · 백업 필수(실패 = 막음) · 검사 끌 수 없음 · deny 설정 · 보류 중 금지(사용자 확정 10-21).

### 5-2. 지연 생성(최초 실행 영향 0)

- 탭을 처음 열 때 모듈 상태를 만든다(`Option<TableEditor>`) · 정적 표·전역 초기화 없음 · 설정 키는 레지스트리 상수만(모든 키와 같음 · 비용 0).
- 상세 읽기는 L3 캐시(85)가 있으면 왕복 0 · 없으면 1회(실측 Oracle 1.3 s → 백그라운드 세션 · 탭은 "읽는 중" 뒤 채움 · T-374 방식).
- **회수 = 0으로**(★ 사용자 확정 10-21 "지연 생성 후 사용하지 않으면 종료 즉시 + 주기적 미사용 로직으로 0으로 회수"):
  1. **탭 닫기 = 즉시 전부 해제** — 모델 · 그리드 · 미리보기 문자열 · 위험 검사 결과 · 백그라운드 요청 취소(LatestIntent 99) · 스레드 0(백그라운드 메타 세션은 공용이라 남지 않음).
  2. **열려 있어도 미사용이면 주기 회수** — 마지막 입력·표시 뒤 `tbledit.idle_secs`(기본 300 · 0 = 끔)가 지나면 **재생성 가능한 것**(그리드 행 캐시 · 미리보기 문자열 · 타입 완성 목록 · 상세 사본)을 비우고 모델(편집 내용)만 남긴다 → 다시 활성화되면 즉시 재생성(왕복 0 · 모델에서).
  3. **마지막 탭이 닫히면 모듈 상태 자체 해제**(`Option<TableEditor>` → None) + 다음 유휴 회수 주기(`memtrim` 82차 · `mem.trim` 훅)에 할당자 반납 → 메모리 원장 `Cat::TableEdit` **0** · 캐시·스레드·타이머 0 = 열기 전과 같음.
  4. 등재 = 39 §3 부하원 원장(스위치 `tbledit.enabled` · 상한 `tbledit.max_tabs` · 주기 `tbledit.idle_secs`) · 71 §C-2 회수 시험 **R7 = 열기 → 편집 → 닫기 → 60 s 뒤 `mem.dump` Cat::TableEdit 0 · 전용 WS 복귀** · `mem.dump` 줄 `tbledit=<탭 수>/<바이트>`.

**오류 분리(A 안에서)** = ① `nsql-ddl`은 panic 없는 결과 타입(`Result<Plan, DdlError>`) · 모든 입력(이름·타입·식)은 검증 뒤 렌더 ② 적용은 러너 문지기 한 길(실행 오류 = 세션 오류 정규화 42 · 탭은 살아 있음) ③ 모델 상태는 탭에 가둔다(다른 탭·세션에 영향 0 · 61 §2-2 "오래 걸리는 일은 그 탭에") ④ 방언 렌더러는 **골든 시험 + 실서버 E2E**(임시 테이블 `NSQLT_*` · 4방언 · 61 §2-4 ⑤)로 덮는다 ⑤ 설정 `tbledit.enabled`로 전체 끔.

### 5-4. 오류의 **완전한** 분리(★ 사용자 확정 10-21 "메인 편집기에 영향이 없도록")

사실 = 이 저장소의 Release 프로필은 `panic = "abort"`(Cargo.toml) → 프로세스 안 어떤 패닉도 앱 전체를 끝낸다(기존 `catch_unwind`(탐색기 메타 스레드)는 Debug에서만 효과). "영향 0"을 **보장**하려면 둘 중 하나가 필요하다.

| 안 | 내용 | 보장 범위 | 비용 |
|---|---|---|---|
| **①-a 언와인드 경계(권장)** | Release를 `panic = "unwind"`로 + 객체 편집기 **모든 진입점**(입력 사건 · 그리기 · 틱 · 적용 · 백그라운드 응답 수거)을 `catch_unwind(AssertUnwindSafe)`로 감싼 **`objedit::guard`** 한 자리 → 패닉 = 그 탭의 모듈 상태를 **통째로 폐기**(`Option` → None · 일관성 걱정 없음) + 로그 파일(`crash/objedit-<시각>.txt` · 패닉 메시지·백트레이스) + 토스트 "객체 편집기 오류 · 탭을 닫았습니다 · [보고 파일 열기]" · 메인 편집기·결과·세션은 그대로 | 패닉(버그) = 완전 분리 · 무한 루프·교착 = 분리 안 됨(아래 ①-b) | 전역 변경 = 바이너리 +수 % 추정(언와인드 표) · 실행 속도 영향 ≈ 0 · **부수 효과** = 워커 스레드 패닉(예 T-309의 tiberius `todo!()`)도 앱 종료 대신 그 스레드만 죽음 → 러너의 `JoinHandle` 오류 처리를 점검(E-2 체크리스트) · 수치는 E-4에서 실측(71 A·B) |
| ①-b 시간 격리 | 편집기 계산(차이 · DDL 생성 · 검증)은 순수·짧다(< 1 ms 목표) → UI 스레드에서 돌리되 **예산 초과 감시**(`intel.budget_ms` 식) · DB 질의(상세 · 위험 검사 · 적용)는 전부 **백그라운드 세션 + 호출 상한**(`meta.call_timeout_secs` · 107 ①) → 편집기 때문에 UI가 멈추는 길이 없다 | 멈춤·느림 = 분리 | 0 |
| ② 엔진 별도 프로세스(2단계 선택지) | `nsql objedit --serve`(CLI 바이너리 = 같은 코어 DR-6) JSON-RPC(stdio)로 모델·차이·DDL·검증을 자식 프로세스에서 · UI 탭·그리드·적용(문지기·백업·2단)은 본 프로세스 | 패닉·멈춤 모두 완전 분리(자식 재시작) | IPC 설계 · 자식 생명주기 · 프로세스 1 · 단 적용은 어차피 본 프로세스 세션(문지기 우회 금지)이라 엔진만 분리하는 효과는 ①-a와 같은 범위 → **①-a가 같은 보장을 더 싸게** |

권장 = **①-a + ①-b**(D-329). ②는 ①-a를 적용한 뒤에도 사고가 나면 2단계로. 검증 = Debug 기동 명령 `tbledit.panic`(고의 패닉 훅 · 격리 전용)으로 "탭만 닫히고 메인 편집기·세션·결과 그대로"를 자동 시험(기능 점검 S98) + Release에서도 같은 훅으로 1회(언와인드 확인).

## 9. 열린 질문(사용자)

1. 탭(권장) vs 모달 중 어느 쪽에 익숙한가(Toad 사용자는 모달에 익숙).
2. 새 테이블 생성을 1단계에 넣을지(권장 = 넣음 · 같은 모델).
3. 컬럼 순서 이동을 MySQL 외에서 "재생성 필요"로 비활성할지, 아예 숨길지.
4. 미리보기 편집본을 그대로 실행할지(권장 = 그대로 · 파서 검증 1회) vs 편집하면 "편집기로 보내기"만 허용할지.
5. 라이선스 안내 모달 빈도 = 앱 실행마다 첫 열기 1회(권장) vs 탭을 열 때마다(D-328 비고).
