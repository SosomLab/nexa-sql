## 3차 (win) — 라이선스 모듈 범용성 점검(beep·clip·dir2)

**요청**(사용자): *"이 라이선스 모듈은 beep, clip, dir 등에 범용 사용 가능하도록 설계되었는지 확인"*.
**실측**: beep = `ed25519-dalek 2` 핀(snow와 curve25519 공유) · vendored nexa-conf · `user_config_dir("nexa-beep")` · DR-21 포트 원칙 | clip = snow·sha2 · vendored nexa-conf · nclip-store 봉투 | **dir2 = 외부 crate 0(B3 인박스 DLL만) · exe 옆 `data\` 포터블 · X-15 = ECDSA P-256 + CNG 계획** | 공통 rust 1.82 · sha2 0.10 · getrandom 0.2.
**판정**: 골격은 범용, 전용 가정 7곳 — ① 이름(`NSQLREQ1`·`nsl1`·`nexa-sql.license`·서명 도메인) → `Product` 기술자 + 공통 접두 ② 기기 ID 도메인 → 계열 공통(한 PC = 한 코드) ③ 폴더 고정·nexa-conf 의존 → 경로 주입 + 자체 파서 ④ **dalek 고정 → 서명 포트(`alg=ed25519|p256`) · dir2는 CNG 어댑터 · 루트 키 2개(D-40)** ⑤ 안내 문자열 → 열거형만 ⑥ 빌드일 환경변수·설정 키 → 주입 ⑦ 서버 단일 제품 → 제품별 조직 라이선스 N개·리스에 `product=`. dir2 X-15의 별도 발급기 `nexa-lic`는 불필요해진다(그쪽 TODO 정정 필요). → [25 §10](../25-license-tiers-and-server.md)

## 2차 (win) — 라이선스 종류 4단 · 사내 인증 서버 · 공유 라이브러리 분리 (설계 · 코드 0)

**요청**(사용자): *"Device당 · User당(5대 · OS 무관) · 소규모 조직(1~5명) · 그외 조직(6명+)으로 구분하면 어떤가 — 경쟁 제품·최근 정책과 교차 조사·설계 · 조직은 사내 인증 서버 + 데몬으로 사용자/대수 기준 · 서버 개발 설계 포함"* → 이어서 *"인증서버는 별도 Repository · 공유 기능은 별도 라이브러리 · SosomLab(kiros33) 비공개 저장소"*.

**조사**(웹 8건 · [25 §1](../25-license-tiers-and-server.md) 출처 표): 사용자 단위가 표준(DbVisualizer·Sublime·Beekeeper·DBeaver — 본인 기기 무제한 또는 여러 대) · 기기 단위는 TablePlus뿐(1대/2대 · Team $79/석 3석~) · DataGrip은 무제한+동시 1 · 조직용 서버는 **JetBrains License Vault/Floating License Server**(IDE 종료 20분 후 좌석 회수 · 48h 오프라인)가 유일한 실물, DBeaver는 named user만 · Navicat은 주 1대+보조 1대 + deactivate 필수(원성) · DBeaver는 영구 폐지→구독, 나머지는 영구+업데이트 기간.

**판정**: 사용자 4단은 관행과 맞음. 조정 2건 — ① Team(1~5)은 **서버 없이 사용자 파일 묶음이 기본**(5명 조직에 데몬 강제 = 안 팔림 · TablePlus Team도 키만) ② Organization은 **named-user 좌석 기본 + concurrent(floating) 옵션 ×2**. User 5대 상한은 오프라인 파일 방식의 정직한 한계(동시성을 셀 수 없으니 열거).

**서버 설계**([25 §4](../25-license-tiers-and-server.md)): 3단 Ed25519 체인(SosomLab 루트 → 조직 라이선스(`server_key`) → 서버가 서명한 리스) · 클라이언트는 전부 오프라인 검증 · 리스 TTL 7일(서버 장애 내성) · 하트비트 10분 · concurrent 회수 30분 · 오프라인 리스(borrow) 30일 · 구독 만료 유예 30일 · HTTP/1.1 + key=value 본문(JSON 파서 0 · 라이선스 파일과 같은 파서) · SQLite · 정적 관리 페이지 · 3-OS 서비스 스크립트 · HA 미지원(단일+백업 · JetBrains도 단일).

**저장소 분리**([25 §9](../25-license-tiers-and-server.md) · **DR-25**): `SosomLab/nexa-license`(공유 라이브러리 · 형제 path 의존 · nexa-ui 방식 · format/types/verify/request/machine/sign/proto/keys · `Feature`는 없음) ← `nsql-license`(앱 얇은 층) · `SosomLab/nexa-license-server`(비공개 · `nexa-licensed` + `nexa-license-tool`). CI는 checkout 한 줄 추가 — 라이브러리가 비공개면 PAT 필요 → **D-39(공개 권장)**. 확인: nexa-ui·nexa-sql은 PUBLIC(gh) · CI는 토큰 없이 형제 체크아웃.

**결정 대기**: D-32(Team 서버★) · D-33(좌석 모드★) · D-34(가격 비율★) · D-35~38 · D-39(라이브러리 가시성). TODO T-45(라이브러리 저장소 먼저) · T-40~42 · T-44 · T-35는 T-41로 흡수.

### 1. 정품 인증 — [23](../23-license-activation.md) (설계만 · 코드 0)

- 참조 확인: [13 §3](../13-licensing.md)(nexa-dir 17 재사용 방침 — 원본 저장소는 이 기기에 없음 → 원칙만 계승) · nexa-beep `ed25519-dalek 2` 원장(09-06) · `nsql-vault` DPAPI 기기 키(DR-22). nexa-beep P-3(하드웨어 ID 금지)는 **사람 신원** 맥락이라 여기(=이 PC인가)와 목적이 다름을 명기.
- 절차: 요청 코드(`NSQLREQ1.<base32 기기ID 20B>.<메타>`) → 오프라인 발급기(`nsql-license-tool` · 비밀키) → `nexa-sql.license`(key=value + Ed25519 `sig`) → `nsql license install`/GUI → 실행 시 로컬 검증만(네트워크 0).
- 기기 ID = SHA-256(도메인 ‖ OS 기기 식별자: Windows `MachineGuid` · macOS `IOPlatformUUID` · Linux `/etc/machine-id`)[..20] — 원문 미전송.
- 형식: PASETO 대신 **자체 key=value 봉투 + PAE식 정규화 서명**(JSON 파서 0). `features`는 등급이 아니라 낱개.
- 판정: `nsql-license` 크레이트 `check(Feature) -> Allowed | Denied` 순수 함수 1개 · 게이트는 **UI/CLI 진입점 기능당 1곳** · Core/Run/드라이버는 라이선스를 모른다 · 메뉴는 숨기지 않고 `Pro` 배지.
- 정직한 한계: 네이티브 바이너리 패치는 못 막는다 — DRM 아님 · 난독화 안 함.
- **사용자 결정 D-23~D-31** 등재([10 §3](../10-decision-record.md) · D-6 세분): 게이트 목록(★) · 기기 묶음 원천(★) · 모델 영구+1년(★) · 형식 · 키 보관 · 체험판 · 온라인 2차 · 집행 시점 · Team. ⚠️ 13 §3 "무료 제한 없음" 권장을 **정정**하는 결정(D-23).
