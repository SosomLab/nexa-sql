**④ 안전 수정의 경위(데이터 보호 · 있는 그대로)** — `rebase`(적용 중단 뒤 · 고친 스크립트 뒤 다시 읽기)가 서버에 새로 생긴 항목(지난 원본에 없고 편집 모델도 모르는 것)을 편집 모델에 들이지 않아, 다음 차이 계산이 그것을 `DROP COLUMN`으로 잡았다. 개발이 ②를 V1로 돌리다가 발견했다 — 고친 스크립트로 `extra2`를 더한 뒤의 덤프에 `stmt|Danger|ALTER TABLE … DROP COLUMN extra2`. 수정 = 그런 항목을 편집 모델에 들인다(`origin = 자기 이름`) + 시험 `rebase_adopts_server_side_additions_and_keeps_pending_edits`.

이 결함은 1차 · 2차 커밋판(e32337bf · e7e4d719)에도 있었다. 그때 `rebase`로 들어가는 길은 "문장이 중간에 멈춘 뒤"뿐이어서 서버 쪽 추가분이 생기는 경우는 다른 세션의 동시 변경(같은 테이블에 컬럼 · 제약 · 인덱스를 더함)뿐이었지만, 그 경우에도 다음 적용 전 재확인(F-13)은 방금 다시 읽은 원본을 기준으로 통과하므로 **실제 위험이 있었다** — 미리보기에는 위험 문장으로 보이나, 사용자가 요청하지 않은 삭제 문장이 스크립트에 들어간다. 일어났다는 보고는 없다. 배포판(v0.10.2)에는 구조 편집기가 들어 있지 않다(1차 = 11-27 커밋).

## §3. T-526 — 생성 DDL · 객체 백업 DDL의 FK에 삭제 · 갱신 규칙 싣기(개발 구현 · 협업 검증 · 문서)

**무엇(개발 · 2파일)** — `nsql-catalog` `gen.rs` `constraint_line`의 외래 키 가지가 FK 본문 뒤에 ` ON DELETE x` · ` ON UPDATE y`를 붙인다 — 4차의 방언 사전 질의 `key_extras`(이제 `pub(crate)`)로 읽고 새 순수 함수 `fk_rules`가 꼬리를 만든다(빈 값 = 생략 · Oracle은 갱신 규칙을 붙이지 않음 · 시험 `fk_rules_tail`) · 못 읽으면 종전대로(규칙 없는 줄) · PostgreSQL은 종전처럼 `pg_get_constraintdef`. 보수적 생성 원칙([100 §5](../100-object-source-run-and-output-tab.md))의 구멍 = 종전 DDL을 그대로 실행하면 규칙이 `NO ACTION`으로 바뀌었다.

**테이블 DDL이 나오는 길(코드 읽기 + 실행)**

| 방언 | 길 | FK 규칙 |
|---|---|---|
| Oracle | `DBMS_METADATA.GET_DDL`(서버가 만든 DDL) — `constraint_line`을 타지 않는다(테이블 DDL · 하위 DDL 둘 다) | 서버 DDL에 `ON DELETE …`가 종전부터 있다(이번 수정과 무관 · 갱신 규칙은 문법에 없음) |
| PostgreSQL | 자체 조립 + FK 줄은 `pg_get_constraintdef` | 종전부터 포함 · 회귀 없음 |
| SQL Server | 자체 조립 → `constraint_line` | **이번 수정** · 실서버 확인 |
| MySQL / MariaDB | 자체 조립(`table_with_keys` → `constraint_line`) | 이번 수정이 닿는 길(코드 읽기) · **실서버 미확인**(환경 없음) |
| 그 밖 | 자체 조립 | `key_extras`가 `None` → 종전대로(규칙 없는 줄) |
| SQLite | `sqlite_master.sql` 원문 | 원문 그대로 |

**검증(협업)** — Debug 빌드 ✓ · `cargo test -p nsql-catalog` 36 / 0 / 0 · `clippy --workspace --all-targets -D warnings` ✓ · 실서버 3방언(부모 · 자식 임시 테이블 · 규칙 있는 FK `_FK` 하나 + 규칙 없는 FK `_F2` 하나 · 격리 홈 · 헤드리스 · 끝에 `DROP` 뒤 남은 수 0) = **각 10 통과 / 0 실패**. 요약 = `target/verify/n1128-t526/summary.txt` · 방언별 로그 `e2e3-*.log`.

| 판정 | SQL Server | Oracle | PostgreSQL |
|---|---|---|---|
| ① 테이블 DDL(`nsql cat … gen ddl <T>`) — `_FK`에 규칙 · `_F2`에 꼬리 없음 | ✓ | ✓(서버 DDL) | ✓ |
| ① 하위 DDL(`gen ddl <T> table foreign_keys <이름>`) — 같은 판정 | ✓ | ✓ | ✓ |
| ③ 생성 DDL의 테이블 이름만 바꿔 실행(rc 0) → 사본의 카탈로그 규칙 = 원본 | ✓ | ✓ | ✓ |
| ② 구조 편집기에서 `ALTER TABLE … ADD` 한 문장 적용(`Applied 1 of 1`) → `backups/objects` 백업 파일의 FK 두 줄 | ✓ | ✓ | ✓ |

원문(이름은 익명 · `<T>` = 자식 · `<TP>` = 부모):
- SQL Server 생성 DDL · 객체 백업(같은 두 줄) = `ALTER TABLE <DB>.dbo.<T> ADD CONSTRAINT <T>_F2 FOREIGN KEY (pid2) REFERENCES dbo.<TP> ([id]);` · `ALTER TABLE <DB>.dbo.<T> ADD CONSTRAINT <T>_FK FOREIGN KEY (pid) REFERENCES dbo.<TP> ([id]) ON DELETE SET NULL ON UPDATE CASCADE;` · 카탈로그(원본 = 사본) = `_F2` 갱신 `NO_ACTION` / 삭제 `NO_ACTION` · `_FK` 갱신 `CASCADE` / 삭제 `SET_NULL`.
- Oracle(서버 DDL · 두 줄에 걸침) = `ALTER TABLE "<S>"."<T>" ADD CONSTRAINT "<T>_FK" FOREIGN KEY ("PID")` + `REFERENCES "<S>"."<TP>" ("ID") ON DELETE SET NULL ENABLE;` · `_F2`는 `… ("ID") ENABLE;` · 카탈로그(원본 = 사본) = `_F2` 삭제 `NO ACTION` · `_FK` 삭제 `SET NULL`.
- PostgreSQL = `ALTER TABLE public.<T> ADD CONSTRAINT <T>_f2 FOREIGN KEY (pid2) REFERENCES <TP>(id);` · `… <T>_fk FOREIGN KEY (pid) REFERENCES <TP>(id) ON UPDATE CASCADE ON DELETE SET NULL;` · 카탈로그(원본 = 사본) = `_f2` `a` / `a` · `_fk` 갱신 `c` / 삭제 `n`.

**판정 스크립트에서 배운 것(제품 결함 아님)** — ① 객체 백업은 `ALTER` · `DROP` · `RENAME` · `TRUNCATE` · `CREATE OR REPLACE` 문장에서만 만들어진다(`objbackup.rs` `backup_targets`) — 코멘트만 바꾸는 적용(`COMMENT ON …` · `EXEC sys.sp_addextendedproperty …`)은 대상이 아니라 백업 파일이 없다(첫 판이 "백업 파일 없음"으로 떨어진 까닭) → `ALTER TABLE … ADD t526 …` 한 문장을 미리보기 편집본 길(`tbledit.apply_script`)로 실행 ② `tbledit.apply_script`는 대기 중인 변경이 있을 때만 동작한다(`can_apply`) — 변경 없이 부르면 조용히 아무 일도 없다 ③ Oracle 서버 DDL은 FK가 두 줄이라 줄 단위 grep이 규칙을 놓친다 → 문장(`;`) 단위로 판정.

**소견(개발에 전달 · 막지 않음)** — ① `gen.rs` 시험 모듈에서 `fk_rules_tail`이 문서 주석 `/// 바인드 목록 주석(09-28): …`과 그 주석의 주인(`bind_note_lists_binds_in_order`) 사이에 들어가 주석이 엉뚱한 시험에 붙었다(겉보기) ② `key_extras`를 FK 줄마다 다시 질의한다(FK N개 = 테이블 DDL 한 번에 질의 N번 더 · 재지 않음 · 한 번 읽어 넘기면 준다) ③ 자체 조립 길은 제약 상태(비활성 · 미검증 · `NOT FOR REPLICATION`)를 싣지 않는다(코드 grep · 실행 재현 안 함) → **T-527** ④ PostgreSQL FK 줄의 참조 대상은 검색 경로에 있으면 스키마 없이 나간다(`REFERENCES <TP>(id)` · 테이블 이름 쪽은 `public.`으로 한정됨 → T-527 ④) ⑤ 코멘트 변경 · `sp_rename`만 있는 적용은 객체 백업이 없다(설계대로 · 위 ①).

**확인하지 않은 것** — MySQL / MariaDB 실서버(규칙 글자 `RESTRICT` · `SET DEFAULT` 포함) · 화면 메뉴의 Generate DDL 조작 길(같은 생성기를 CLI와 객체 백업으로 확인) · 다른 스키마 대상 FK · 다중 컬럼 FK · 비활성 FK(T-527) · `cargo test --workspace` 전체와 V1 전체(이번 = 바뀐 크레이트 범위) · Windows · macOS(커밋 뒤 CI).
