### ⑲ 환경 변수 치환 — `${env:이름[:형식]}`
- 조사한 도구: sqlcmd = `$(v)`가 스크립트 변수 → **환경 변수** 순으로 찾는다 · VS Code = `${env:NAME}` · psql = `\getenv` · SQL*Plus = 없음(셸에 맡김). 이미 만든 `${…}` 문법에 **`env:` 접두**로 붙였다(사용자 정의 `env`라는 치환 변수와 섞이지 않는다 — `${env}` = 사용자 변수 · `${env:X}` = 환경 변수).

- 설정 **`vars.env_subst`**(기본 켬 · `vars.brace_subst`에 종속) — 값이 서버로 가는 SQL 글의 일부가 되고 로그에도 남으므로 설명에 "믿을 수 없는 스크립트를 돌린다면 끄세요"를 적었다.
- 확인: CLI로 `${env:USERNAME:q}` · `${env:NUMBER_OF_PROCESSORS:n}` · 없는 변수 그대로.

### 수정
- 옆으로 나가도 **y의 줄을 따라간다**: 왼쪽 밖 = 그 줄의 처음 · 오른쪽 밖 = 그 줄의 끝(VS Code·Sublime과 같다). 한 글자씩 가는 가로 자동 스크롤은 **같은 줄에서 그쪽에 가려진 글이 있을 때만**(왼쪽 = 가로 스크롤 > 0 · 오른쪽 = 보이는 끝 뒤에 글이 더 있음).
- 줄 판정 = 버퍼의 줄 표(`line_of` · `line_count` · `line_end` — O(log 줄 수)) → **0.001 ms 미만/이동**(2 MB · 20 MB 같음).
- 위·아래 밖: 사건마다 한 줄 → **멀리 나갈수록 여러 줄**(거리 ÷ 줄 높이 + 1 · 최대 12줄) — 긴 구간을 빠르게.
- 같은 종류 조사: 입력 처리 경로의 `text()`/글자 배열 사용을 훑어 **세 번 클릭(줄 선택)** 도 본문 전체를 문자열 + `Vec<char>`로 뜨던 것을 줄 표로 바꿨다(큰 파일에서 수백 MB 할당).
- 남긴 것: 포인터를 밖에 **가만히** 두면 계속 스크롤되는 타이머식 자동 스크롤은 없다(지금 = 움직일 때만) → T-158.

### 일회성 비밀번호(T-132 ②)
- **세 가지를 구분한다**(`ConnectSpec::parse`): `user@host` = 비밀번호 **없음**(`None` → 묻는다) · `user:@host`(`user/@host`) = 빈 비밀번호를 **명시**(`Some("")` → 묻지 않고 그대로 접속) · `user:pw@host` = 그 값. CLI도 같다(`ensure_password`는 `None`일 때만 묻는다 · 도움말 갱신).
- **묻는 자리 = 접속을 여는 한 곳**(워커의 `Opener`): 편집기 `CONNECT` · 시작 인자 · 탐색기 "연결" · 끊긴 뒤 재접속 · 비밀번호 없이 저장한 프로필이 모두 이 길을 지난다. `password_required`(SQLite 아님 · 호스트 있음 · `password == None`)이면 `ConnOutcome::PasswordNeeded{가린 접속 문자열}`을 내고 답(`PwReply`)을 기다린다 — **서버에는 아직 아무것도 가지 않았다**(도달 불가 서버는 빠른 판정이 먼저 걸러 묻지도 않는다). 취소 = "접속 취소" 오류.
- **입력 창** = 변수 입력 창의 비밀번호 모드(`InputWin::open_password`): 가린 입력란 하나 · 안내 "… 의 비밀번호 — 이번 접속에만 쓰고 저장하지 않습니다" · 버튼 = 접속/취소("건너뛰기" 없음) · Enter/Esc · ■(중지)·연결 해제 = 취소.
- **새지 않게**: 값은 `nsql_core::Secret`(복제 없음 · `Debug`는 `***` · 버려질 때 volatile 쓰기로 **0 덮어쓰기**)로만 옮긴다 · 입력란은 꺼내는 즉시 본문·되돌리기 기록·조합 글을 0으로 덮는다(nexa-ctl `TextBox::take_secret_text`/`wipe`) · **가린 입력란은 복사·잘라내기를 하지 않는다**(종전에는 됐다 — 클립보드로 새는 길) · 붙여넣기로 뜬 사본도 지운다 · 워커는 그 접속용 스펙 사본에만 넣고 드라이버가 돌아오면 덮어쓴다 · Oracle 드라이버는 비밀번호를 복제하지 않고 빌려 쓴다 · 세션 스펙·프로필·설정·로그·이력·상태줄에는 **들어가지 않는다**(표시는 늘 `redacted()`).
- **탐색기 메타 세션**: 같은 자격이 있어야 트리가 보이므로 둘째 사본을 `App.pw_once`에 잠깐 쥐었다가 `explorer_attach`에서 그 호출에만 빌려주고 지운다(못 쓰면 20초 뒤 폐기) · 메타 스레드도 접속 뒤 지우고 재개용 스펙에 넣지 않는다 → 그 서버 칸은 **유휴 회수를 하지 않는다**(`Explorer::one_time` — 다시 열 자격이 없으므로). 또 메타 스레드는 비밀번호 자리가 없는 스펙으로는 **서버에 가지 않는다**(빈 비밀번호 로그인 시도가 쌓여 계정이 잠기는 것을 막는다 · 26 §8).
- **한계(정직하게)**: 우리가 쥔 버퍼만 지울 수 있다 — 드라이버 크레이트(tiberius · postgres · ODPI-C)의 내부 사본, OS 입력 메시지 큐, 페이지 파일로 내려간 메모리, 버퍼가 자라며 반환된 옛 할당은 닿지 않는다. 규칙 = 사본 최소 · 쓰자마자 지움 · 저장 0.
- 검증: 단위 테스트(해석 3형 · `password_required` MC/DC · 워커 "묻는다 → 취소 = 드라이버에 안 감 / `user:@` = 묻지 않음"(로컬 더미 리스너 · 네트워크 0) · `Secret` 덮어쓰기 · 가린 상자 복사 불가 + 꺼낸 뒤 되돌리기로도 안 돌아옴) · 실기 캡처(입력 창 · `user:@` = 창 없이 드라이버 오류). **실제 비밀번호를 쳐서 접속하는 실기는 사용자 몫**(입력 주입 금지 · 비밀번호를 모른다) → T-154 U-12.

## 89차 추가 13 (win) — 사용자(캡처) "새로 고침을 한 뒤 자동으로 확장된다 — 확장되지 않게 · 한 번도 열지 않았던 대상만 그렇다 · 펼쳤다 접은 대상은 확장 없이 갱신된다"

## 89차 추가 21 (win · push 뒤) — 사용자(캡처) "SQL Server에서 `SELECT :V_LIMIT, :V_NOTE …`를 실행하면 결과 머리줄이 비어 있다 — Oracle은 변수 이름이 머리줄로 나온다"
- **원인**: Oracle은 `:V`를 그대로 보내므로 서버가 그 표기를 열 이름으로 돌려준다. SQL Server는 `:V` → `@V` 매개변수로 고쳐 보내는데, **매개변수만 있는 열에는 서버가 이름을 주지 않는다**(PostgreSQL은 `?column?`).
- **수정**(nsql-script `prepare_with`): **바인드 하나뿐인 SELECT 항목**에 변수 표기를 열 이름으로 붙인다 — SQL Server `@V AS [:V]` · PostgreSQL `$1 AS ":V"`(쓴 그대로의 대소문자). 판정 `lone_select_items` = 괄호 밖 · 가장 가까운 절 머리가 `SELECT` · 앞이 `SELECT`/`DISTINCT`/`ALL`/`,` · 뒤가 `,`/`;`/끝/`FROM` · 주석·글자 상수 밖(`lexer::classify`). 연산(`:a + 1`) · 이미 별칭이 있는 항목 · 함수 인자 · `IN (…)` · `WHERE` · `ORDER BY` · `UPDATE … SET` · 부속 질의 안은 건드리지 않는다. `?` 표식 방언(MySQL · SQLite · ODBC)은 인용 규칙이 제각각이라 이번에는 두지 않았다.
- 같은 캡처의 `3.0000000000`: 숫자 변수는 값이 돌아올 수 있게 `DECIMAL(38,10)`으로 선언해 보내는데, **읽기만 하는 바인드**까지 그래서 정수 3이 소수 10자리로 돌아왔다 → mssql 드라이버 `declared_type`: `IN` 방향의 숫자 = 정수면 `BIGINT` · 소수면 그 자릿수의 `DECIMAL(38,s)`(`OUT`/`IN OUT`은 종전대로). 결과 셀을 다듬는 대신 **보내는 타입**을 고쳤다(서버가 준 자릿수를 화면이 바꾸면 진짜 `DECIMAL(10,2)` 열까지 달라진다).
