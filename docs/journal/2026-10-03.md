## 2. 🔧 `EXEC`로 시작하는 문장이 포맷되지 않음(사용자 10-03)

요구 = ① `EXEC` 뒤가 `SELECT … INTO`면 정상 포맷 ② `EXEC` 뒤가 패키지/프로시저 호출이면 **한 줄**.

- 원인: nsql-format `layout`이 첫 단어가 SELECT/WITH/INSERT/UPDATE/DELETE/MERGE가 아닌 문장을 **원문 통과**시켰다 — `EXEC`도 그 하나. 게다가 문장을 최상위 `;`로만 나눠, `;` 없는 스크립트 명령 줄(`PRINT` · `EXEC :v := …` · `:setvar`)이 다음 `;`까지 뒤 문장을 삼켜 통째로 통과였다.
- 수정(`crates/nsql-format/src/layout.rs` `exec_statement`): `EXEC`/`EXECUTE` 문의 끝을 **실행기(nsql-script `split`)와 같은 규칙**으로 정한다 — 홀로 선 `EXEC` = 다음 줄부터 `;` · 빈 줄 · 단독 `/` · 다음 명령 줄까지(블록) · 한 줄 `EXEC …` = 그 줄(괄호가 열려 있거나 · 콤마로 이어지거나 · `@a = 1` 이름 지정 인자면 다음 줄까지).
  - 본문이 `SELECT`/`WITH` → `EXEC` 한 줄 + 본문을 평소대로 포맷(블록 꼴 · 한 줄 꼴 `EXEC SELECT …`도 블록 꼴로 · `;` 없이 바로 다음 줄에 SQL이 이어지면 블록이 그 줄을 삼키지 않게 `;`를 붙인다 = 토큰 보존의 명시적 예외).
  - 본문이 프로시저·패키지 호출(`이름[.이름…]` 뒤가 끝/`(`/인자) → **한 줄**(줄 바꿈만 없앤다 · 이미 한 줄이면 간격은 원문 그대로 · 여러 줄이었으면 줄 안 간격은 한 칸).
  - 그 밖(대입 `:v := …` · `OPEN … FOR` · 주석이 낀 호출) → 원문 그대로(사용자 탭 정렬 `EXEC	:V			:=	'…'` 유지).
- 같이 고친 것(포맷 결과가 **실행되게** 하는 데 필요했던 것):
  - 그 밖의 스크립트 명령 줄(`PRINT` · `SET` · `VARIABLE` · `:setvar` · `@파일` · 단독 `/`·`GO` …)은 **그 줄에서 끝**(원문 그대로) · 단독 `/`·`GO` 줄 = SQL 문장의 끝(실행기 `collect_sql`과 같게) · 명령 줄 앞뒤에는 빈 줄을 강제로 넣지 않는다(원문 빈 줄 수 유지).
  - 빈 줄 수를 넣는 자리 = 문장이 만든 **첫 줄**(종전 `apply_blank`는 첫 단어로 시작하는 줄을 거꾸로 찾아, 앞 문장에 빈 줄이 없으면 앞 문장의 줄에 넣었다 → 제거).
  - 렉서: 치환 변수 `&v`·`&&v`·`&1` = 한 토큰(종전 `&Top` → `& TOP` · 대소문자 변환까지).
  - `SELECT … INTO :변수`에는 `format.column_alias_all`이 별칭을 만들지 않는다(실행기가 `@V = 식` · `식 AS "V"`로 다시 쓰므로 붙인 별칭이 문장을 깨뜨린다 · `Walker::select_into_vars`).
  - 🔧 **실행기 결함 둘**(nsql-script): ① `is_command_start`가 명령 단어 뒤 글자를 영숫자만 봐서 `EXEC` 블록 본문의 `COLUMN_NAME` · `SET_ID` 줄을 `COLUMN`/`SET` 명령으로 읽어 본문을 끊었다 → `_`·`$`·`#`도 이름 글자 ② 블록 본문의 `CONNECT BY`뿐인 줄(포맷터가 절 키워드를 제 줄에 둔다)을 접속 명령으로 읽어 끊었다 → 본문 안에서는 절.
- 검증: nsql-format 시험 +5(35) · nsql-script +2(113 → `exec_block_body_keeps_identifier_and_connect_by_lines` · `brace_format_suffix_is_not_a_bind`) · 전체 739 ✓ · clippy 0 · `examples/*.sql` 6개를 기본 옵션으로 포맷한 뒤 `nsql plan` 전/후 = 항목 수·재작성 SQL 같음(줄 바꿈만 다름) · 격리 홈 GUI(`open → edit.format → file.save`) = 캐럿 문장(홀로 선 `EXEC` 블록만 바뀜)·전체 선택(여러 줄 호출 → 한 줄) 둘 다 저장 파일로 확인.
- 남음: ① 확장 **SQL Formatter for kiros33**은 nsql-format을 wasm 안에 품는다 — 이 PC에는 `wasm32-unknown-unknown` 타깃이 없어 재빌드하지 않았다(다음 확장 빌드 때 `scripts/ext-build` + 버전 올림 · 그때까지 kiros33로 포맷하면 `EXEC`는 종전대로 통과) ② 한 줄 꼴 `EXEC p(…` 가 여러 줄에 걸친 경우 **캐럿 문장 포맷**은 실행기 범위(첫 줄)만 잡는다 → 선택해서 포맷(홀로 선 `EXEC` 꼴은 캐럿만으로 된다) ③ 발견한 기존 흠(이번 범위 밖): `N'x'` → `N 'x'` · 단항 음수 `-1` → `- 1`(SELECT 포맷 · T-255 후보).

## 3. 🔧 `SELECT ${who:q} …` 실행 = 변수 값 입력 창이 `:Q`를 묻는다(사용자 10-03 캡처)

- 원인: 실행 전 입력 조사 `nsql_script::missing_inputs`가 치환 **전** 원문에서 바인드를 찾는다 — `${who:q}`의 형식 접미 `:q`가 바인드 `:Q`로 읽혔다(`'${own:lower}'`는 문자열 안이라 안 걸림). 엔진 자체는 정상(`nsql plan` = `SELECT 'O''Neil' AS quoted, 'sys' AS low FROM DUAL`).
- 수정(`crates/nsql-script/src/inputs.rs` `mask_brace_refs`): 바인드를 찾을 때 `${…}` 구간을 같은 길이의 공백으로 가린다(SQL 문장 · `EXEC` 본문 · 블록) — 치환은 실행 때 엔진이 그대로.
- 검증: 단위 시험(`:real`만 묻는다) · 격리 홈 GUI(SQLite · `DEFINE` 둘 + `SELECT ${who:q}, '${own:lower}'` `run.all`) = 입력 창 없음 · 결과 `O'Neil | sys`.

찾아서 고친 것(전부 **뜻이 바뀌거나 구문이 깨지던** 것 · nsql-format):
- 🔧 **`${who:q}` → `$ { who :q }`**: 렉서가 `${…}`를 네 토큰으로 찢어 치환이 깨졌다 → `${이름[:형식]}`·`${env:…}` = 한 토큰(같은 줄의 `}`까지).
- 🔧 **PL/SQL 블록 뒤 문장이 전부 원문**: 통과 블록(`DECLARE`/`BEGIN`/`CREATE … PROCEDURE|FUNCTION|PACKAGE|TRIGGER|TYPE|BODY`)이 **문서 끝까지** 통과였다(설계 · 95 §3) → `layout::block_end` = 단독 `/`·`GO` 줄 앞 · 없으면 `BEGIN`/`CASE`…`END` 짝이 0으로 돌아온 뒤(짝 없는 `END p;` = 명세 끝) 다음 최상위 `;` 뒤(`END IF`·`END LOOP`·`END WHILE`·`END REPEAT`·`END FOR`는 짝 아님) · `BEGIN;`·`BEGIN TRANSACTION` = 블록 아님(실행기 `is_begin_transaction`과 같게).
- 🔧 **접두 문자열 `N'x'` → `N 'x'`**(SQL Server에서 뜻이 바뀜) · **Oracle `q'[it's]'` 토막**: 단어 바로 뒤 `'` = `N`·`B`·`X`·`E`(`\'` 이스케이프)·`U`·`R` 접두 문자열 · `q`·`nq` = 구분자 짝(`[]{}()<>` · 그 밖 같은 글자)까지 한 Str 토큰.
- 🔧 **단항 부호 `-1` → `- 1`** · **캐스트 `a::text` → `a :: text`**: `need_space` = 조각 첫머리·`(`·`,`·연산자·키워드 뒤의 `-`/`+`는 붙인다(`a - 1`은 그대로) · `::` 앞뒤 붙임.
