## 8차 (mac) — 신호등 점검 대상 기준 · macOS ICMP 판정

**증상**(사용자): 서버는 살아 있고 포트만 안 열리는 두 번째 프로필이 Test/Connect를 해 봤는데도 실행 시 점검 대상이 아니다(회색). Windows에서는 파란색(호스트 살아 있음)이 바로 뜬다.
**원인 2가지**
1. 기준: 대상 = "한 번 이상 접속에 **성공**한 프로필"(`connected.list` · 09-14)이라 실패만 한 프로필은 실패 직후 1회만 묻고 재예약하지 않는다 → 다음에 창을 열면 회색.
2. **OS 이슈**: unix ICMP 판정이 `ping -c 1 -W <초>`인데 macOS `ping`의 `-W`는 **밀리초**(Linux iputils는 초) → 맥에서는 2ms 대기 = 항상 실패 → "연결 거부"가 아닌 타임아웃(필터링 포트)은 파란색이 될 수 없고 빨강/회색. ★ 정정(실측 뒤): 이 맥에서 61.81.244.214에 `-W 2000 -t 2`도 `-W 2`(=2ms)도 exit 0 — macOS `ping`은 `-W`를 넘겨 늦게 온 응답도 통계에는 반영해 `-c 1`이면 성공으로 끝난다. 즉 단위 불일치는 사실이고 고쳐야 맞지만(응답이 느린 망에서 판정이 흔들림), **회색의 확정 원인은 1번(대상 기준)**이다.
**조치**: 기준을 "한 번 이상 **시도**(Test/Connect)한 프로필"로 확장 — `ConnWin::mark_attempted`(시도 시작 시 `connected.list`에 기록 · 활성 프로필은 건드리지 않음 · 즉시 예약) · 문서/주석 정정. macOS는 `ping -c 1 -W <ms> -t <초>`(`ping_args` · 테스트). Windows(`IcmpSendEcho`)는 변경 없음.

## 11차 (win) — 저장소 최신화 · Windows 빌드/테스트 · 즉시 접속 해제(서버 무응답)

**최신화**(사용자 "저장소 최신화 및 변경사항 분석"): nexa-sql 11 커밋 · nexa-ui 6 커밋 fast-forward(로컬 변경 0). Windows 검증 = release/debug 빌드 ✓ · nexa-sql 테스트 132 ✓ · nexa-ui 테스트 258 ✓ · clippy ✓ · CI 3-OS 양쪽 success. 맥 세션 변경의 실기 재검증(T-88 · 잉크 정렬·스플리터·아이콘·메뉴 배율)은 사용자 캡처 몫.

**즉시 접속 해제**(사용자: VPN 끊긴 채 테이블 조회가 "Loading…"에 멈추면 Disconnect가 무반응 → 서버 상태와 무관하게 끊기게).
- **원인**: DB 워커·탐색기 메타 스레드 모두 순차 큐. Disconnect는 큐 뒤에 서고, 워커 자체의 해제도 세션 `commit`/닫기(OCI 왕복)를 부르므로 응답 없는 서버에서 TCP 타임아웃까지 갇힌다 → UI `busy`가 안 풀리고 탐색기는 Loading 유지.
- **조치**(`main.rs disconnect_now` · `Explorer::disconnect`): **기다리지 않고 버린다** — 옛 워커/메타 스레드에 Disconnect/Close를 남기고 채널을 버린 뒤 새 스레드로 교체(`spawn_worker` · `spawn_meta`). 갇힌 호출이 풀리면 옛 스레드가 세션을 닫고 스스로 끝난다(늦은 이벤트는 버려진 채널로 사라짐). UI는 즉시 해제 상태(`busy=false` · 상태줄 · 탐색기 초기화 · 툴바 · 접속 창 = `on_conn_disconnected` 공용). 실행 중이었으면 상태줄/로그에 `StDisconnectedAbandon`("서버 응답 없음 · 세션은 버림"). 다음 접속은 새 워커가 받는다.
- 테스트 `worker::tests::replacement_worker_answers_while_old_one_is_stuck`(옛 워커가 비라우팅 주소 접속에 갇혀도 새 워커가 5초 안에 응답).
- 남는 것: 버려진 스레드는 드라이버 타임아웃(수십 초~수 분)까지 하나 남는다 — 회수는 OS/드라이버 몫 · 반복 눌러도 스레드는 해제마다 1개.
