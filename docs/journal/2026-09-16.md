## 8차 (mac) — 신호등 점검 대상 기준 · macOS ICMP 판정

**증상**(사용자): 서버는 살아 있고 포트만 안 열리는 두 번째 프로필이 Test/Connect를 해 봤는데도 실행 시 점검 대상이 아니다(회색). Windows에서는 파란색(호스트 살아 있음)이 바로 뜬다.
**원인 2가지**
1. 기준: 대상 = "한 번 이상 접속에 **성공**한 프로필"(`connected.list` · 09-14)이라 실패만 한 프로필은 실패 직후 1회만 묻고 재예약하지 않는다 → 다음에 창을 열면 회색.
2. **OS 이슈**: unix ICMP 판정이 `ping -c 1 -W <초>`인데 macOS `ping`의 `-W`는 **밀리초**(Linux iputils는 초) → 맥에서는 2ms 대기 = 항상 실패 → "연결 거부"가 아닌 타임아웃(필터링 포트)은 파란색이 될 수 없고 빨강/회색. ★ 정정(실측 뒤): 이 맥에서 61.81.244.214에 `-W 2000 -t 2`도 `-W 2`(=2ms)도 exit 0 — macOS `ping`은 `-W`를 넘겨 늦게 온 응답도 통계에는 반영해 `-c 1`이면 성공으로 끝난다. 즉 단위 불일치는 사실이고 고쳐야 맞지만(응답이 느린 망에서 판정이 흔들림), **회색의 확정 원인은 1번(대상 기준)**이다.
**조치**: 기준을 "한 번 이상 **시도**(Test/Connect)한 프로필"로 확장 — `ConnWin::mark_attempted`(시도 시작 시 `connected.list`에 기록 · 활성 프로필은 건드리지 않음 · 즉시 예약) · 문서/주석 정정. macOS는 `ping -c 1 -W <ms> -t <초>`(`ping_args` · 테스트). Windows(`IcmpSendEcho`)는 변경 없음.

## 16차 (win) — CLI 표 폭: 확인·설정·기본값(`cli.*` · `--width` · 셸 `set`)

**증상**(사용자): `nsql shell`에서 45개 컬럼 결과가 터미널 폭에서 접혀 깨진다 — 기본 폭을 확인/설정하는 방법과 CLI 기본 설정을 두는 방법.
**종전**: 컬럼 상한 60 고정(`format_grid(rs, 60)`) · 줄 폭 개념 없음 → 터미널이 접는다.

| 층 | 방법 | 범위 |
|---|---|---|
| 확인 | `nsql config get cli.width` · `nsql config list`(CLI 분류) · 셸에서 `show` | — |
| 영구 기본값 | `nsql config set cli.width 160` · `cli.max_col_width 40` · `cli.overflow wrap\|truncate\|expanded\|none`(GUI 설정 창 CLI 분류에도 보임 · `settings.conf` 공유) | 모든 명령 |
| 1회성 | `--width N` · `--max-col-width N` · `--overflow …` · `-x`(expanded) | 그 실행 |
| 세션 | 셸 `set width <n\|auto>` · `set colwidth <n>` · `set overflow …` · `\x`(토글) · `show` | 셸 동안 |

**기본값**: `cli.width` 0 = **터미널이면 콘솔 폭 자동**(Windows `GetConsoleScreenBufferInfo` · unix `COLUMNS`/`stty size`) · 파이프/파일이면 무제한(종전과 동일 출력) · `cli.max_col_width` 60(종전) · `cli.overflow` **wrap**(컬럼을 폭에 맞는 묶음으로 나눠 묶음마다 표 · 맨 앞 `#` 행 번호로 행을 잇는다 · sqlplus LINESIZE 줄바꿈의 읽기 쉬운 형태). truncate = 넓은 컬럼부터 줄여 한 줄에(최소 4칸 · `…`) · expanded = `-[ RECORD n ]` + `컬럼 | 값`(psql `\x` · 폭과 무관하게 늘) · none = 종전.
**구현**: nsql-io `GridOpts`/`Overflow`/`format_grid_opts`/`write_result_set_opts`(기존 `format_grid`·`write_result_set`은 종전 동작 유지) + 테스트 4(폭 안 보장 · 잘림 표시 · 레코드 수 · 맞으면 단일 표 동일) · nsql-settings `cli.width`/`cli.max_col_width`/`cli.overflow`(CATEGORY_TREE 접속 옆 CLI) · i18n 12 · nsql-cli `grid_opts`(설정 → 플래그 → 자동 폭) · `Printer.grid` · `shell_set` · `term::columns()` · 도움말.
**셸 조회**(사용자 후속): `get width` · `show width` · `get`/`show`/`help set` = 전체 + 사용법 · `set width 120;`처럼 끝 `;` 허용. 모르는 키는 SQL로 넘어간다(MSSQL `SET NOCOUNT ON` 같은 진짜 SQL을 막지 않기 위해).
**검증**: 파이프 = 종전 출력 · `--width 70` wrap 묶음 2개 + `#` · truncate `…` · `-x` 레코드 · `config get/list`. 사용 문서는 다른 세션이 쓰는 [40 CLI 사용법](../40-cli-usage.md)에 §(표 폭) 추가 필요 — 그쪽 세션에 인계.

## 44차 (win) — ★ 글자 선명도: Windows GDI 글리프 경로(`ui.text_gdi`) · 자체 캡처 비교 · D-77

- **§4 출력 형식 상세**(사용자 요청) — 형식 12종 별칭표 · 같은 결과를 형식만 바꾼 실제 출력(markdown `---:` 오른쪽 정렬 · json 배열 · jsonl) · **SQL 5종**(`sql:select|insert|update|delete|merge` + `insert:<테이블>`) 생성문 · 표 모양 4모드(`none`/`wrap`/`truncate`/`expanded` · `-x`) · 세 층위(셸 `set` > 플래그 > `cli.*`) · **stdout/stderr 분리**(데이터만 리다이렉트) · 종료 코드 = 실패 항목 수 · 셸 `copy`.
  - ★ **안전 경고를 본문에 넣었다**: `sql:update|delete|merge`는 PK도 유니크 인덱스도 없으면 **앞 3컬럼**을 키로 쓰고 주석 경고를 단다([41](../41-sql-copy-key-rules.md)) — 이때 실행 전 `WHERE`/`ON` 확인, `sql.key_mode all` 대안까지.
- **§1 접속 — 직접 지정을 프로필보다 앞에**(사용자 요청). 파서(`nsql-script/src/connect.rs`)를 읽고 `NSQL_HOME`을 임시 폴더로 돌린 `conn add --no-prompt` → `conn show`로 **파싱만** 검증(실제 vault 무손상):
  - URL 형식에서만 퍼센트 디코딩(`p%40ss%2Fword` → `p@ss/word`) · SQL\*Plus 꼴은 **마지막 `@`**가 호스트 구분자라 `scott/p@ss@host`는 통함
  - `as sysdba` 접미 · `?dialect=`/`?type=` 강제 · 빈 사용자 `@host:1521/ORCL`
  - ⚠️ **`@`는 생략 불가** — `dbhost:1521/ORCL?dialect=oracle`은 `dbhost`를 **사용자명**으로 읽는다(실측 `oracle://h:1521/***`)
  - 비밀번호 순서 = `-p` → **`NSQL_PASSWORD`** → 숨김 프롬프트 → `--no-prompt`면 실패 · 필드 형식(`--host` 등)은 `conn` 전용이 아니라 `run`/`shell`/`export`/`explain`/`cat` 전부가 받는다
- **결함 1건 발견(미수정 · T-101)**: `nsql run --help`의 `--overflow` 설명이 *"Default: cli.overflow = wrap"*인데 실제 기본값은 **`none`**(`config get cli.overflow` · 셸 `show` 모두 `none`). `help.rs` 문구 오류 — 문서에는 실제값을 적었다.
- **이 세션은 소스를 고치지 않는다**(사용자 09-15 지정 · 조사·문서 전담). 46차 STATUS의 *"`docs/README.md`·`docs/40-cli-usage.md`는 다른 세션 소유(미커밋)"* 인수인계대로 이 커밋에서 정리했다.
