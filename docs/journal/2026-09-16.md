## 8차 (mac) — 신호등 점검 대상 기준 · macOS ICMP 판정

**증상**(사용자): 서버는 살아 있고 포트만 안 열리는 두 번째 프로필이 Test/Connect를 해 봤는데도 실행 시 점검 대상이 아니다(회색). Windows에서는 파란색(호스트 살아 있음)이 바로 뜬다.
**원인 2가지**
1. 기준: 대상 = "한 번 이상 접속에 **성공**한 프로필"(`connected.list` · 09-14)이라 실패만 한 프로필은 실패 직후 1회만 묻고 재예약하지 않는다 → 다음에 창을 열면 회색.
2. **OS 이슈**: unix ICMP 판정이 `ping -c 1 -W <초>`인데 macOS `ping`의 `-W`는 **밀리초**(Linux iputils는 초) → 맥에서는 2ms 대기 = 항상 실패 → "연결 거부"가 아닌 타임아웃(필터링 포트)은 파란색이 될 수 없고 빨강/회색. ★ 정정(실측 뒤): 이 맥에서 61.81.244.214에 `-W 2000 -t 2`도 `-W 2`(=2ms)도 exit 0 — macOS `ping`은 `-W`를 넘겨 늦게 온 응답도 통계에는 반영해 `-c 1`이면 성공으로 끝난다. 즉 단위 불일치는 사실이고 고쳐야 맞지만(응답이 느린 망에서 판정이 흔들림), **회색의 확정 원인은 1번(대상 기준)**이다.
**조치**: 기준을 "한 번 이상 **시도**(Test/Connect)한 프로필"로 확장 — `ConnWin::mark_attempted`(시도 시작 시 `connected.list`에 기록 · 활성 프로필은 건드리지 않음 · 즉시 예약) · 문서/주석 정정. macOS는 `ping -c 1 -W <ms> -t <초>`(`ping_args` · 테스트). Windows(`IcmpSendEcho`)는 변경 없음.

## 16차 (win) — CLI 표 폭: 확인·설정·기본값(`cli.*` · `--width` · 셸 `set`)

**증상**(사용자): `nsql shell`에서 45개 컬럼 결과가 터미널 폭에서 접혀 깨진다 — 기본 폭을 확인/설정하는 방법과 CLI 기본 설정을 두는 방법.
**종전**: 컬럼 상한 60 고정(`format_grid(rs, 60)`) · 줄 폭 개념 없음 → 터미널이 접는다.

| 층 | 방법 | 범위 |
|---|---|---|
| 확인 | `nsql config get cli.width` · `nsql config list`(CLI 분류) · 셸에서 `show` | — |
| 영구 기본값 | `nsql config set cli.width 160` · `cli.max_col_width 40` · `cli.overflow wrap\|truncate\|expanded\|none`(GUI 설정 창 CLI 분류에도 보임 · `settings.conf` 공유) | 모든 명령 |
| 1회성 | `--width N` · `--max-col-width N` · `--overflow …` · `-x`(expanded) | 그 실행 |
| 세션 | 셸 `set width <n\|auto>` · `set colwidth <n>` · `set overflow …` · `\x`(토글) · `show` | 셸 동안 |

**기본값**: `cli.width` 0 = **터미널이면 콘솔 폭 자동**(Windows `GetConsoleScreenBufferInfo` · unix `COLUMNS`/`stty size`) · 파이프/파일이면 무제한(종전과 동일 출력) · `cli.max_col_width` 60(종전) · `cli.overflow` **wrap**(컬럼을 폭에 맞는 묶음으로 나눠 묶음마다 표 · 맨 앞 `#` 행 번호로 행을 잇는다 · sqlplus LINESIZE 줄바꿈의 읽기 쉬운 형태). truncate = 넓은 컬럼부터 줄여 한 줄에(최소 4칸 · `…`) · expanded = `-[ RECORD n ]` + `컬럼 | 값`(psql `\x` · 폭과 무관하게 늘) · none = 종전.
**구현**: nsql-io `GridOpts`/`Overflow`/`format_grid_opts`/`write_result_set_opts`(기존 `format_grid`·`write_result_set`은 종전 동작 유지) + 테스트 4(폭 안 보장 · 잘림 표시 · 레코드 수 · 맞으면 단일 표 동일) · nsql-settings `cli.width`/`cli.max_col_width`/`cli.overflow`(CATEGORY_TREE 접속 옆 CLI) · i18n 12 · nsql-cli `grid_opts`(설정 → 플래그 → 자동 폭) · `Printer.grid` · `shell_set` · `term::columns()` · 도움말.
**셸 조회**(사용자 후속): `get width` · `show width` · `get`/`show`/`help set` = 전체 + 사용법 · `set width 120;`처럼 끝 `;` 허용. 모르는 키는 SQL로 넘어간다(MSSQL `SET NOCOUNT ON` 같은 진짜 SQL을 막지 않기 위해).
**검증**: 파이프 = 종전 출력 · `--width 70` wrap 묶음 2개 + `#` · truncate `…` · `-x` 레코드 · `config get/list`. 사용 문서는 다른 세션이 쓰는 [40 CLI 사용법](../40-cli-usage.md)에 §(표 폭) 추가 필요 — 그쪽 세션에 인계.

1. **툴팁이 다른 컨트롤 밑에** — 결과 도구줄 툴팁이 아래로 그려져 상태줄과 겹쳤다 → nexa-ui 12차 `Toolbar::set_tooltip_above`(결과 도구줄 4묶음 전부 위쪽).
2. **현재 문장 실행 뒤 캐럿**: 설정 `run.after_statement` = `stay`(기본 · 현재 위치) / `next_ok`(성공하면 다음 문장) / `next_always`(실패해도) — 워커 done 신호(오류 수 메시지 = 실패)에서 판정 · `single_run`(Ctrl+Enter만 · F5·새로고침 제외). **다음/이전 문장 단축키** `edit.next_statement`/`edit.prev_statement` = **Alt+↓ / Alt+↑**(Sublime 기본 맵에서 비어 있음 — Ctrl+Shift+↑/↓는 줄 교체 · Ctrl+Alt+↑/↓는 커서 추가 — 방향키라 "이동"으로 읽힘 · 캡처 창에서 바꿀 수 있음). 이동 = `split_script`의 `Item.span`(`;` 기준) 다음/이전 시작으로 `select_range`.
3. **No Records = Golden 방식**(2번 이미지): 행번호 칸 + `No Records` 글자 폭만큼의 작은 셀 하나(테두리) · 나머지는 빈 바탕 · 글꼴 크기 따라 폭 계산.
4. **헤더 경계 더블클릭 = 자동 너비**: 같은 경계를 400ms 안에 다시 누르면 `autofit`(다음 페인트에서 헤더 이름 + 최대 5,000행 측정) · 한계 = 설정 `grid.col_min_width`(40)/`grid.col_max_width`(420) — 첫 채움에도 같은 한계.
5. **결과 글꼴 face/size**: `grid.font_face`(비면 **시스템 UI 글꼴** = Golden 결과 창과 같은 비례 글꼴 · `mono` = 편집기 고정폭 · 글꼴 이름) + `grid.font_size` 기본 15 → **13**(Golden 참고). 그리드·텍스트 보기 모두 이 글꼴(`App.grid_font` · 설정 즉시 반영).
6. **풀다운 메뉴 "탭"**(Golden Tabs): 열린 탭 순서대로 · 활성 ✓ · 고르면 전환(`tab:<id>`) · 탭 목록 서명이 바뀌면 메뉴 재생성(드롭다운 열린 동안은 미룸 · `sync_tabs_menu`).
**탭 이름 검색 추천안(구현은 후속 T-96)**: (A) **Goto Anything(Ctrl+P · Sublime)** — 명령 팔레트 부품(Ctrl+Shift+P · 퍼지 매치 · 최근 사용 우선)을 그대로 쓰되 항목 = 열린 탭(제목 · 경로 · 수정 표시 · 접속) + 최근 파일 → Enter = 전환/열기 · 타이핑 즉시 필터 · 키보드만으로 끝. (B) 탭 메뉴 맨 위 검색 입력란(메뉴 열고 타이핑 → 아래 항목 필터) — 마우스 경로 · nexa-ctl Pulldown에 입력란 항목이 없어 부품 확장 필요. (C) 탭바 오른쪽 ▾ 드롭다운 + 필터(VS Code) — 탭이 많을 때 스크롤 대신. **추천 = A 우선**(부품 재사용 · Sublime 습관 · 0 신규 컨트롤) → 탭 메뉴 하단에 "탭 찾기… Ctrl+P" 항목으로 연결 · C는 탭바 넘침 표시와 함께 후속.
**검증**: 워크스페이스 테스트 green · clippy ✓(nexa-ctl 216). 실기(툴팁 · Alt+↓ · 자동 너비 · 결과 글꼴 · 탭 메뉴)는 사용자 확인.

## 27차 (win) — 결과 다중 탭 비용 검토(사용자 09-16) → [43 §4-3a](../43-fetch-model-and-result-tabs.md) D-73~75

## 28차 (win) — 자동 페치 휠 경로 · 결과 글꼴 14 · 편집기 거터 띠 · 보기 메뉴 이미지 아이콘

- **스크롤 끝 자동 페치가 안 됨**: 요청은 `clamp()`에서 만들어졌지만 호스트가 `after_grid_event()`를 **포커스 경로에서만** 불렀다 — 휠은 포커스와 무관하게 커서 아래로 가고, 포커스 없는 스크롤바 드래그도 마찬가지 → 두 경로에도 `after_grid_event()`(요청 회수) 추가.
- **결과 그리드 글자 크기**(Golden 좌측과 맞춤): `grid.font_size` 기본 13 → **14**(비례 UI 글꼴 기준 Golden 결과 창과 같은 크기). 사용자 설정에 값이 있으면 그 값이 우선(`nsql config get grid.font_size`).
- **편집기 거터**(Golden식): 줄번호 오른쪽 4px 표시 띠(3px 색 막대 자리 · `TextBox::set_line_marks`로 북마크·오류·변경을 색별로 · 지금은 자리만) + 첫 글자 앞 2px 여백 — nexa-ui 13차.
- **보기 모드 메뉴**: 토글 도형 대신 **이미지 아이콘**(표 · 문서 · 중괄호 · DB 마스크) + 현재 모드는 **강조색**(`CtxItem::with_active` · nexa-ui 13차). 텍스트/Markdown은 문서 아이콘, TSV/CSV는 표 아이콘을 공유 — 전용 마스크는 후속.
**검증**: nexa-sql 30 · nexa-ctl 216 · clippy ✓. 실기(휠 자동 페치 · 거터 띠 · 메뉴 아이콘)는 사용자 확인.

## 29차 (win) — 텍스트 보기 지연 변환(백그라운드 블록 + 진척 카드) · 툴팁 왼쪽 잘림 · 툴팁 문구

**요청**(사용자 09-16): 텍스트 보기로 바꾸면 데이터가 많을 때 오래 멈춘다 → 틀은 즉시 · 위에서부터 적당한 크기로 잘라 **순차** 변환 · 우하단 **반투명 진척 카드** · 다른 보기로 바꾸면 스레드 **무효화** · 다른 탭으로 가면 **백그라운드에서 완성**.

**원인**: ① 전체 변환(`render_result_set`)이 UI 스레드에서 한 번에 ② 첫 페인트가 **전 줄을 글꼴로 측정**(수천 줄 shaping = 수백 ms) — ②가 더 컸다.

**구현**:
- **nsql-io 블록 렌더**: `block_layout(rs, opts)`(표 폭·정렬을 전 행 한 번 계산 · 문자 폭만) + `render_block(rs, fmt, dialect, layout, range, first, last, table, key)` — Grid(헤더는 첫 블록만 · `render_table_rows_num(header)`) · Markdown · CSV/TSV · JSON(`[` 첫 블록 · `,` 행 사이 · `]` 마지막) · SQL(`generate` 블록별) · Insert. 모든 블록이 같은 배치를 써 열이 어긋나지 않는다.
- **그리드 `TextJob`**: `start_text_job(fmt, key)` → 표시 순서대로 복제한 결과(`ordered_rs`)를 스레드 `nsql-textview`로 · **500행 블록**을 `mpsc`로 · 취소 = `Arc<AtomicBool>`(블록마다 확인 · `TextJob` drop이 세움) · `poll_text()`는 호스트 `tick`(33ms · `text_pending()`이 타이머 근거)에서 줄을 이어 붙인다 · **잠든 그리드도 tick**(다른 탭에서 완성 · 그리지는 않음).
- **폭 측정**: 전 줄 대신 **문자 수가 가장 긴 줄 하나**만 잰다(`text_longest` · 블록이 올 때 갱신).
- **진척 카드**: 본문 우하단 · `text` 색 78% 반투명 둥근 카드 · `{형식} 변환 중… {n}%` + 아래 2px 진행 막대 · 변환 중에만.
- 보기 전환·재조회·SQL 키 도착 시 이전 작업은 즉시 취소 후 새로 시작. Ctrl+C는 그 시점까지 받은 줄을 복사(진행 중이면 부분).
- **툴팁 왼쪽 잘림**(사용자 캡처): nexa-ui 14차 `draw_tooltip_in` — 도구줄 x부터 클램프. `TipFetchAll`의 "(조회 건수와 무관)" 제거.
**부하원**(39 §3): 스레드 1개(변환 중에만 · 취소 깃발) · 결과 복제 1회(변환 중 메모리 ×2 · 끝나면 해제) · 33ms tick은 변환 중에만.
**검증**: nsql-io 테스트 green · nexa-sql 30 · nexa-ctl 216 · clippy ✓. 실기(큰 결과 텍스트 전환 · 진척 카드 · 탭 전환 뒤 완성)는 사용자 확인.

## 30차 (win) — 상태줄 캐럿/선택 세그먼트(Sublime 3종)

- **자동 페치가 400행에서 멈춤**(사용자 09-16): 두 번째 페이지부터 `more`가 늘 false — 래핑 질의가 정확히 `limit`행만 돌려주니 상한 초과 판정(`limit+1`)이 성립하지 않았다 → 래핑은 **limit+1행**을 달라고 하고 상한은 limit(한 행이 더 오면 more). 워커 `FetchPage`.
- 사용자 캡처(Sublime): 입력 = `Line 17, Column 29` · 일반 선택 = `6 lines, 90 characters selected` · 열 모드/다중 선택 = `5 selection regions`. 우리 상태줄 세그먼트는 위치·다중 선택만 있었다 → **일반 선택** `{0}줄, {1}자 선택`(`Editors::selection_summary` · 구간 1개 · 걸친 줄 수·문자 수) 추가 · 다중 선택 문구 `선택 영역 {0}개`로. 그리드 포커스면 종전대로 `행 × 열`.

## 31차 (win) — 결과 그리드 글자 선명도(Golden 수준) — 원인 3가지와 보정

**요청**(사용자 09-16 · 캡처 2장): Golden(좌)은 깨끗·선명, 우리(우)는 흐리고 조금 작다 → 원인 분석 · 렌더링·글꼴 크기 보정.

| 원인 | 내용 | 보정 |
|---|---|---|
| ① 글꼴 얼굴 | Windows UI 체인이 **맑은 고딕** 우선 — x-높이가 작고 획이 가늘어 같은 px에서도 Segoe UI/Tahoma(Golden)보다 작고 연하게 보인다 | 결과 글꼴 기본(`grid.font_face` 비움) = **Segoe UI 우선 + 한글은 맑은 고딕 폴백**(`load_grid_font` · Windows만) |
| ② 배치 | 힌팅 없는 회색 AA + 1/3px 서브픽셀 배치 → 세로획이 두 픽셀에 걸쳐 흐림 | `ui.text_snap`(기본 켬) — 글리프 원점 정수 스냅(nexa-gfx `set_text_snap`) |
| ③ 대비 | 커버리지 선형 → GDI ClearType(감마 ≈1.4)보다 연함 | `ui.text_contrast`(기본 140%) — `cov^(1/1.4)`(nexa-gfx `set_text_contrast` · 캐시 키에 감마) |

- 둘 다 **전 창 공통**(편집기·그리드·로그·메뉴) · 설정 즉시 반영 · 끄면(100 · off) 종전 렌더링.
- 글자 크기는 14px 유지(①이 해결되면 Golden과 같은 크기로 보인다) · 필요하면 `grid.font_size`.
- 남는 차이: GDI는 **힌팅**(외곽선을 픽셀 격자에 맞춤)까지 한다 — 우리는 힌팅 없음. 필요하면 후속(오토힌트 근사 · T-97 후보).
**검증**: nexa-gfx/nexa-ctl 테스트 green · nexa-sql 30 · clippy ✓. 실기 비교(선명도·크기)는 사용자 확인.
