문장 원문(1판) — PostgreSQL = `ADD COLUMN note varchar(20)` · `ALTER COLUMN name TYPE varchar(100)` · `ALTER COLUMN qty SET DEFAULT 1` · `COMMENT ON COLUMN …` · `COMMENT ON TABLE …` / Oracle = `ADD (NOTE VARCHAR2(20))` · `MODIFY (NAME VARCHAR2(100))` · `MODIFY (QTY DEFAULT 1)` · `COMMENT ON …` 2 / SQL Server = `ADD note varchar(20) NULL` · `ALTER COLUMN name varchar(100) NULL` · 기존 기본값 제약 삭제(`DECLARE @nsql_df … EXEC(…)`) · `ADD CONSTRAINT DF_<테이블>_qty DEFAULT 1 FOR qty` · `EXEC sys.sp_addextendedproperty …` 2.

**발견(첫 검증 · 개발에 회신 — 처리 = 아래 "재검증")**

1. **SQL Server 기본값 변경 문장을 서버가 거절** — `'QUOTENAME' 근처의 구문이 잘못되었습니다. (line 1)` · 문장 = `DECLARE @nsql_df sysname = (…); IF @nsql_df IS NOT NULL EXEC(N'ALTER TABLE [dbo].[<테이블>] DROP CONSTRAINT ' + QUOTENAME(@nsql_df))` — `EXEC( )` 안의 이어 붙이기에 함수 호출이 들어간 것으로 추정. 뒤 문장(새 기본값 · 확장 속성 2)은 미검증.
2. **중단 문구가 상태줄에 남지 않는다**(3방언) — 적용 +1 s ~ +20 s 덤프가 전부 `1 error(s)`(백업 중에는 `Generating <테이블>_ddl…`). 토스트는 +3 s에 확인.
3. **PostgreSQL · 실패 뒤 가짜 변경** — 이미 서버에 추가된 컬럼이 `*`로 남고 `ALTER COLUMN extra TYPE varchar(20)`가 대기 문장으로 남는다(서버 표기 `character varying(20)`와 입력 글의 차이).
4. **Oracle · 기본값을 읽지 못한다** — `DEFAULT 0`으로 만든 컬럼도 기본값 칸이 빈 글(적용은 됨 · `data_default` = 1 대조 ✓).
5. 사소 — 구조 편집 탭에서도 상태줄 `Read-only` 칸 · 미리보기 창이 열린 뒤 `Checking the table on the server…` 글 잔류.
6. 참고 — SQL Server는 인덱스가 걸린 컬럼의 NULL → NOT NULL을 막는다(`인덱스 '<이름>'은(는) 열 'title'에 종속되어 있습니다.`).
7. 시험 스크립트 쪽 — SQL Server 제약 대조 질의가 정렬 충돌로 빈 결과였다(협업 스크립트 결함 · 고침 · 편집기의 다시 읽기로 대신 확인) · V1 시나리오 몇 개가 격리 홈을 OS 임시에 남긴다(이번 실행분 3개 삭제 — 어느 시나리오인지는 미추적).

**확인하지 않은 것** — MySQL/MariaDB 실서버(이 PC에 프로필 없음) · 운영 프로필 경로(2단 확인 · `tbledit.prod=deny`) · 미리보기 창의 [Apply] 버튼(창 열림까지만 · 적용은 `tbledit.apply_now`가 같은 길) · SQL Server 4 ~ 6번째 문장 · 71 영향 측정 · Windows · macOS.
