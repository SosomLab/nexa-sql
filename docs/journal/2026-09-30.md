- **로그인 폼**(사용자 "오라클의 기본 스키마 위치에 MSSQL Database를 배치 → Database · 서버 유형 한 줄"): `ConnectPanel::db_in_last_row` = 스키마 칸이 없는 네트워크 방언(SQL Server · MySQL) → Database 칸을 마지막 줄 왼쪽(기본 스키마 자리) · 서버 유형 오른쪽 · User는 호스트 바로 아래로. 파일 방언(SQLite)은 경로 칸 제자리(줄 전체). ## 16. ★ 자동완성 빈 곳 조사·보완 1차(10-01 오후 · 사용자 "SQL Server `USE` 뒤 DB 목록 + DBMS별 빈 곳 조사·보완")
- **조사(에이전트 · 문법 `.sqlg` × GUI `intel.rs` 대조)**: ① 문법의 `objects =`는 **아무도 읽지 않는다**(키워드만 · 82 §6 그대로) — 객체 종류는 `CtxKind`(Relation = `FROM/JOIN/UPDATE/INTO/TABLE/DESC/TRUNCATE/USING/ON` 뒤 · Member · Expr)로만 정해졌다 ② **MySQL 문법 파일·키워드 표 없음**(ansi로 떨어짐) ③ 빈 곳 = `USE`(DB 없음) · Oracle `ALTER SESSION SET CURRENT_SCHEMA =` · PG `SET search_path` · `EXEC/CALL`(프로시저 없음 · `스키마.`로만) · `DROP VIEW/PROC/…`(TABLE만 관계) · `ALTER TABLE t` 뒤 컬럼 · `CREATE INDEX ON t(` 컬럼 · **`JOIN … ON |` = 테이블이 나옴**(ON이 관계 키워드) · `MERGE USING` 별칭 · `OUTPUT INSERTED.` · `sp_*` 목록 · `#tmp` 컬럼 · CTE/서브쿼리 컬럼 · `GRANT … TO` 사용자 · 3·4부 이름.
- **구현(nsql-script `intel.rs`)**: **`CtxKind::Want(Want)`** = `Database` · `Schema` · `Routine` · `Kind(code)` — `want_at`(순수): `USE |`(SQL Server = DB · MySQL = 스키마) · `CURRENT_SCHEMA = |` · `search_path TO|=|, |` · `EXEC|EXECUTE|CALL |`(`EXEC @r = |`) · `DROP|ALTER <VIEW·PROC·FUNCTION·SEQUENCE·SYNONYM·INDEX·TRIGGER·TYPE·PACKAGE·DATABASE·SCHEMA> [IF EXISTS] |`(`MATERIALIZED VIEW` = mview · TABLE은 관계 그대로). **`ON`·`USING`은 문장별**(`relation_after_special` = GRANT/REVOKE/CREATE/COMMENT의 ON · MERGE의 USING만 관계 → `JOIN … ON |`은 Expr = 별칭 컬럼). 별칭 표 = `ALTER TABLE t` · `MERGE … USING s` · `CREATE INDEX … ON t(` 추가 · SQL Server 변경 문장 = **`INSERTED`/`DELETED` 가짜 별칭**(대상 테이블 컬럼). `mysql.sqlg` 신설(USE · SHOW · LIMIT/OFFSET · REPLACE · ON DUPLICATE KEY UPDATE · CALL …) + `MYSQL_KEYWORDS` · `builtins::MSSQL_SYSTEM_PROCS`(32). `CandKind::Database`.
- **호스트(GUI `intel.rs`)**: `want_cands` = Database → 버킷 `("", Database)`(SSMS 탐색기가 접속 때 채움 · 없으면 `request_objects("")` → `ObjectsMeta{"" · Database}` = `sys.databases`) · Schema → 스키마 목록 · Routine → 현재 스키마 프로시저·함수·패키지 + 스키마 + `sp_*` · Kind → 현재 스키마 그 종류 + 스키마. 키워드·문서 낱말은 내지 않는다.
- 시험 `want_contexts`(nsql-script 111) — 문맥 20여 경우 + 별칭·가짜 별칭 + MySQL 키워드. GUI 후보 생성은 단위 시험 없음(실기).
- 남음(T-274): `GRANT … TO` 사용자·역할(버킷 없음) · CTE/서브쿼리 컬럼 추론 · `#tmp` 컬럼 · `sp_*` 인자 안내 · 3·4부 이름(`DB.스키마.` = T-272) · 문법 `objects =` 소비(82 §6) · `DESC` 뒤 오판(`ORDER BY x DESC |`) · SELECT 별칭을 ORDER BY에.
