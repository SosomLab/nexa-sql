## §4. 시험 자산 결함 2(이 세션에서 발견·수정)

1. **`scripts/mac-bulk-e2e.sh`가 CRLF** — 115차 win(T-309 ③ 파이썬 보정)이 Windows에서 고쳐 커밋한 뒤 줄 끝이 CRLF로 들어와 맥에서 `env: bash\r: No such file or directory`(exit 127). 저장소 전수 = 이 파일 하나. 조치 = LF 변환(내용 diff 0) + **`.gitattributes` 신설**(`*.sh`·`*.py`·`*.rb`·pkg `postinstall`·deb `control`·rpm `.spec`·`.desktop` = `text eol=lf`) → 어느 OS에서 커밋해도 LF. 교훈 = **시험 자산도 UI 문자열과 같은 커밋(T-309 교훈)에 "줄 끝"을 더한다**.
2. **기능 점검 스크립트의 맥 창 수 판정** — `linux-func-check.sh`는 `xwininfo`(X11)로 창을 세서 맥에선 늘 0 = 전부 `FAIL(no window)`. 111차(10-04)는 협업 세션이 swift(CGWindowList) 사본으로 돌렸지만 **저장소에 올라오지 않았다** → 이번에 저장소 스크립트에 Darwin 분기(`target/func-check-tools/wincount` = `swiftc` 1회 컴파일 · **내가 띄운 PID의 창만** 셈 · 접근성 권한 불필요) + `wins_now "$p"`. Linux는 종전 그대로. 이제 맥 기능 점검 = 같은 스크립트 하나(S01~L16 82).

교훈(102 §12 원장) = ① 점검 도구는 **음성 대조(잡혀야 할 표본)** 없이 ✓를 믿지 않는다(§2 영어 점검 1판 거짓 ✓) ② 다른 OS에서 만든 시험 사본은 저장소로 올린다(111차 swift 사본 유실 → 6일 뒤 재작성).
