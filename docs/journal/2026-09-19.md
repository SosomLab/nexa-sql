### ① "비밀번호가 없는데 연결이 되고 있어" — 분석과 조치

- **현상**: 편집기에서 `CONNECT oracle://BISCM@61.81.244.214:1521/BISCM`(비밀번호 없음)을 실행하면 접속이 됐다.

### ② No connection이 공유로 되돌아감(fail-over 보완)

- **현상**: 공유 연결 1 + 전용 탭에서 표식 메뉴 **No connection**을 고르면 잠시 미연결이었다가 공유 연결로 묶였다.
- **원인**: `RunEvent::Disconnected` 처리의 "공유 모드 ∧ 전용 ∧ !idle_closed → `closing`"이 스크립트 `DISCONNECT`용 복귀 규칙인데, 배지 메뉴의 해제(`disconnect_private_as(tab, keep=true)`)도 같은 이벤트를 받아 세션을 거두고 `sync_sess`가 공유로 묶었다.
- **조치**: 조건에 `!user_disconnected` 추가 — 사용자가 명시적으로 고른 미연결은 그대로 남는다. 툴바 Disconnect(keep=false)는 종전대로 공유 복귀 · 전용 직접 해제 기능은 두지 않음(사용자 "필요 없음"). 52 §12 ②의 호스트 분기가 조건 4개가 됐다 → T-122 순수 함수화 후보 그대로.

- **수정**: 두 창의 생성 직후 `win.set_ime_allowed(true)`. 규칙: **텍스트 입력란이 있는 창은 만들 때 IME를 켠다**(메인 창은 포커스 대상에 따라 토글 · 탐색기는 끄고 앱이 조합).

- **후속(사용자 "한글은 되지만 검색에 바로 반영되지 않는다")**: 설정 창의 검색 반영(`search.take_changed` → `rebuild_cards`)이 일반 사건 경로에만 있어 IME 경로(Preedit/Commit)로 들어온 글자는 다음 키/클릭 때에야 걸러졌다 → IME 분기에서도 검색 상자면 **조합 중 글자까지 포함한 `display_text`로 즉시** 거른다(한 글자씩 반응). Debug/Release 빌드 · 재실행.

## 76차 (win) — 괄호 자동 닫기 옵션 위치(사용자 09-19 "옵션 위치를 알려 주고 없으면 추가")

- **현황**: 옵션은 `rainbowpair.auto_close`(설정 ▸ 확장 ▸ Rainbow Pairs) 하나였다. 그런데 이 분류는 **확장이 꺼져/미설치면 숨고**, 꺼진 상태의 효과(`disabled_effect` = `BracketOpts::default()`)는 nexa-ctl 기본값이 `auto_close: true`라 **자동 닫기는 켜진 채 끌 방법이 없었다**(주석은 "끄면 전부 off"였으나 실제 기본은 on).

- 검증: 실기 캡처 `target/capture/autoclose_on.png`(`f(x` → `f(x)`) / `autoclose_off.png`(`f(x` 그대로) · clippy 0 · 설정/i18n 테스트 green · Debug/Release 빌드 · 재실행.

- **조정(사용자 "괄호·인용부호 자동 닫기는 Rainbow Pairs 기능이 아니다")**: 확장 키 `rainbowpair.auto_close`와 라벨을 없애고, 자동 닫기는 **편집 코어 설정 `editor.auto_close_pairs` 하나**로(호스트가 `BracketOpts.auto_close`에 그 값을 그대로 넣는다 · 확장은 관여하지 않음 · 확장 꺼짐/미설치와 무관). extensions/README 설정 목록 정정.
