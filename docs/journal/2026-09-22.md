### 1. Oracle Instant Client(Linux) — 셸 `sqlplus` + 앱 자동 탐지
- **설치**: Instant Client **23.26** Basic + SQL*Plus(`download.oracle.com/otn_software/linux/instantclient/instantclient-{basic,sqlplus}-linuxx64.zip` · 로그인 없는 "latest" 주소) → `~/oracle/instantclient_23_26`(382 MB · sudo 없이 홈에). `~/.zshrc`에 블록(`ORACLE_IC_HOME` · `LD_LIBRARY_PATH` · `PATH` · `TNS_ADMIN=<IC>/network/admin` · `NLS_LANG=AMERICAN_AMERICA.AL32UTF8`). 저장소에는 아무것도 넣지 않음(사용자 "환경 구축만").
- **Ubuntu 24.04+ 함정**: Oracle이 찾는 `libaio.so.1`이 패키지 `libaio1t64`에서는 `libaio.so.1t64`로만 온다 → `libaio1t64` 설치(sudo가 터미널에서 안 되어 **`pkexec` 폴킷 GUI 인증 창**으로) + **Instant Client 폴더 안에 심볼릭 링크** `libaio.so.1 → /usr/lib/x86_64-linux-gnu/libaio.so.1t64`(시스템 폴더를 건드리지 않는다 · `LD_LIBRARY_PATH`에 그 폴더가 있어 해결된다).
- 검증: `sqlplus -V` = 23.26.2 · `ldd sqlplus` 미해결 0 · 실서버 접속 OK. 앱은 자동 탐지 ③(`LD_LIBRARY_PATH`)으로 찾는다 — 데스크톱 런처는 셸 환경이 없으므로 설정 ▸ DBMS ▸ Oracle 직접 지정 또는 `NSQL_ORACLE_CLIENT_DIR`. 절차는 `scripts/install-instantclient-linux.sh`(맥 스크립트의 Linux 판 · `--rc`)로 스크립트화.

### 4. ★ 기동 병목(Linux 전용) — 글꼴 가족 탐색이 폰트 트리를 12번 걷는다
- `strace -ttt` 타임라인: 설정 +13 ms → 폰트 열기 +14~18 ms → **100~700 ms 구간 = `/usr/share/fonts` 아래 `statx` 11,786회** → Wayland 연결 +686 → 프로필 +776 → CPU 220 ms(무호출) → 배터리 확인 +997 → 첫 화면 버퍼 +1234 ms.
- 원인: nexa-font `find_font_by_family`가 **호출마다** `FONT_DIRS`를 재귀로 걷고(폰트 976개 · 408 MB) 항목마다 `path.is_dir()`(= `statx`)를 부른다. 가족 탐색은 고정폭(D2Coding …) · 기호 폴백 4가족 · UI 본 선호까지 프로세스마다 10여 회 → 걷기 ×12. Windows·맥은 고정 경로 후보라 이 비용이 없다.
- 조치(nexa-ui 53차): ① `collect_font_files`가 `DirEntry::file_type()`(getdents의 d_type · 추가 호출 0)를 쓴다 ② 폴더 목록은 **프로세스에서 한 번만** 걷는다(`font_files()` · `OnceLock`). 새로 설치한 폰트는 다음 기동에서 보인다(설정 창 글꼴 변경도 재시작 안내가 있어 같다).
- 계측(nexa-sql): `NSQL_TRACE_FRAMES=1`이면 `[startup] settings · fonts · event_loop · worker+probe · profiles · connect_panel · theme · syntax · keymap · explorer · colors_win · sess · app`(누적 ms) 한 줄 + `[frames] … first paint … at +N ms`(기동 기준) — 39 §2 S-14 "기동 미계측"을 닫는다. 220 ms CPU 구간의 정체는 이 표시로 가른다(§6에 결과).

### 12. Linux 모달 = 메인에 붙은 창(사용자 "접속 창이 모달일 때 메인을 눌러도 모달이 위 · 두 창이 하나의 포커스 — Windows처럼")
- 증상: Wayland에서 메인을 누르면 메인이 앞으로 와 접속 창을 가렸다. winit 0.30의 Wayland 경로는 **부모 창(`with_parent_window` 미지원) · 창 올리기(`focus_window` = no-op)** 둘 다 없어 호스트 가드만으로는 z-순서를 못 지킨다.
- 조치: ① **Linux 창 백엔드 기본 = X11(XWayland)** — 설정 `gfx.linux_backend`(`x11` 기본 · `wayland` · `auto` · 재시작 뒤 · `DISPLAY` 없으면 winit 기본으로 폴백) ② 보조 창 속성 = `_NET_WM_WINDOW_TYPE_DIALOG`(`winfocus::owned_by`) ③ `attach_child`가 X11에서 **`WM_TRANSIENT_FOR` = 메인 + `_NET_WM_STATE_MODAL`**(속성 + EWMH 클라이언트 메시지 · x11rb 0.13 = winit의 의존 · RustConnection이라 libxcb 링크 0 · DR-3 예외 원장) → GNOME(mutter)이 "부모에 붙은 모달"로 다룬다: 부모를 눌러도 둘이 함께 올라오고 모달이 위 · 함께 최소화 · 작업 표시줄 항목 하나 — Windows의 owner + `EnableWindow`, 맥의 `addChildWindow`와 같은 모델. 앱 아이콘도 X11 `WM_CLASS`로 `.desktop`과 붙는다(§10).
- 확인(`xprop` · Debug · 격리 홈): 로그인 창 `WM_TRANSIENT_FOR = 0x1e00004`(메인) · `_NET_WM_WINDOW_TYPE_DIALOG` · `WM_CLASS nexa-sql` — 첫 시도에서 `_NET_WM_STATE`가 비어 있던 것은 **매핑 전 클라이언트 메시지를 WM이 버린 것** → 속성에도 덧붙여 해결. ⏳ 실기(사용자): 메인 클릭 → 접속 창이 위에 남는지 · Esc/Connect 뒤 메인 복귀 · 최소화 동반.
- 부작용·한계: XWayland라 분수 배율(125 %·150 %)에서는 글자가 흐릿할 수 있다(정수 배율은 `Xft.dpi`로 정상) · IME는 X11 경로(XIM) — T-163 ①에 반영 · Wayland 네이티브를 고르면 종전 동작(가드만). 26 §7-7의 상주 수치는 Wayland 백엔드에서 잰 값 — X11에서는 화면 버퍼가 XShm(공유)라 RssAnon은 같고 RSS만 조금 다를 수 있다(다음 점검에서 A/B).
