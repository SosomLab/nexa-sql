## 2. 🔧 속도 HUD(`×N` 배지)가 맥에서 작다(사용자 캡처 둘 = Windows · macOS)

**실측**(캡처에서 배지 픽셀을 직접 잼 · 글자 상자 높이 = 캡슐 높이 − 여백 `sc(3)`×2):

| | 캡슐(물리 px) | 캡슐(논리 px) | 숫자 잉크 높이(논리) | 글자 상자 높이(논리) |
|---|---|---|---|---|
| Windows(배율 1.0) | 29 × 18 | 29 × 18 | 8 | 12 |
| macOS(배율 2.0) | 47 × 28 | 23.5 × 14 | 5.5 | 8 |

편집기 줄 간격은 두 캡처 모두 논리 20px = 주변 UI는 같은 크기인데 HUD만 작다(높이 78 % · 글자 67 %).

**원인** = 맥 고유가 아니라 **물리 px ↔ 논리 px 단위 혼용**(HiDPI 전반). nexa-ctl `SpeedHud::paint`가 `ctx.text_height()`(물리 px = 크기 × 배율)를 `select_font_sized`의 증분(논리 px · `cur.size`에 더한 뒤 배율이 다시 곱해진다)으로 그대로 넘겼다 → 줄이는 양이 배율만큼 커져 글꼴 = `1 − 0.25 × scale`:

| 배율 | 실제 글꼴 |
|---|---|
| 1.0 | 75 %(의도) |
| 1.5 | 62.5 % |
| 2.0 | 50 % |
| ≥ 4.0 | 하한 1px |

호출자 글꼴 높이를 논리 16으로 두면 Windows 16 × 0.75 = 12 · 맥 16 × 0.5 = 8 = 위 표 그대로. Windows도 표시 배율 150 %면 같은 증상이 난다.

**수정**
- nexa-ui 102차 `SpeedHud::paint`: 증분 = `-(base_h / scale) * 0.25`(배율 1에서는 식이 같아 Windows 모양 불변) + 시험 `speed_hud_size_scales_with_dpi`(단위 모형 `ScaleCtx` = 슬롯 크기·증분 논리 px · 측정 물리 px · 1·1.5·2배 캡슐 크기 단언 · 옛 식으로 되돌리면 2배 = 48 × 28로 실패 = 맥 캡처 실측 47 × 28과 일치).
- **같은 부류** `explorer.rs` 탐색기 용량 글자(`64K` 등): 증분 `-(4.0 / 3.0) * s`(`s` = `self.scale`) → `* s` 제거(맥에서 "Status보다 1pt 작게"가 2pt 작게 되고 있었다 · 캡처 대조는 하지 않음 = 사용자 실기).
- 나머지 `select_font_sized` 호출(아바타 · 타임아웃 버튼 `-2.0` · DBMS 아이콘 라벨 `delta` 루프)은 논리 px 그대로라 문제없음.

**검증**(맥 2배율 · 격리 실행 · 같은 방법으로 전/후)

| | 캡슐(물리 px) | 캡슐(논리 px) | 숫자 잉크 높이 |
|---|---|---|---|
| 수정 전(기존 Release 빌드) | 47 × 28 | 23.5 × 14 | 11 px |
| 수정 후(Debug 빌드) | 55 × 36 | 27.5 × 18 | 16 px |
| Windows 캡처(기준) | 29 × 18 | 29 × 18 | 8 px |

논리 높이 18 = Windows와 일치(폭 1.5 차이 = 글꼴이 달라 생기는 글자 폭 차이로 봄). 시험 nexa-ctl 382 · nexa-sql 311 · fmt ✓.

**캡처 방법**(입력 주입·포커스 이동 0 · 다음에 다시 쓸 수 있게): `NSQL_HOME` 격리(`settings.conf` = `demo.prompted=on` · `scroll.fast_hud_hold_ms=10000`) + `NSQL_NO_ACTIVATE=1` + 접속 인자 `sqlite:<임시 파일>` + `NSQL_STARTUP_CMD="@connected:open:<큰 파일>,@after:3500:ui.wheel:1800/800/-120 × 45"` → 창 번호는 `CGWindowListCopyWindowInfo`(swift 몇 줄 · PID로 고름)에서 얻어 `screencapture -x -o -l <창 번호>`. ⚠ 접속 인자가 없으면 **로그인 창(모달)**, `demo.prompted`가 없으면 **데모 안내 팝업**이 휠을 가로막는다(두 번 헛돌았다). System Events(접근성 권한)가 필요 없다.

**충돌·조정**: 분석 때 권장안으로 "Base 글꼴을 먼저 선택"을 냈으나 적용하지 않았다 — 코드 주석의 설계가 "호출자 글꼴 높이의 75 %"(영역 글꼴에 비례)이고, 바꾸면 Windows에서 눈으로 맞춘 크기가 달라질 수 있어 단위 수정만.

**규칙**([61 §1-5](../61-core-design-and-working-rules.md) 끝에 한 줄 추가): `select_font_sized`의 증분은 **논리 px** — 측정값(`text_height()`·`text_width()` = 물리 px)이나 `scale`을 곱한 값으로 만들지 않는다(만들어야 하면 배율로 나눈다).
