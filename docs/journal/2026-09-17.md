### 텍스트 계열 보기 자동 페치 결함 + ★ 전체 조회 = 나머지 이어 받기(위치 유지)

- **자동 페치**(사용자 캡처 "CSV에서 200행 뒤로 스크롤 시 자동 조회 안 됨" · 그리드 외 전부): `text_view_event`가 휠·스크롤바 사건을 스크롤바가 소비하면 "끝 → 다음 세그먼트" 판정 **앞에서 return** — 키보드 스크롤만 판정을 지났다. → `text_auto_fetch()` 헬퍼로 빼 휠·스크롤바·키 어느 경로든 판정(그리드 `clamp`와 같은 규칙). 회귀 테스트 `text_view_wheel_to_end_requests_next_page`.
- **전체 조회 뒤 1행으로 감**(사용자 "현재 위치 유지 기술 검토" → 권장안 B로 구현): 종전 = 커서 닫고 원문 **재실행·교체**(`set_result`가 스크롤·정렬·선택 초기화). 이제 = **`offset = 든 행 수`부터 나머지를 이어 받아 `append_page`** → 스크롤·정렬(재적용)·텍스트 보기 스크롤(`text_keep_scroll`)이 기존 경로대로 유지. 워커 `limit == 0` 분기: ① 같은 문장 커서가 그 위치(`cursor_matches`)면 `fetch_all`(재전송 0 · 순서 일관) ② 커서 없음·다른 문장 → `query_stream`으로 재실행해 앞 `offset`행은 **배치 단위로 버리며**(메모리 0) 이어 받기 ③ 커서 없는 드라이버(MSSQL) → `fetch_offset(offset, 0)` 한 번(예산 절단). `ConnOutcome::Page.all` 플래그로 늦은 세그먼트와 구별 → 호스트 `append_all`. 예산 = 이 탭 예산 − 든 바이트(남은 만큼). 진행률 rows는 절대값(offset+받은), bytes는 그리드가 든 데이터를 더해 표시. **자동 페치가 나가 있으면 전체 조회는 큐**(`take_fetch_request`가 `fetching` 동안 보류 → 그 세그먼트가 붙은 뒤 정확한 offset) — 종전 "늦은 세그먼트 버리기" 삭제. ■/Esc는 큐에만 있으면 요청 취소(워커 깃발 없이). **전체 조회 버튼은 더 있을 때만 활성**(전부 받았으면 흐림 · 예산에서 멈추면 다시 켜져 이어서 받을 수 있다). 테스트 갱신(생명주기 · 위치 유지 · 큐 · 큐 취소). 부하 표(26 §8) 신규 행 없음(사용자 동작당 1요청 · 재시도 0 · 오히려 첫 200행 재전송이 사라짐).

### 트랜잭션 버튼(사용자 09-17 · 세부 결정 → [44 §5](../44-transaction-log.md))

- 툴바 실행 그룹 끝에 **`tx.log`**(문서 아이콘 · 항상 활성) — 클릭 = 트랜잭션 로그(T-107 창이 오기 전까지 상태줄 트랜잭션 팝업). 자동 커밋 = 기본색 · 배지 없음 · 툴팁 "자동 커밋: 문장마다 커밋됨". 수동 커밋 = **배지 = 미커밋 문장 수**(오래되면 `!n`) · **색 = 가장 심각한 문장 종류**: 조회만 초록 · 오브젝트 생성/변경 보라 · 행 추가 파랑(accent) · 값 변경 호박 · 행 삭제/TRUNCATE/오브젝트 삭제 빨강 · 오래됨 빨강 · 툴팁에 종류 목록·시작 시각.
- 분류 = nsql-core **`TxClass`**(`of_sql` 첫 키워드 · 주석 건너뜀 · 심각도 Drop > Delete/Truncate > Update > Insert > DdlCreate > Read) · 방언 규칙 `Dialect::ddl_transactional`(PG·MSSQL·SQLite = DDL도 대기) · **`truncate_transactional`**(사용자 질문 "Truncate는 대상이 아니지?": Oracle·MySQL = 아니오(암묵 커밋) · PG·SQL Server = **예**(롤백 가능) · SQLite = 문장 없음) · `implicit_commit`을 core로 이관(호스트 방언 문자열 비교 제거). 수동 모드의 조회는 `tx_read`(읽기 트랜잭션 · 배지 없음 · 초록).
- nexa-ctl `Toolbar`: 항목 **배지**(오른쪽 위 캡슐 · 색조 색 · `set_item_badge`) · `set_item_tip` · `ToolTone::Custom(Color)` · `ToolDock` 전달. 테스트 `tx_class_and_dialect_rules`.

### ★ 트랜잭션 로그 창(사용자 09-17 "누르면 별도 모덜리스 창 · DBeaver처럼 목록") → [44](../44-transaction-log.md) · T-107 ✅

- **nsql-run `txlog`**(UI 무의존): `TxEntry`(시각 · 편집기 탭 · 목적 User/Meta/Util · 원문 · 소요 · 행 · 결과 Running/Ok/Err/Stopped · `tx` · 배치 index) · `TxRecord`(시작/끝 · `TxOutcome` Pending/Committed/RolledBack/ImplicitCommit(무엇)/Switched/Lost · 갱신 수) · `TxLog`(링 `cap` · `begin_batch/begin/result/done/timing/error/stopped` · `attach_tx`(열린 트랜잭션에 붙임 · 없으면 연다) · `close_tx(outcome)` · `entries(filter)` 최신 우선 복사 0 · `outcome_of(entry)` **표시 시점에 읽음**). 오류 문장은 트랜잭션 밖(DBeaver `QMUtils` 규칙). 테스트 2(롤백 뒤 같은 트랜잭션의 UPDATE·SELECT 행이 "롤백됨"으로 · 필터/링).
- **`txlog_win.rs`**(모덜리스 · 메인 소유 · Esc 닫기): 위 검색 상자 · 표 7열(시간 · 종류 `SQL / 사용자|메타|보조` · 문장 한 줄 `¶` · 소요 · 행 · 결과 · **Tx**) · 아래 스위치 3(모든 질의 · 이전 트랜잭션 · 이 탭만) + 푸터(건수 · 열린 트랜잭션 미커밋 수·시작 시각) · 행 색 = 상태 보조(대기 accent · 롤백/끊김 흐림+**취소선** · 오류 danger · 중지 호박) · 휠 스크롤 · hover.
- **호스트 배선**: `RunEvent::Begin`(index 0 = 새 배치 · `SET AUTOCOMMIT`은 보조) → `begin` · `ResultSet` → `result` + 수동 모드면 `attach_tx(읽기)` · `Done` → `done` + 대기 대상이면 `attach_tx(갱신)` · `Timing` → 총 소요 · `Error` → `error`. `tx_clear`를 부르던 자리 전부 **`tx_close(outcome)`** 로(해제/접속/끊김 = Lost · 암묵 = ImplicitCommit(첫 단어) · 커밋/롤백 메시지·`_then`·탭 닫기 = Committed/RolledBack · 자동 커밋 전환 = Switched). 툴바 `tx.log`·View ▸ 트랜잭션 로그·팔레트 `view.txlog` → 창(열려 있으면 앞으로). 설정 `txlog.max_entries`(10000 · 로그 범주). 상태줄 트랜잭션 팝업(`open_tx_menu`)은 그대로.
- 남김(44 §3): `tx_pending` 원천을 `TxLog`로 교체(지금은 병행) · 우클릭(문장 복사·편집기로) · 중지(T-108) 결과 연결 · 서버 롤백 판정(§4).

### SQL Server 취소(사용자 09-17 "MSSQL에서 중지가 안 됨 · SSMS는 어떻게 하나 · Attention 방식은 안 되나")

**SSMS 조사**: SSMS = .NET SqlClient `SqlCommand.Cancel()` → `TdsParserStateObject.SendAttention()` → **같은 접속**에 TDS Attention 패킷(타입 0x06 · 헤더 8바이트)을 보낸다(암호화 접속이면 TLS 스트림을 통해). 서버는 실행 중 배치를 멈추고 `DONE` 토큰에 `DONE_ATTN`(0x0020)을 세워 답한다 → 클라이언트는 남은 토큰을 버리고 "Query was cancelled by user" · **접속은 유지** · 열린 트랜잭션은 롤백되지 않는다(`SET XACT_ABORT ON`이면 롤백). JDBC(`SQLServerStatement.cancel()` → `TDSCommand.interrupt()`)도 동일. Attention ack가 일정 시간 안 오면 접속을 버린다.
**우리 제약**: tiberius 0.12는 Attention을 구현하지 않았고(`PacketType::AttentionSignal`·`DoneStatus::Attention` 상수만 있음) `EncryptionLevel::Required`면 로그인 뒤 모든 패킷이 tiberius 내부 TLS 스트림을 지나 **우리가 끼워 넣을 수 없다**. tiberius `Off` = **로그인만 암호화 · 이후 평문**(`post_login_encryption`이 TLS를 벗긴다) → 이 모드에서는 소켓 복제본으로 Attention 8바이트를 보낼 수 있고, tiberius는 `DONE_ATTN`을 특별 취급하지 않아 결과 스트림이 정상 종료(부분 행)된다.
**구현**: 설정 `mssql.encrypt`(`required` 기본 · `login`) → 드라이버 전역 `set_encryption` · `login`이면 취소 = **Attention**(세션 유지 · `drops_session=false` · 오류 없이 부분 결과로 끝나므로 `worker.done`에서 "중지됨" 판정) · `required`면 취소 = **소켓 종료**(`drops_session=true` · 트랜잭션 Lost · 상태줄 "접속을 끊어 중지 · 다음 실행 때 재접속" · 워커 `suspect` + `connect.auto_reconnect`). 접속은 `std::net::TcpStream`으로 열어 복제본을 남기고 논블로킹으로 tokio에 넘긴다. 후속 = tiberius 포크로 TLS 안에서 Attention(설정 없이 항상 세션 유지).
