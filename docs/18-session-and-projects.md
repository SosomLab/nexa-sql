# 18 · 세션 복원(hot exit) · 프로젝트 — 미저장 버퍼도 그대로 돌아온다

> 사용자(09-12): *"Sublime의 Project 관리처럼 저장된 파일 외에 미저장 파일도 다시 열면 그대로 복원. 성능 영향을 최소화하면서 지속적으로 내용이 저장되어야 하고, 닫기/종료 같은 확실한 시점은 어렵지 않게 구현될 것."*

## 1. 모델 (Sublime 대응)

| Sublime | nexa-sql | 위치 |
|---|---|---|
| `Session.sublime_session`(창·탭·미저장 버퍼·선택) | **세션 파일** `session.json` + 버퍼 본문 `buffers/<id>.txt` | 앱 데이터 폴더(`nexa-conf` 경로 규칙 — 포터블 우선) |
| `hot_exit: always` | 기본 켬 — 종료·창 닫기 시 프롬프트 없이 저장하고 다음 실행에 복원 | 설정 `session.hot_exit` |
| `*.sublime-project` + `*.sublime-workspace` | **프로젝트**(`.nexa-project`: 폴더·연결 프로필·설정) + **워크스페이스**(`.nexa-workspace`: 열린 탭·미저장 버퍼·레이아웃·결과 탭) | 프로젝트 폴더(또는 앱 데이터) |
| 프로젝트 전환(`Switch Project`) | 프로젝트별 워크스페이스 복원 · 최근 프로젝트 목록 | Command Palette |

★ SQL 클라이언트 고유: 워크스페이스에는 **연결 프로필 참조(비밀번호는 키체인)** · 탭별 방언/접속 · 세션 변수 값(옵션 · 기본 저장 안 함 — 민감할 수 있음) · 마지막 결과 그리드(옵션 · 크기 상한)도 들어간다.

## 2. 지속 저장 — 성능 영향 최소화

| 시점 | 동작 |
|---|---|
| 타이핑 중 | 아무것도 쓰지 않는다. dirty 플래그 + 세대 번호만 |
| 변경 후 **2초 유휴** 또는 **30초 주기**(둘 중 먼저) | 변경된 버퍼만 `buffers/<id>.txt.tmp` → `rename`(원자적). 세션 메타(`session.json`)는 탭/레이아웃이 바뀌었을 때만 |
| 탭 닫기 · 창 닫기 · 종료 · 프로젝트 전환 · 포커스 이탈(옵션) | 즉시 flush(확실한 시점 — 사용자 지적대로 단순) |
| 크래시 | 마지막 유휴 저장본 + `journal`(옵션 · 변경 델타 append-only)로 복원. 1차는 스냅샷만 |
| 대용량 버퍼(> 4MB) | 스냅샷 대신 **원본 경로 + 델타**만 저장(로프 변경 로그) · 미저장 대용량은 경고 |

구현: `nexa-edit::session`(순수 로직 · 직렬화 · 스냅샷 판정) + 호스트 타이머(coalesce · [17 §3](17-editor-incremental-plan.md)). 저장은 워커 스레드, UI 스레드는 버퍼 스냅샷(로프는 O(1) 클론)만 넘긴다.

## 3. 복원 규칙

1. 시작 시 `session.json` 읽기 → 탭 순서·활성 탭·레이아웃 복원.
2. 저장된 파일 탭: 디스크를 읽고 **base 스냅샷 해시**([15](15-external-file-changes.md))와 비교 — 다르면 "외부 변경" 배지. 파일이 사라졌으면 "(deleted)" 탭 + 마지막 본문.
3. 미저장 버퍼 탭: `buffers/<id>.txt` 그대로 · 제목 "untitled-N" · dirty 표시 · 커서/선택 복원.
4. 결과 그리드는 옵션(기본 복원 안 함 — 재실행이 정확).
5. 손상된 세션 파일은 무시하고 백업(`session.json.bak`)으로 시도 → 둘 다 실패면 빈 창(조용히 죽지 않는다).

## 4. 열린 결정
