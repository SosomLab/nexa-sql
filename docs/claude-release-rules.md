- ★ **패키지 게시물 + 프로그램 내부 정보 = 전부 영어**(사용자 10-04 "choco, winget에 제출하는 내용은 모두 영어로" → **10-10 확장** "패키지 게시 작업은 기본 문서와 설명, 버전 등 프로그램 내부의 정보가 영어로 작성되도록") — 범위 셋 = ① **외부 패키지 저장소 제출물**(아래 종전 규칙) · ② **프로그램·패키지 안에 박히는 정보** = Cargo `description`·메타(바이너리 크레이트) · exe VERSIONINFO · MSI/pkg/deb/rpm/`.desktop`/cask의 이름·요약·설명·저작권 · `--version`/`--help` **기본** 출력 · 정보(About) 창 기본 글 · 설치/제거 스크립트가 사용자에게 내는 글(pkg 환영문 · postinstall · uninstall) · THIRD-PARTY-NOTICES · 동봉 고지(NOTICE) · **버전 표기** = SemVer 숫자 + 영어 접미(`-dev`·`-rc`)만 · ③ **기본 문서** = 패키지가 동봉하거나 패키지 메타데이터 URL(Homepage·ProjectUrl·ReleaseNotesUrl)이 가리키는 문서(README · LICENSE · 릴리스 노트 = 영어 절 먼저) · **한국어는 덧붙이기만**(i18n `Msg` 한국어 열 · `.desktop` `Comment[ko]` · `LICENSE.ko.md` · `README.ko.md`) — 기본(영어)을 대체하지 않는다 · **적용 안 함** = 저장소 내부 문서(docs/) · 빌드 스크립트·워크플로의 주석과 CI 로그 · 사용자와의 대화(한글 규칙 그대로) · 점검 = `scripts/pkg-text-english-check.sh`(릴리스 전 · 한글 줄 = 실패) + [33 §5-2](docs/33-distribution-and-packaging.md) 점검표 · 남은 적용 = T-320(README 영어 주판 + `README.ko.md` · DBMS 로고 NOTICE.md 영어 · 위키 영어판은 사용자 결정) · 자세히 = [33 §5-6](docs/33-distribution-and-packaging.md). **종전 ① 규칙** — 외부 패키지 저장소·검수자에게 나가는 모든 글(winget 매니페스트 글 필드 · 기본 로캘 en-US · winget-pkgs PR 제목·본문·코멘트 · choco nuspec title/summary/description/releaseNotes/tags · 패키지 스크립트 주석·출력 · VERIFICATION.txt · moderator 코멘트·메일 초안) · 가리키는 문서(ReleaseNotesUrl 등)가 한국어뿐이면 영어 판을 먼저 · 한글·이메일 주소 금지 · "모든 답은 한글로"와 충돌하지 않음(대상이 외부 패키지 저장소일 때만 · 사용자 보고 = 영어 원문 + 한글 요약) · 지금은 두 채널 닫힘(열 때 적용) · ★ **릴리스마다 저장소 변수 `WINGET_PUBLISH`·`CHOCO_PUSH` 값을 사용자에게 확인**(사용자 10-08 "배포시마다 확인 필요" · 기본 = 지난 릴리스 값 유지) · 자세히 = [33 §5-3](docs/33-distribution-and-packaging.md).
- ★ **Linux 배포 = deb + rpm 둘 다 · 저장소 채널 pkg.sosomlab.com**(사용자 10-05 "rpm 배포 포함" · "linux-repo 저장소 기준 배포") — 릴리스마다 `.deb`와 `.rpm`을 함께 올린다 · 서명된 APT + RPM(dnf) 저장소 = `../linux-repo`(SosomLab/linux-repo · 등록 `apps/nexa-sql.toml` · 패키지 파일은 Release 자산으로 302) · 릴리스 **공개** 때 `.github/workflows/linux-repo.yml`이 갱신 신호(시크릿 `LINUX_REPO_DISPATCH_TOKEN` · 없으면 하루 1회 정기 실행이 반영) · 자산 이름 규칙(`nexa-sql_{ver}_amd64.deb` · `nexa-sql-{ver}-1.x86_64.rpm`)을 바꾸면 워크플로 확인 줄 + 등록 파일을 함께 · **한 번 공개한 Release 자산은 지우거나 다시 올리지 않는다**(서명 색인의 해시가 가리킨다 — 고치려면 버전을 올린다) · 자세히 = [33 §5-5](docs/33-distribution-and-packaging.md) · T-280.
- ★ **확장 드라이버 릴리스 = pre-release · 태그 `drivers-v<ver>` 하나에 전 드라이버**(사용자 10-22 D-349 · 10-23 D-350) — 같은 nexa-sql 저장소에 올리되 절대 정식(Latest) 릴리스로 올리지 않는다(앱 `releases/latest`를 보는 Homebrew·linux-repo가 가로채인다) · 워크플로 `drivers.yml`(Actions 시크릿 `NEXA_DRIVER_KEY_B64`·`NEXA_DRIVER_KEY_PASS` 필수 · 서명 없는 자산은 올리지 않음) · 오프라인 번들 `nsql-drivers-all-<ver>-<os>-<arch>.zip` · 색인 = 저장소 파일 `drivers/index.json`(워크플로가 갱신 커밋) · 앱 설치본 = 드라이버 없는 판(`NSQL_FEATURES`) · 앱 배포 워크플로 3곳은 `v*` 태그 릴리스에만 반응 · 자세히 = [33 §5-5-1](33-distribution-and-packaging.md).
- ★ **릴리스 변형(D-352 · 사용자 10-23)** = 기본 **lite만** 만들고 채널에 게시 · **full(통합판)은 기본 미생성** — 릴리스마다 `WINGET_PUBLISH` · `CHOCO_PUSH`와 함께 **"full 변형 여부"(`full_variant` / `RELEASE_FULL`)를 사용자에게 확인** · full 자산은 `-full` 꼬리로 Release에만(채널 게시 없음).
- ★ **드라이버 릴리스 전 `nsql_abi::DRIVER_VERSION` 올리기**(사용자 10-23 · 4fd25c2) — 드라이버는 앱과 따로 버전을 매긴다 · `drivers-v<ver>` 태그 = 상수 값이어야 한다(`package-drivers.py`가 다르면 중단) · 한 번 공개한 드라이버 버전은 다시 올리지 않으므로 고치려면 상수부터 올린다.
  - 예(10-23 첫 적용) = `drivers-v0.1.2` 전에 1a9f02f에서 `DRIVER_VERSION` 0.1.1 → 0.1.2 · 앱 릴리스 `v0.2.8`과 별개 번호.
- ★ **10-23 저장소 변수 현재값**(사용자 "winget/choco 제외") = `WINGET_PUBLISH` false · `CHOCO_PUSH` false · `RELEASE_FULL` false — 다음 릴리스 전에도 사용자에게 다시 확인.
